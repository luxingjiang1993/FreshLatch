# evidence_id 规范与判定依据(Lead 侧)

## evidence_id 时点格式

`doc_id#anchor@as_of`,例:`t0-competitor-notes#p2@T1`。

- `@T0` = 签发时快照,`@T1` = 复验时刻快照;判 fresh / stale 引用的证据**必须锚 T1**。
- id 必须逐字来自**本会话** `retrieve` 返回(会话级白名单);凭记忆、凭上一轮主张的证据、凭想象写出的 id 会被工具层拒收。
- `read_source` 读到原文不等于拿到 evidence_id;点回以 chunk 级 id 为准,原文用于理解语义。

## 判定依据的最低要求

- **fresh**:主张的每个前提都能在 T1 原文中指认对应句;一个前提悬空即不够格。
- **stale**:T1 原文存在与某前提互斥的表述,且能写成因果句(哪句 ↔ 哪个前提)。
- **unknown**:以上两者都拿不出,或 T1 无覆盖。

三档的完整口径(定义、干扰项正反例、理由须引证据 id)以 **Auditor 的 `references/verdict-rubric.md` 为单一真相**;本文件不复制定义,防止两份拷贝漂移。

## 干扰项提示

语料埋了污染位:看似已死其实活、看似活其实死、以及「无因果关系的新闻」式干扰。判定时只认「原文表述 ↔ 主张前提」的直接对应,不认时间相近、主题相关这类表面线索。
