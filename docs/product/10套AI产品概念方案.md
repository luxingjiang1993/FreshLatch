本文是产品战略委员会批准后的**第五轮唯一正本**。十套方案各按 20 节完整展开，自方案 1 至方案 10 未删减、未压缩；五维分数一律沿用已批准计划，文中只解释口径，不改分。文末给出 A–E 裁决与唯一立项建议。本正本不修改第一轮至第四轮仓库，也不改历史项目代码。本轮**只交文档**，不把示例代码当成已经完成立项。

## 委员会说明

第一轮回答 2026 年的第一问：**AI 工作如何敢出门**——仿真能失败、签发能举证、Skill 能回归。第二轮回答第二问：**不可逆写操作如何被 API 验收**。第三轮回答第三问：**运行态例外与问责真空**。第四轮回答第四问：**答案已经商品化之后，高风险判断缺可辩护卷宗**。那四条曲线仍然成立，而且已经写成可执行方案。第五轮若再做门禁换皮、实施手换皮、认款闩换皮或卷宗换皮，蓝海项目5 会变成注释。

第五轮面对的是第五问：卷宗、报价、决议、记忆、Skill、交接包都已经在 T0 变绿。**世界在 T1 变了，上周的绿灯如何作废？** Mem0 把记忆过期列为 2026 年未解决问题；GitHub Copilot 写明过期记忆比没有记忆更危险；Confluent 在 2026 Q3 公开说 Agent 建立在过期数据上会失败；LangGraph 把长时程、checkpoint、HITL 做成生产原语。红海在卖「记住更多、检索更快、摘要更顺」。组织真正付学费的地方变成了**过期主张仍亮绿灯**——客户按上周报价下单、董事会按过期简报拨款、Agent 按死事实写回系统、班次按腐坏交接包开工。这些一旦做错，亏的是合同、预算、生产事故与职业信誉，而不是「记忆不够长」。

委员会因此把本轮北星定为：**时效作废**。复验、找反证、对照 T0/T1 原文由真 Agent 在环境反馈下循环处理；过期不得保持绿灯、人审作废/续命、checksum / `last_confirmed_at` 闸、fail-closed 评测由 Workflow 拥有。干活必须符合 Anthropic 对 Agent 的定义——模型在环境反馈下自己决定下一步与工具，循环直到停，每步有 ground truth。禁止再把固定 DAG、一次 top-k RAG、聊天框 Copilot、又一个记忆层叫成 Agent。

本轮同时服务三件事：个人开发者在 Windows 上 2–4 周做出可演示切片；作品集能通过硅谷 / 上海 AI Applied Engineer 的生产级拷问（尤其是 AI Agent、Agentic RAG、Memory、MCP、Skill、Eval）；起步后解释得清为什么以后能长成公司。十套允许起步薄、格局大；不允许起步空、只靠平台叙事。目标用户以 **B2B 与可付费专业职人** 为主；禁止做成通用助手或 B2C 闲聊。

用法：前半是十套可执行方案书；后半是委员会拍板记录。若只能做一个，以 E 节为准：**FreshLatch 复验闩**。它与第一轮 E（SimGate）、第二轮 E（ConfigForge）、第三轮 E（RemitLatch）、第四轮 E（EvidenceOS）错开：同一作者的作品集同时有「门禁」「不可逆写操作」「运行中的钱的例外」「答案之后的证据层」与「签发之后的作废层」。

## PHASE 0：实时情报摘要（截至 2026-09-19）

### 情报摘要

- **技术拐点：** LangGraph 于 2025-10 达 v1.0 GA，2026 年初迭代至 v1.1.x；公开材料将其定位为长时程、checkpoint、time-travel、HITL 的生产默认（TrueFoundry / Uvik 等 2026 框架对比，A 级交叉）。MCP 2026-07-28 规范引入无状态核心与 Streamable HTTP，官方博客与 Cloudflare / Google Cloud 背书（A 级）。Anthropic Agent Skills（2025-10 起，2026 与 MCP 分层并存：MCP 接工具，Skill 教怎么用）成为面试与产品表面的标准词汇（A 级：Anthropic 工程博客 + Claude Help Center）。Agentic RAG 相对一次检索：延迟大约 3–10 倍，咨询项目口径质量可升 20–35%，并出现「证据不足则拒答」路径（B 级：Ortem 2026 架构文、Pexon 八客户项目口径，非标准公开基准）。
- **市场空白：** Mem0 *State of AI Agent Memory 2026* 把 **memory staleness** 列为未解决问题：高相关记忆「直到某一刻之前都很对，然后开始自信地错」（A 级：Mem0 官方报告）。Mem0 另文 *The Day 30 Problem* / decay 文档承认 TTL 与衰减解决的是检索近因，不是源认证（A 级）。第三方实验室口径称 Mem0 OSS 在 30 天后 staleness 约 38%、有效准确率从基准 91.6 掉到约 49（C 级：RankSquire 2026-05，单一实验室，不作 TAM 依据）。Confluent 2026 Q3：Agent 建立在过期数据上会失败（B 级：厂商一季度产品叙事，与 Mem0 交叉后升为产品动机）。GitHub 2026-01 写 Copilot 跨 Agent 记忆必须对当前代码状态做即时核验，过期记忆比没有记忆更危险（A 级：GitHub 工程叙述）。LangChain *State of Agent Engineering 2026* 二手转述：88% Agent 试点达不到生产；复杂任务成功率约 50%（B 级：被多家二次引用，未见本委员会下载原报告全文）。
- **竞品弱点：** Gartner 2025-06-25 新闻稿预测 **超过 40% 的 agentic AI 项目将在 2027 年底被取消**，原因是成本上升、业务价值不清、风险控制不足；同一研究线预测 2026 年底 40% 企业应用内嵌任务型 Agent（A 级：Gartner 新闻稿被 Deloitte / 行业文交叉引用）。Gartner 另称自称 agentic 的供应商里大约只有 130 家有实质能力，其余有 agent washing 风险（B 级：二手转述）。Devin 2024 演示与 SWE-bench 口径争议在 2026 仍被当作「演示到生产的缺口」教材；Cognition 2026-06 发布 Devin Fusion 多模型 harness 降本约 35%，说明竞品自己也在补可靠性和成本，而不是补「过期主张作废」（B 级）。记忆层红海（Mem0 / Cognee / Zep / Letta）优化的是记住与召回，不是「无源认证不得当长期记忆、过期必须打红」。
- **面试重点：** 2026-09 公开的 Agentic AI 面试清单把 Agent vs LLM、Agent loop、Memory 类型、MCP、Context Engineering、Context Compaction、Skills、HITL、Eval、LangGraph 列为必考（B 级：培训机构视频大纲，与 Anthropic / LangGraph 官方叙事一致）。硅谷 / 上海 Applied Engineer 作品集最缺的不是「我接了 RAG」，而是：**真 loop、Agentic RAG、过期/作废闸、MCP/Skill 分层、fail-closed eval**。

## 筛选原则

每套方案必须同时满足下列约束，缺一则不出列：

1. **作者约束：** 个人开发者，无大团队、无大资金；demo 必须在 2–4 周内可演示；Windows 环境可执行。
2. **双用途：** 同一套切片既要能拿去面试，也要能指向未来可发布的产品。
3. **错位原则：** 必须是蓝海 / 替代品 / 反定位 / 颠覆式创新至少一种；能讲清「为什么以后能变成大公司」。
4. **真 Agent 原则：** 至少 1 个、最好多个真 Agent。作废名单、人闸、checksum 断言、TTL 字段不是 Agent。Agentic RAG 由被授权角色多轮自拟查询，按 `as_of` / T0 vs T1 换源，命中不足则改写。
5. **市场原则：** 必须有较大市场潜力；禁止小插件、伪需求。经济买方要写到职称与预算科目。
6. **分数纪律：** 五维为创新性、商业潜力、技术可 demo 性、个人开发者可行性、面试展示价值。分数锁定在本正本委员会评分。创新分奖励品类错位，不奖励堆 Agent 名词。

## 真 Agent 纪律（Anthropic）

依据 Anthropic *Building effective agents*：

- **Workflow：** 代码拥有控制流。过期不得绿灯、人审作废/续命、步数/检索预算、checksum 比对、`unsupported` / `stale` 不得保持绿、导出格式，都是 Workflow。
- **Agent：** LLM 在环境反馈下动态决定下一步与工具，维持对如何完成任务的控制。开始于人的目标（复验这批主张 / 这张报价 / 这份记忆）；执行中每步从环境取 ground truth（T0 原文、T1 原文、工具 schema、交接包、checkpoint）；可在检查点暂停等人；以完成或最大轮次 / 预算停止。

Simon Willison 的压缩版委员会也采用：**Agent = 为了目标、在循环里调用工具，直到停。**

诚实自治等级写在账本上：L0 编排、L1 工具循环但写入/放行人闸、L2 沙箱内可循环写入、L3 生产写入。本轮没有任何方案把 L3 宣传成默认。Lead 派驻 Critic / Auditor 必须是动态决定，不是固定「第 3 步一定召唤」。

共享骨架（十套同构，角色不同）：

应用编排（Workflow）调度一个或多个真 Agent 进入各自环境；Agent 只通过工具读写；过期不得绿灯、人闸、评测仍由代码拥有。LLM 只吐结构化意图；应用拥有预算、暂停与升级。LangGraph 用于 checkpoint / interrupt 承载长时程复验，**不把图本身宣传成真 Agent**。

## 红海回避与错位失败标志

错位失败的标志很具体：FreshLatch 若主界面是聊天框，就掉进 Perplexity；若只做一次新调查，就掉进 EvidenceOS 换皮。QuoteTTL 若主按钮是「生成比价表」，就掉进 QuoteHunter。CommitWatch 若主按钮是「生成待办」，就掉进 PromiseOS。MemoryForensics 若主卖点是「无限记忆」，就掉进 Mem0。SkillRot 若只做 linter 不跑 Agent，就掉进静态扫描插件。ShiftDecay 若做成 CRM 线索路由，就掉进 HandoffRelay。LivingBrief 若去掉保质期只剩导出，就掉进 EvidenceOS 附件。BronzeCheck 若只做 wiki 问答，就掉进 Glean。IncidentReplay 若主界面是轨迹瀑布图，就掉进 LangSmith。ProvenanceWatch 若自动把无源条目写成长期记忆，就掉进虚假记忆事故。

委员会宁可要「更慢、会作废、会停」的复验系统，也不要「什么都记得」的演示。

## 方案 1｜FreshLatch 复验闩

### 1. 一句话定位

把已签发主张从「曾经为真」改成「现在仍可复验」；过期、冲突、无 T1 原文支持的主张不得保持绿灯，人决定作废或续命。

### 2. 目标用户

分市场写死职称与预算科目，避免卖给会把产品听成「更好的搜索」或「第二个 EvidenceOS」的人。

**中国第一年现金楔子：** 独立顾问、产业研究员、战略岗。他们已经用 ChatGPT 或第四轮那种卷宗出过一版判断，两周后客户追问「还成立吗」。买的是复验报告，不是再生成一篇。设计伙伴价按课题 3000–8000 元，或个人订阅 199–349 元/月。

**美国经济买方：** 独立 consultant、sales engineer、policy researcher。预算：research quality / proposal integrity，不是 Copilot 席位。定价 $29–49/月个人，团队按席 + 按复验次数。

**日活：** 做课题、要对自己上周附件负责的人。经济买方常常就是日活。

**明确拒绝：** 只要「更快摘要」的增长团队；要企业 SSO 全家桶的 Glean 采购；要自动商业裁决的幻想买方；要无限记忆的 Agent 平台采购。

### 3. 核心痛点

EvidenceOS / Perplexity / 咨询 PDF 在 T0 给出看起来可辩护的判断。T1 价格变了、竞品发了新闻、监管口径更新、访谈对象改口。人仍把 T0 绿灯附件发给客户。Mem0 2026 报告指出高相关记忆会突然自信地错；GitHub 写明过期记忆比没有记忆更危险。做错一次是职业风险，频率按顾问课题计大约每 2–6 周一次「客户追问还成立吗」。

未满足的 JTBD：**给我一份能指回 T0 与 T1 原文的复验单：哪些主张仍成立、哪些必须作废、缺口是什么；不要再给我一篇新摘要。** 未验证推断：若买方已有卷宗工具，下一痛是「卷宗没有保质期」。

> [Tavily Query: "Mem0 State of AI Agent Memory 2026 staleness"]  
> 结果：官方报告把 memory staleness 列为 hardest open problems 之一；高相关记忆 until it is not, then confidently wrong。衰减解决近因，不解决源认证。截至 2026-09-19。

### 4. 产品概念描述

一次复验有五段。**Lead、Critic 默认是 Agent。过期绿灯闸与人审名单是 Workflow。Auditor 可以是短循环 Agent，不得拥有放行权。**

1. **Lead Reverifier（真 Agent）：** 看见 T0 主张列表、已检索的 T0/T1 块、被驳回 id、缺口。下一步由模型决定：改写查询、按 `as_of=T0|T1` 换源、read 原文、`reverify_claim`、`mark_stale`、`mark_gap`、spawn_critic、spawn_auditor、finish。ground truth 是两份原文，不是模型记忆。
2. **Critic（真 Agent）：** 只找「主张已死」的反证。不得强化「仍然成立」。动态决定检索什么。
3. **Auditor（短循环 Agent + 规则闸）：** 判定 `fresh` / `stale` / `unknown`。`stale` 与 `unknown` 不得保持绿灯（代码强制）。
4. **Scribe / 复验单 UI（Workflow）：** 只排版，不复验。
5. **HumanLatch（Workflow）：** 人点「作废」或「续命（给出理由与新 evidence_id）」。续命必须带 T1 原文。Agent 不得自己把红灯改回绿灯。

禁止给出「建议进入 / 不进入市场」的最终商业裁决。诚实自治：复验 L1；作废与续命给人 L0。

### 5. 创新类型

**反定位：** 红海卖记住更多、检索更快；本产品卖更慢但会作废。蓝海是证据商品化之后的时效层。颠覆点不在模型更大，而在「绿灯有保质期」成为默认产品形态。情报锚：Mem0 staleness 未解决 + Confluent「过期数据上的 Agent 会失败」。

### 6. 与红海产品的差异化

| 现有方案 | 本方案 |
|----------|--------|
| EvidenceOS / 深度研究 | T0 取证成卷 | T1 对已签发主张复验作废 |
| Mem0 / Cognee / Zep | 存储与召回记忆 | 无源认证不得当长期有效 |
| Perplexity / Glean | 更快给一段话 | 复验单：fresh/stale/unknown |
| 法规订阅 / RegDelta | 推新规或改政策清单 | 不立项法规 diff；只问这批主张还是否成立 |

仍值得做的理由：记忆巨头必须优化召回率；你优化「被时间挑战后是否还敢亮绿灯」。错位失败标志：主界面变聊天框，或再跑一遍 T0 调查。

### 7. 使用场景与用户旅程

顾问导入两周前的市场进入卷宗（合成：东南亚 SMB AI 客服）。语料含 T0 访谈/成本/竞品，以及 T1 变更（竞品降价、监管口径收紧、客户访谈改口）。Lead 循环对照 → 写出复验单。用户点一条「竞品价格仍高」作废 → 禁用名单重跑 → 导出「仍成立 / 已作废 / 缺口」。全程可回放工具轨迹。对照脚本：无工具 LLM 读 T0 摘要必须把已死主张判绿；本产品必须红。

### 8. 核心功能模块

复验 Planner Agent；按 `as_of` 的 Agentic RAG；Devil’s Advocate 专找已死主张；fresh/stale/unknown Auditor；复验单编辑器；作废/续命人闸；claim-level freshness 评测页；MCP 暴露 retrieve/read/reverify；项目记忆（已证/已废/缺口/`last_confirmed_at`）。

### 9. 技术架构

**角色诚实表：**

| 角色 | 类型 | 职责 | 禁止 |
|------|------|------|------|
| Runner | Workflow | 预算、步数、作废名单、LangGraph checkpoint | 编造仍成立；最终商业裁决 |
| Lead | 真 Agent | 自主规划复验与派驻 | 无 T1 原文把 stale 改 fresh；放行 |
| Critic | 真 Agent | 找「已死」反证 | 强化原主张；放行 |
| Auditor | 短循环 Agent | 判定 fresh/stale/unknown | 改主张正文；放行 |
| 规则闸 | Workflow | stale/unknown 不得绿灯 | 扮演复验 |
| HumanLatch | Workflow | 作废或续命 | 自动续命 |

**Agentic RAG：** 私有语料与公开源分 `source_type`，时间分 `as_of=T0|T1`。Agent 自拟查询；命中不足必须改写或换源。未命中禁止用模型记忆作答。强制「无 T1 原文不得续命」。

**数据来源：** Demo 用合成市场笔记 + 公开风格监管/媒体摘要，故意在 T1 改三条关键事实。真实客户资料不进作品集。Windows 本地 Chroma / SQLite。

**记忆架构：** 短期=本轮轨迹与检索块。长期=主张 TTL、`last_confirmed_at`、`validity_basis`（doc_id + checksum）、作废名单。上下文只装主张列表、最近检索、作废名单，不装全部语料。

**评估闭环：** 黄金集「必须打成 stale」的主张；用户作废率作在线指标。北极星不是「报告好读」。Bad case 回流进 `data/eval/gold.json`。

**工具签名（OpenAI tools / MCP 同构）：** `retrieve(query, source_type, as_of)`、`read_source(doc_id)`、`reverify_claim(claim_id, status, evidence_ids)`、`mark_stale(claim_id, reason)`、`mark_gap(description)`、`spawn_critic(focus)`、`spawn_auditor(claim_id)`、`finish_reverify()`。栈：OpenAI 兼容接口 + 薄 runner + LangGraph checkpoint。Skill 文件写复验纪律（不得用记忆补原文）。

**Windows：** Python 3.11 + FastAPI 或 Streamlit + Pydantic v2；不要 Docker。

### 15. 面试包装策略

## 方案 2｜QuoteTTL 报价保质期

### 1. 一句话定位

盯住上周已经发出或已经收到的报价：数字、税率、交期、汇率必须能在 T1 原文上复验；过期报价不得继续当谈判依据。

### 2. 目标用户

**中国现金楔子：** 中小外贸/ SaaS 销售助理、独立采购顾问。买的是「这张 PDF 还能不能报给客户」。按份 200–800 元，或月订 199–399 元。

**美国经济买方：** SMB AE、procurement coordinator。$19–49/月或按份 $29–79。预算：deal desk / procurement ops，不是 BI。

**日活：** 报报价的人。经济买方：销售负责人或采购经理。

**明确拒绝：** 要 ERP 全家桶的采购平台；要「生成 100 份比价」的 QuoteHunter 幻想买方。

### 3. 核心痛点

QuoteHunter 解决 T0 三家比价。真实事故是 T0 比完、T1 供应商改交期或汇率，人仍拿旧 PDF 上桌。频率：外贸与 SaaS 折扣单常见 7–30 天有效期，过期后仍被转发。痛的程度：一次过期报价可吃掉整单毛利或造成虚假承诺。

> [Tavily Query: "Gartner agentic AI projects canceled 2027 cost risk"]  
> 结果：Gartner 预测超 40% agentic 项目 2027 年底取消，原因含成本与风险控制。报价过期是可度量风险控制，不是又一个 Agent 试点。截至 2026-09-19。

### 4. 产品概念描述

导入一张 T0 报价（结构化表 + PDF 文本）+ T1 供应商函/网页摘要。

1. **Extractor（短循环 Agent 或规则优先）：** 抽出金额、币种、税率、交期、有效期字段。字段抽取能规则就规则。
2. **Reverifier（真 Agent）：** 在 T1 源上循环：改写查询、read、对每个字段 `reverify_field`。
3. **Critic（真 Agent）：** 专找「字段已死」：隐性加价、交期从 14 天变 45 天、税率口径变化。
4. **规则闸：** 数字对不上或过有效期必须红。金额守恒：行合计 = 总额（代码）。
5. **HumanLatch：** 人确认「仍可报」或「作废并通知对方」。禁止自动对外发邮件。

诚实自治：复验 L1；对外通知 L0。

### 5. 创新类型

**替代：** 替代 Excel 里把旧 PDF 当真理。**反定位：** 对比价引擎（更快找到更低价），本产品问「手里这张是否还算数」。情报锚：Gartner 风险控制不足导致项目取消——本产品把风险做成红灯字段。

### 6. 与红海产品的差异化

| 现有方案 | 本方案 |
|----------|--------|
| QuoteHunter / ChatGPT 比价 | 当下三家谁便宜 | 已持有报价是否过期 |
| ERP / 进销存 | 库存与订单 | 不接 ERP；只复验报价文件 |
| 合同工具 BothSides | 条款对抗 | 数字与有效期，不改合同正文 |

错位失败：主按钮变成「生成比价表」。仍值得做：付费贴下一单毛利，ERP 覆盖不到中小价格带的 PDF 现实。

### 7. 使用场景与用户旅程

销售导入「9 月 1 日供应商报价」+「9 月 18 日供应商更新函（合成：交期 14→45 天，运费上浮 12%）」。Agent 循环核对字段 → 交期与运费打红，含税合计守恒仍绿。人点作废运费行。导出给客户前的「仍有效字段清单」。对照：无工具 LLM 必须把过期交期说成仍有效。

### 8. 核心功能模块

报价字段抽取；按字段 Agentic RAG；数字守恒闸；有效期日历；作废/仍可报人闸；差异红灯表；MCP `retrieve`/`read_source`/`reverify_field`。

### 9. 技术架构

| 角色 | 类型 | 职责 | 禁止 |
|------|------|------|------|
| Parser | Workflow/规则 | 金额、税率、日期 | 编造数字 |
| Reverifier | 真 Agent | 字段级复验 | 对外发信 |
| Critic | 真 Agent | 找已死字段 | 放行 |
| 守恒闸 | Workflow | 行合计=总额 | 扮演调查 |
| HumanLatch | Workflow | 仍可报/作废 | 自动通知客户 |

**RAG：** T0 报价与 T1 更新分 `as_of`。Agent 对每个红灯候选自拟查询。  
**数据：** 合成中英报价 PDF 转 Markdown + 更新函。  
**记忆：** 供应商历史「爱改交期」标签后期再加；12 周只记本张单据。  
**评估：** 金标必须红的字段列表；守恒差额必须为 0。  
**工具：** `retrieve`、`read_source`、`reverify_field(field_id, status, evidence_ids)`、`mark_expired`、`spawn_critic`、`finish`。LangGraph：每字段可 interrupt。Skill：`quote_ttl.md` 写「不得口算汇率」。  
**Windows：** Python 3.11 + FastAPI；金额用 Decimal，禁止 float。

### 10. 商业模式

按份或按月订阅。不要抽成交额。不要保证「最低价」。LTV：销售团队每月数十张报价，按份可快速回款。CAC：外贸/SaaS 社群样张。

### 11. 获客与分发

成交句：「这张上周的报价，交期和运费已经死了，别拿去见客户。」渠道：外贸群、采购社群、公开一张红灯样张。拒绝 ERP 替换 RFP。

### 12. 护城河分析（战略七力）

- **规模经济：** 字段抽取模板可摊薄。
- **网络效应：** 弱。
- **反定位：** 比价产品不能把「你手里的单是假的」当首页。
- **切换成本：** 供应商过期手法库。
- **品牌：** 漏掉一次过期交期即受伤。
- **垄断性资源：** 无。
- **能力优势：** 守恒 + 字段级原文，难用聊天复制。

### 13. 为什么是现在

## 方案 3｜CommitWatch 决议衰减

### 1. 一句话定位

人已经基于旧简报点过「批准」的决议，必须在事实变化后重闩；过期依据上的批准不得继续当授权。

### 2. 目标用户

**中国现金楔子：** 创业公司创始人兼战略、咨询项目经理。买的是「三个月前那次立项会还作不作数」。按决议包 2000–6000 元，或月订 299–499 元。

**美国经济买方：** founder、product lead、investment committee secretary。$39–79/月。预算：decision quality / governance，不是 OKR 软件。

**日活：** 写简报的人。经济买方：拍板的人。

**明确拒绝：** 要 Jira 替代的项目管理采购；要自动改战略的幻想买方。

### 3. 核心痛点

PromiseOS 管待办。MandateRing 管授权议价。真实事故是：T0 批准「Q4 进入某市场 / 签某供应商 / 冻某预算」，T1 关键依据死了，批准记录仍绿。董事会/投资人按旧授权行动。频率：成长型公司每季度至少 1 次「那次会还算数吗」。痛：错配预算与合规责任。

> [Tavily Query: "GitHub Copilot agent memory freshness invalidation 2026"]  
> 结果：GitHub 工程叙述：跨 Agent 记忆必须对当前状态即时核验；过期记忆比没有记忆更危险。决议是组织记忆的一种。截至 2026-09-19。A 级。

### 4. 产品概念描述

导入 T0 决议卡（标题、批准人、依据主张列表、日期）+ T1 语料。

1. **Historian（真 Agent）：** 在决议依据上做 Agentic RAG，找出每条依据的 T0 原文。
2. **Reverifier（真 Agent）：** 对每条依据做 T1 复验，决定是否 spawn_critic。
3. **Critic（真 Agent）：** 专找「批准依据已死」。
4. **规则闸：** 任一条 P0 依据 stale，则整项决议 `needs_relatch`，不得保持「已批准」绿。
5. **HumanLatch：** 人重新批准、降级或作废。禁止 Agent 改批准状态。

诚实自治：调查 L1；批准状态 L0。

### 5. 创新类型

**反定位：** 红海卖更多自动化执行；本产品卖「旧批准遇到新事实必须停」。颠覆：把 HITL 从「执行前点一次」改成「依据死后强制再点」。情报锚：GitHub 过期记忆更危险；LangGraph interrupt 已是生产原语。

### 6. 与红海产品的差异化

| 现有方案 | 本方案 |
|----------|--------|
| PromiseOS / 待办 | 任务完成 | 批准依据是否仍真 |
| MandateRing | 授权内议价 | 授权所依据的事实是否腐烂 |
| Notion AI / 会议纪要 | 更快记录 | 记录上的绿章要过期 |
| EvidenceOS | 新调查 | 旧决议的衰减 |

错位失败：主按钮变成「生成待办」。仍值得做：治理软件卖流程，你卖依据死亡。

### 7. 使用场景与用户旅程

创始人导入「2026-06 批准进入东南亚客服市场」+ 当时简报主张 + T1 监管收紧与竞品降价（合成）。Agent 把两条 P0 依据打红 → 决议卡从绿变 `needs_relatch`。人选择降级为「仅试点」并写理由。对照：无工具 LLM 必须把旧批准说成仍有效。

### 8. 核心功能模块

决议卡 schema；依据级复验；P0 依据死亡则整卡重闩；人审重批；决议账本；MCP `retrieve`/`reverify_claim`/`propose_relatch`。

### 9. 技术架构

| 角色 | 类型 | 职责 | 禁止 |
|------|------|------|------|
| Runner | Workflow | 决议状态机 | 自动改批准 |
| Historian | 真 Agent | 找回 T0 依据原文 | 编造依据 |
| Reverifier | 真 Agent | T1 复验 | 放行 |
| Critic | 真 Agent | 依据已死 | 强化批准 |
| Relatch | Workflow | 人重批 | Agent 签名 |

**RAG：** 决议附件与 T1 新闻分 `as_of`。  
**数据：** 合成董事会一页纸 + 变更新闻。  
**记忆：** 长期=决议账本与历次重闩理由。  
**评估：** 金标「P0 依据死后必须 needs_relatch」。  
**工具：** `retrieve`、`read_source`、`reverify_claim`、`flag_relatch(decision_id, dead_claim_ids)`、`spawn_critic`、`finish`。LangGraph interrupt 停在重闩。Skill：`commit_watch.md`。  
**Windows：** Python 3.11 + FastAPI；状态枚举代码写死。

### 10. 商业模式

按决议包或治理席位。不要抽「帮你取消项目」的成功费。不要卖「自动战略」。LTV：季度委员会场景。CAC：创始人社群。

### 11. 获客与分发

成交句：「三个月前那次批准，依据已经死了，绿灯不能继续当授权。」渠道：创业社群、咨询交付附件。拒绝 OKR 平台 RFP。

### 12. 护城河分析（战略七力）

- **规模经济：** 决议模板摊薄。
- **网络效应：** 弱。
- **反定位：** 执行类 Agent 公司不能把「停」当首页。
- **切换成本：** 决议账本。
- **品牌：** 漏掉 P0 依据死亡即治理事故。
- **垄断性资源：** 无。
- **能力优势：** 状态机 + 依据级原文。

### 13. 为什么是现在

Agent 开始「做事」之后，旧批准被当成永远有效。LangGraph HITL 原语成熟。Gartner 取消潮=治理真空被定价。窗口是「决议卡没有 freshness 字段」。

### 14. 个人开发者 Demo 路径

**第 1 周：** 决议卡 UI + 两条依据 + 人工改 T1。  
**第 2 周：** Agent 复验 + 整卡 needs_relatch。  
**第 3–4 周：** 人重批/降级 + 金标。验收：P0 依据死后旧绿章必须灭。

### 15. 面试包装策略

> 「A decision is a latch on claims. When a P0 claim dies, the decision cannot stay approved. The agent loops the evidence; the human relatches.」

现场：绿章变黄、人降级。揭短：不是董事会 SaaS；一类决议。

### 16. 12 个月演进路线

0–3 月：单类立项决议。3–6 月：供应商签约决议。6–9 月：只读日历提醒。9–12 月：挂 FreshLatch。不改名叫治理平台。

### 17. 最大风险与应对

做成待办。法律上「系统建议取消」像咨询：界面写准备材料。政治：没人想看自己的旧批准变红——成交对象选要对过期负责的人。

### 18. 市场潜力

每家成长公司都有决议腐烂。SAM 是有正式立项会的中小企业与基金投委会秘书。定性中（商业 8）：销售周期长于报价 TTL，短于企业 GRC。

### 19. 综合评分

| 维度 | 分 | 解释 |

## 方案 4｜MemoryForensics 记忆刑侦

### 1. 一句话定位

审计生产 Agent 的长期记忆：找出矛盾、死事实、无源条目；有问题的记忆不得继续被检索当真相。

### 2. 目标用户

**中国现金楔子：** 已经上了客服/内部 Agent 的 20–200 人团队的 AI 负责人或兼职开发。买的是一次记忆体检。按次 4000–12000 元，或月订 499–999 元。

**美国经济买方：** founding engineer、agentic ops lead。LangChain 2026 转述显示 named agentic ops 角色在增加。$79–149/月。预算：AI reliability，不是又一个向量库。

**日活：** 维护 Agent 的工程师。经济买方：怕 Agent 用错客户事实的负责人。

**明确拒绝：** 要「无限记忆、越用越聪明」的 Mem0 采购。

### 3. 核心痛点

团队接了 Mem0/自建 memory 之后，Agent 在第 30 天开始用过期雇主、过期价格、过期政策答用户。官方承认 staleness 未解决。TTL 会忘掉仍正确的高频事实，留不住已死的高频事实。频率：一旦生产记忆上线，每周都有「它怎么还以为我们…」的工单。痛：客户信任与合规。

> [Tavily Query: "State of AI Agent Memory 2026 memory staleness"]  
> 结果：Mem0 官方 hardest open problems 含 memory staleness 与跨 session 身份。A 级。RankSquire 30 天 38% staleness 为 C 级旁证，不写入 TAM。

### 4. 产品概念描述

导入一份合成记忆库（JSON 条目：content、written_at、last_confirmed_at、source_ref）+ 当前语料。

1. **Forensic Lead（真 Agent）：** 决定抽哪条记忆、检索当前源、对比。
2. **Contradiction Hunter（真 Agent）：** 专找条目之间互斥（用户既在 A 公司又在 B 公司）。
3. **Source Auditor（短循环）：** 无 `source_ref` 或 checksum 对不上 → `unverified`，不得继续召回。
4. **规则闸：** `dead` / `contradictory` / `unverified` 移出召回集（代码）。
5. **HumanLatch：** 人确认删除、归档或重绑源。禁止 Agent 直接抹生产记忆（demo 用副本）。

诚实自治：审计 L1；删除 L0。

### 5. 创新类型

**反定位：** 记忆厂商卖写入与召回；本产品卖刑侦与隔离。蓝海是记忆层标配之后的卫生层。情报锚：Mem0 自己说 staleness 未解决。

### 6. 与红海产品的差异化

| 现有方案 | 本方案 |
|----------|--------|
| Mem0 / Zep / Cognee / Letta | 记住 | 找出不该再被记住的 |
| LangSmith | 轨迹观测 | 记忆条目级生死 |
| EvidenceOS | 课题主张 | 生产记忆库 |

错位失败：主卖点变成「我们记忆更准」。仍值得做：记忆厂商必须优化基准分；你优化生产第 30 天。

### 7. 使用场景与用户旅程

### 9. 技术架构

| 角色 | 类型 | 职责 | 禁止 |
|------|------|------|------|
| Runner | Workflow | 只读副本、预算 | 直连客户生产库写入 |
| Lead | 真 Agent | 选择审计顺序 | 无源当作 fresh |

**RAG：** 当前政策/CRM 合成语料为 T1 源；记忆库不是源。

## 方案 8｜BronzeCheck 青铜复验

### 1. 一句话定位

银层 wiki / 内部摘要必须能重新拉取青铜源 checksum；拉不到或校验失败的银层句子不得当知识。

### 2. 目标用户

**中国现金楔子：** 知识运营 / 文档负责人、Agent 知识库管理员。按库体检 4000–10000 元。

**美国经济买方：** knowledge manager、applied engineer。$49–99/月。预算：knowledge quality。

**日活：** 维护 wiki 的人。经济买方：怕 Agent 引用过期 wiki 的负责人。

**明确拒绝：** 要 Glean 替换；只要 wiki 问答。

### 3. 核心痛点

Karpathy 风格 LLM wiki：青铜源 → 银层结构化笔记 → 金层产出。生产里银层脱离青铜，Agent 只读银层。OrgArchaeologist 挖实践；本产品问银层是否还能对上源文件。频率：每次源 PDF/政策更新后。痛：制度性幻觉。

> [Tavily Query: "Karpathy LLM wiki bronze silver gold agent memory 2026"]  
> 结果：2026 Agent Reliability 笔记把 bronze/silver/gold 与可重新拉取源当作可靠性方法。B 级方法论文，非市场规模。

### 4. 产品概念描述

导入银层 Markdown（带 `source_ref`）+ 青铜文件。

1. **Checker（真 Agent）：** 选银层句子，read 青铜，决定是否需要改写查询找源段落。
2. **Critic：** 专找「银层有、青铜无」或 checksum 变化。
3. **规则闸：** 无青铜祖先的银层句 `orphan`，不得入金层。
4. **HumanLatch：** 人删除孤儿或重绑源。禁止自动改 wiki 生产库（副本上操作）。

诚实自治：检查 L1；改 wiki L0。

### 5. 创新类型

**反定位：** 知识库产品卖覆盖率；本产品卖孤儿检测。情报锚：可靠性工程把无青铜祖先当幻觉。

### 6. 与红海产品的差异化

| 现有方案 | 本方案 |
|----------|--------|
| OrgArchaeologist / Glean | 找到知识 | 银层能否回到源 |
| CiteGate | 外发签发 | 内部银层卫生 |
| 普通 RAG 评估 | 回答准不准 | checksum 能不能复验 |

错位失败：做成 wiki 问答。仍值得做：每个 Agent 知识库都有银层漂移。

### 7. 使用场景与用户旅程

银层写「退货 30 天」，青铜政策已改为 14 天（checksum 变）。Agent 将银层句打成 orphan/stale。人重绑。对照：Glean 式问答仍答 30 天。

### 8. 核心功能模块

银层解析；青铜 checksum；孤儿清单；人闸重绑；eval must_orphan；MCP `read_bronze`/`read_silver`。

### 9. 技术架构

| 角色 | 类型 | 职责 | 禁止 |
|------|------|------|------|
| Runner | Workflow | sha256 计算 | 编造源 |
| Checker | 真 Agent | 句子对段落 | 改生产 wiki |
| Critic | 真 Agent | 无祖先 | 放行 |
| HumanLatch | Workflow | 重绑 | 自动发布 |

工具：`retrieve`、`read_source`、`compute_checksum`、`flag_orphan`、`spawn_critic`、`finish`。数据：合成政策 v1/v2。Windows：Python hashlib + Chroma。

### 10. 商业模式

### 11. 获客与分发

- **能力优势：** checksum 复验闸，不是 wiki 问答。

### 13. 为什么是现在

## 方案 9｜IncidentReplay 时点回放

### 1. 一句话定位

回答「当时 Agent 知道什么」：按 checkpoint 回放决策时点的检索集与工具回包，而不是再生成一份事后解释。

### 2. 目标用户

**中国现金楔子：** Agent 已上线、出过事故要复盘的应用团队。按事故包 5000–15000 元。

**美国经济买方：** agentic ops、SRE for AI。$99–199/月。预算：incident response。

**日活：** 复盘的人。经济买方：要对事故负责的工程经理。

**明确拒绝：** 要 LangSmith 全家桶观测平台。

### 3. 核心痛点

LangSmith 给轨迹瀑布。AgentRedTeam 把失败推进 CI。事故会上要的是：**那个决定发生时，模型面前有哪些块、哪些工具结果、哪些记忆条目**。事后 RAG 会混入 T1 知识，造成假清白或假有罪。频率：每季至少一次「Agent 为什么那样做」。痛：问责真空。

> [Tavily Query: "LangGraph time-travel debugging checkpoint 2026"]  
> 结果：框架对比把 time-travel debugging 列为 LangGraph 能力：可检查任一节点状态。A 级能力描述。本产品卖给非框架用户的事故包，而不是 IDE。

### 4. 产品概念描述

导入一次 run 的 checkpoint（合成 JSON：messages、检索 hits、tool results、as_of）。

1. **Replay Lead（真 Agent）：** 决定打开哪个 checkpoint、对比「当时可见」与「现在可见」。
2. **Anachronism Hunter（真 Agent）：** 专找事后解释里用了当时不存在的证据。
3. **规则闸：** 事后才入库的 doc_id 不得进入「当时依据」。
4. **HumanLatch：** 人确认事故结论草稿。禁止自动发处分邮件。

诚实自治：回放 L1；问责结论 L0。

### 5. 创新类型

**反定位：** 观测平台卖实时瀑布；本产品卖时点诚实。情报锚：LangGraph time-travel 原语 vs 产品空白。

### 6. 与红海产品的差异化

| 现有方案 | 本方案 |
|----------|--------|
| LangSmith / 轨迹 UI | 开发者调试 | 事故时点包 |
| AgentRedTeam | 失败进 CI | 已发生事故的当时可见集 |
| 日志平台 | 基础设施 | 证据是否时间合法 |

错位失败：主界面变瀑布图。仍值得做：面试杀伤力强；商业偏事件制。

### 7. 使用场景与用户旅程

导入一次「错误承诺 30 天退货」的 run。T1 政策已是 14 天，但 checkpoint 显示当时检索到的仍是旧段落。Hunter 标出事后评论里引用了 T1 文件为 **anachronism**。人确认「当时依据合法、政策已变，属 FreshLatch 问题而非模型胡编」。对照：无 checkpoint 的 LLM 复盘会混用新政策。

### 8. 核心功能模块

### 9. 技术架构

## 方案 10｜ProvenanceWatch 出处监视

### 1. 一句话定位

每条长期记忆必须绑定可复验源；无源认证、源消失或 checksum 失败的条目不得进入召回。

### 2. 目标用户

**中国现金楔子：** 要把对话摘成「客户事实」的 CS / 实施团队。按记忆管道 3000–8000 元起步。

**美国经济买方：** AI platform engineer。$49–99/月。预算：data governance for agents。

**日活：** 写 memory connector 的人。经济买方：合规或工程负责人。

**明确拒绝：** 要自动把所有对话变成记忆的增长团队。

### 3. 核心痛点

TTL/衰减解决近因。Mem0 与设计指南都说：**记忆的真假取决于源，源会变，TTL 不是源认证。** 团队仍把模型摘要直接 `memory.add`。频率：每次会话抽取。痛：自信的错事实进入所有后续会话。

> [Tavily Query: "memory staleness source certification TTL not enough 2026"]  
> 结果：Atlan / 设计指南转述 Mem0：decay 不解决 source certification。B 级转述 + A 级 Mem0 原题。

### 4. 产品概念描述

写入路径上的闸，与 MemoryForensics（已有库的刑侦）成对。

1. **Certifier（真 Agent）：** 对候选记忆决定去哪找源、是否 `read_source`。
2. **Critic：** 专找「摘要里有源文没有的数字」。
3. **规则闸：** 无 `source_ref`+checksum 不得 `commit_memory`。
4. **HumanLatch：** 低置信或 PII 候选必须人批。禁止静默写入。

诚实自治：认证 L1；commit L0（高风险）或 L1 仅限已认证且非 PII（demo 全部 L0）。

### 5. 创新类型

**反定位：** 记忆 API 卖 `add()`；本产品卖 `add()` 失败。蓝海是写入时的出处闩。情报锚：source certification 开放问题。

### 6. 与红海产品的差异化

| 现有方案 | 本方案 |
|----------|--------|
| Mem0 add() | 写入 | 无源拒绝写入 |
| MemoryForensics | 事后审计 | 事前闸 |
| CiteGate | 外发文档 | 内记忆条目 |

错位失败：自动把无源摘要写成长期记忆。仍值得做：与刑侦成对，写入侧更像 FreshLatch 亲兄弟。

### 7. 使用场景与用户旅程

会话里模型抽出「客户年费 12 万」。语料中只有「约 10 万级」。Certifier 拒绝 commit。人看到缺口。对照：裸 `add()` 必须让 12 万进入召回。

### 8. 核心功能模块

候选抽取；源绑定；数字核对；拒绝账本；人批；eval：无源 must_reject；MCP `propose_memory`/`commit_memory`。

### 9. 技术架构

| 角色 | 类型 | 职责 | 禁止 |
|------|------|------|------|
| Extractor | 短循环 | 候选 | 直接 add |
| Certifier | 真 Agent | 找源 | 无源 commit |
| Critic | 真 Agent | 多出的数字 | 放行 |
| 规则闸 | Workflow | 无 checksum 拒绝 | 扮演认证 |
| HumanLatch | Workflow | PII/低置信 | 静默写 |

工具：`retrieve`、`read_source`、`propose_memory`、`reject_memory`、`commit_memory`（人闸后）、`spawn_critic`。数据：合成会话+合同摘要。Windows：Python 3.11。

### 10. 商业模式

按管道或按拒绝次数不收费（避免反向激励）。订阅对齐「受治理的记忆写入」。不要保证合规认证。

### 11. 获客与分发

## PHASE 3：最终推荐与决策

分数沿用前文各套第 19 节，不改分。本节是拍板记录，不是对前文 20 节的删节版。

### A. Top 3 推荐方案（综合商业与面试价值）P0

1. **FreshLatch（P0）：** 两端目标同时成立——时间路由 Agentic RAG 与 fail-closed 作废闸是 2026 面试核心，复验单有顾问付费场景，个人 2 周能做出看起来像产品的 demo。与前四轮 E 错开，定义本轮公司曲线：签发之后的作废层。情报：Mem0 staleness 未解决、GitHub 过期记忆更危险、Confluent 过期数据上的 Agent 失败。
2. **QuoteTTL（P1）：** 变现路径最贴个人开发者，差异化清晰（保质期 vs 比价）。商业 9。
3. **MemoryForensics（P1）：** 护城河叙事与 Memory 必考题对齐；可开源获客；也可作为 FreshLatch 的可靠性模块。

不进 Top 3 的简因：LivingBrief 是皮肤不是第二公司；CommitWatch 采购偏治理；SkillRot / IncidentReplay 面试强、现金弱；ShiftDecay 有伪 Agent 风险；BronzeCheck 预算薄；ProvenanceWatch 并入 E 写入面。

> 结果：2026-09 公开清单含 Agent loop、Memory、MCP、Skills、Eval、LangGraph。截至 2026-09-19。B 级培训源，与官方叙事一致。

### B. Top 3 快速 Demo 方案（2 周内可完成）P0

最快的三个是 **QuoteTTL、LivingBrief、FreshLatch**。共同原因：数据在 Markdown 里，少企业连接器，UI 戏剧性强（红灯）。

**QuoteTTL：** 建议 2 周出字段红灯 + 含税守恒。  
**LivingBrief：** 建议 2 周出三栏导出 + `as_of` 页眉。  
**FreshLatch：** 建议 2 周出复验单 + Critic 反证，4 周出作废重跑 + freshness 金标。

三套不要与 E 的 12 周混用同一主仓乱加功能。若执行 E，QuoteTTL / LivingBrief 只能当副目录或第 8–12 周展示附件。

所需组件最新口径（截至 2026-09-19）：Python 3.11、OpenAI 兼容 chat.completions tools、Chroma、FastAPI、mcp Python SDK、LangGraph 1.x checkpoint（加分）。不要 Docker。

### C. Top 3 面试展示方案 P0

最适合面试的三个是 **FreshLatch、SkillRot、MemoryForensics**。共同理由：2026 作品集最缺的不是「我接了 RAG」，而是真 Agent loop、时间/源认证、MCP/Skill 分层、eval。

**FreshLatch：** 开场即 T0/T1 复验。作废不得绿灯。对照 EvidenceOS 一句。  
**SkillRot：** 开场 MCP schema vs Skill 散文。不是 linter。  
**MemoryForensics：** 开场隔离死事实。对照 Mem0「我们不卖存储」。

若面试只够带一个仓库：带 **FreshLatch**（与 E 一致），口播 90 秒收 MemoryForensics（可靠性）与 SkillRot（Skill 卫生）为同一作废层的两张侧脸。不要现场 demo 三个产品。

「为什么不用现有工具」：Mem0/Zep 优化召回；LangSmith 优化轨迹；Perplexity 优化首答；EvidenceOS 优化 T0 卷宗。它们都不会把「上周绿灯作废」当主按钮。

### D. Top 3 商业化方案 P0

最适合个人未来发布的三个是 **QuoteTTL、LivingBrief、CommitWatch**。共同理由：痛在钱包或职业信誉、可按次收费、销售周期短于企业记忆中台与观测平台。

**QuoteTTL（商业 9）：** 按份。话术防比价。  
**LivingBrief（商业 8.5）：** 按课题。页眉保质期。  
**CommitWatch（商业 8）：** 按决议包。免责声明。

FreshLatch 战略上可以是公司名，第一笔现金也可能来自顾问课题制；D 组三套更「下周就有人付钱」。现金可以来自 D；公司叙事仍回到 E。需要面试加强时用 SkillRot / MemoryForensics 另开目录，不得反向把公司改名叫报价插件或记忆插件。

类似产品定价锚：顾问课题 3000–8000 元；个人知识工具 $29–49/月；开发者可靠性工具难卖席位、适合实施费。B 级类比，非审计。

### E. 如果只能选 1 个：完整立项建议

#### 一句话决策

**立项 FreshLatch 复验闩，作为「时效作废」的第一个楔子。** 12 周内只做一类课题（市场进入简报里的价格 / 竞品 / 监管主张是否仍成立），把「T0 主张 + T1 语料 + Lead 循环 + Critic 动态派驻 + 过期不得绿灯 + 人审作废或续命 + claim-level freshness」做成可演示、可给顾问看的切片。叙事是 2026 年软件不缺答案也不缺卷宗，缺的是被时间挑战后仍敢亮绿灯——以及不敢时如何作废。

不立项 QuoteTTL 作为唯一主线：商业 9，但技术故事容易被说成抽取与比价，与 Applied Engineer 的 Agentic RAG / Memory 拷问弱于复验引擎。不立项 MemoryForensics 作为唯一主线：面试 9.5，付费人群偏工程，会把蓝海项目5 写成记忆插件注释。不立项 SkillRot 作为唯一主线：面试 9.5，12 周易收成 linter。不立项 IncidentReplay 作为唯一主线：面试 9，工程与 LangSmith 阴影过高。不把 LivingBrief / ProvenanceWatch 当公司名：它们适合当挂在复验引擎上的皮肤与写入闸。

#### 目标用户与第一批 3 类客户画像

目标用户是已经发出过判断、被客户或老板追问「还成立吗」的人。经济买方常常就是日活。明确拒绝只要更快摘要或无限记忆的采购。

**画像 1：独立顾问（中国现金楔子）。** 两周前发过市场进入 brief。买的是可再发的复验单。Demo 用合成笔记，不碰对方客户机密。

**画像 2：创始人兼战略。** 要决定是否仍执行三个月前的进入决议。买的是作废与缺口，避免自己 confirmation bias。

**画像 3：Sales Engineer / 售前。** 要给客户的「为何选我们」材料保质期。后期可接到 QuoteTTL Skill，12 周不做 ERP。

三类共同成交句：当场把一条 T0 绿灯主张在 T1 打红，并展示 Critic 的已死反证与作废重跑。共同非客户：要企业搜索平台、要自动商业决策、要「我们支持所有连接器」、要无限记忆。

#### 12 周 demo / MVP 里程碑（Windows 个人开发者可执行）

环境固定：Windows 10/11、Python 3.11、VS Code、PowerShell、Chroma 或 SQLite、FastAPI 或 Streamlit、OpenAI 兼容接口。不上 Kubernetes，不要 Docker。代码若开始写，放蓝海项目5 新目录，**不改前四轮仓库**。中文 UTF-8；PowerShell 先设 `$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new()`。

**课题家族锁定（W1 第一天选定，此后禁止改）：** 默认「两周前那份市场进入判断里的主张，现在是否仍成立」。语料用合成访谈、成本模型、竞品笔记（T0）+ 故意变更的监管/媒体/价格（T1）。禁止改成通用开放域问答，禁止再做一遍 EvidenceOS 新调查。

**技术选型（截至 2026-09-19）：**  
- 模型：OpenAI 兼容 `chat.completions` + tools（DeepSeek / 硅基流动 / 官方均可），不必绑定单一云。  
- 编排：薄 Python runner 实现真 Agent loop；LangGraph 用于 checkpoint / interrupt 等人续命，**图不是 Agent**。  
- 向量库：Chroma，metadata 含 `source_type`、`as_of`。  
- MCP：暴露 `retrieve` / `read_source` / `reverify_claim`。  
- Skill：`skills/reverify.md`、`skills/devil_advocate.md`、`skills/freshness_audit.md`。  
- 评测：`data/eval/gold.json` 必须 stale 的 claim_id。

**W1–W2：契约、双时索引、Lead 循环、复验单 UI。** 手写 claim schema（statement、t0_evidence_ids、t1_evidence_ids、status、last_confirmed_at）。LeadAgent 最大 18 轮：`retrieve`、`read_source`、`reverify_claim`、`mark_stale`、`mark_gap`、`finish`。无 T1 evidence_ids 不得 status=fresh。UI：主张、新旧原文、轨迹。验收：不得出现无 T1 原文的绿灯；主按钮不得叫「生成答案」。

**W3–W4：Critic + 人闸 + freshness。** CriticAgent 独立找已死主张，Lead 动态 spawn，不是固定第 3 步。作废 id 进禁用名单重跑。评测页：fresh/stale/unknown。对照：一次无工具 LLM 长文必须在「已死主张」上假绿，而本产品必须红。验收：**W4 结束仍不能演示点回 T1 原文，或 Critic 零有效已死反证，则立项失败。** 主界面若已变成聊天框，或产品被复述成「又一个 EvidenceOS」，同样失败。

**W5–W8：Auditor、黄金集、MCP、一份完整复验包。** Auditor 短循环；stale/unknown 代码不得绿灯。`data/eval/gold.json` 回归。MCP server 暴露 retrieve/read/reverify，面试可接 Claude。导出复验单 Markdown（不是法律意见、不是自动决策）。开始记 token / 延迟，但不按 token 卖。LangGraph interrupt：续命必须等人给 T1 原文。

**W9–W12：口播、第二份更脏 T1、停止 / 继续。** 8–10 分钟口播跑通并录音。找 1 个顾问用脱敏材料本地跑一次；找不到则用第二份故意自相矛盾的 T1 语料补。账本字段预留报价/决议 Skill 形状，12 周不实现 QuoteTTL 或 CommitWatch 产品。W12 评审停止条件。

#### 技术切片与必须能指出来的六件事

1. **真多 Agent：** Lead 与 Critic 均为工具循环；派驻由模型根据「T1 是否与 T0 冲突」决定。
2. **诚实 Workflow：** 过期绿灯闸、作废名单、stale 剔除、步数预算。
3. **Agentic RAG：** 改写查询、换 private/public、换 `as_of=T0|T1`；禁止一次 top-k 完事。
4. **fail-closed：** 无 T1 原文、被作废、审计失败，不得保持绿。
5. **评测：** claim-level freshness 与黄金 must_stale，不是「报告好读」。
6. **MCP / Skill：** 同一套检索/复验工具经 MCP 暴露；复验纪律写在 Skill 文件里。

**如何复用前四轮（只读）：** 搬纪律（人闸、诚实自治、评测、fail-closed），不搬成第二个 EvidenceOS 或第二个 CiteGate。RaidFix / AgentRedTeam 的评测思想可口播，12 周不实现红队产品。**不改历史项目代码。**

#### 变现

前 6 个月卖课题制 3000–8000 元或 $49 月订，用服务换的是场景包与金标，不是客户全量机密。验证有人愿为「可再发的复验单」付钱后，再收团队席位。对咨询机构白标是 9–12 月选项。若 6 个月零成交，先降价换 1 个深度设计伙伴，而不是立刻改卖 QuoteTTL 并宣布主线转向；副业可以做，主品牌不能改。

#### 12 个月演进

- **0–3 月：** 一类复验成为可卖切片；3 个项目制或设计伙伴。
- **3–6 月：** 导出活简报皮肤；开始订阅；QuoteTTL 可另开目录当副业。
- **6–9 月：** 一个只读连接器。仍禁止做成企业搜索或记忆中台。
- **9–12 月：** 复验引擎 API 供给 QuoteTTL / CommitWatch / ProvenanceWatch Skill。公司对外一句话稳定为：让 Agent 复验已签发主张，并用 T1 原文、反证与人审证明没有假绿。

#### 面试 8–10 分钟口播提纲

- **0:00–0:40 定位。** 「Answers and dockets expire. I built a reverify latch. LeadAgent loops on T0 and T1. A critic hunts dead claims. Stale cannot stay green. Renew requires a T1 span.」
- **0:40–2:00 为何是 2026。** 记忆层标配但 staleness 官方未解决；MCP 与 LangGraph 让复验可工具化、可暂停；Gartner 取消潮要的是风险控制不是更多试点。
- **2:00–4:30 现场。** 导入 T0 主张 → 按 as_of=T1 改写检索 → 主张从绿变红 → Critic 已死反证 → 作废重跑 → freshness 页金标。
- **4:30–6:30 生产纪律。** 无 T1 闸；fail-closed；激励分离（Critic 不得把死主张判活）；诚实自治 L1 复验 / L0 续命给人。
- **6:30–8:00 评测。** 北极星 must_stale 与作废率。对照无工具假绿。
- **8:00–9:30 公司曲线。** 复验引擎 → 报价/简报/决议 Skill；记忆刑侦与 Skill 腐烂是可靠性模块。对照前四轮 E：出门、动手、认款、证据，这是作废层。
- **9:30–10:00 缺口。** 无企业 SSO；一类课题；真实机密不进作品集。留问答。

全程术语：agent loop、agentic RAG、as_of、memory staleness、source certification、eval、latch、fail-closed、MCP、Skill。禁止开场「我做了个知识库 GPT」或「我做了第二个 EvidenceOS」。

#### 最大风险与停止条件

最大风险：

1. **做成聊天搜索。** 主界面必须是复验单。
2. **做成 EvidenceOS 换皮。** 口播第一句是作废与 T1，不是取证。
3. **过期仍绿灯。** 代码闸 + eval。
4. **空平台。** 12 周一类课题。
5. **与历史仓库纠缠。** 新目录、只读参考。
6. **真实客户机密进作品集。** 合成 / 脱敏，界面标明 synthetic。
7. **为了成交把主仓改成 QuoteTTL / LivingBrief 内容工厂。** 副业可以，主品牌不能改。

停止条件（触及则停止加功能，先复盘是否立项失败）：

- **W4 结束**仍不能演示点回 T1 原文，或 Critic 给不出可理解的已死反证。
- **W8 结束**仍无作废名单、无 freshness 页、无 MCP 或等价工具暴露。
- **W12 结束**外部观察者仍把产品复述成「AI 搜索」「行业 GPT」或「第四轮卷宗换皮」，两次纠正无效。
- 为了成交把主按钮改成生成答案，或把主仓改成比价工具 / 记忆中台，时效作废叙事被主动放弃。
- 真实客户完整机密资料进入公开作品集——立即停、项目降级为仅合成。

未触及停止条件，则按 E 执行 12 周，再决定是否把 QuoteTTL 升为第二产品表面，或另开目录做 MemoryForensics 面试加强件。批准本正本不等于批准改前四轮代码，也不等于批准开始写 FreshLatch 实现；开始写实现时以本正本纪律为准，另开任务，不把「先写一堆示例代码」当成已经完成立项。

**明确不选的平庸方向：** 通用企业 Copilot、又一个 SDR 群发 Agent、无垂直的 Agent 平台、无评测的 RAG 聊天框、又一个 Mem0 套壳、EvidenceOS 换皮调查。
