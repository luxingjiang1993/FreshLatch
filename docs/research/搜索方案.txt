# PHASE 1: 生成阶段 - 10 套产品概念方案（情报驱动）

基于 Phase 0 的情报，生成 10 套方案。每套方案必须**引用至少 1 条 Phase 0 的情报**作为支撑。

## 硬性要求

每套方案必须满足以下**至少一项**：
- 蓝海机会（基于最新技术拐点）
- 红海替代品（基于竞品弱点）
- 反定位（基于 incumbent 无法跟随的新范式）
- 颠覆式创新（基于边缘市场切入）

**禁止**：小工具、小插件、伪需求、"AI 助手"式泛泛而谈。

## 技术要素 checklist（每套方案必须明确包含）

- [ ] **真正的 AI Agent**（符合 Anthropic 定义：自主规划、使用工具、动态决策，非纯 Workflow）
- [ ] **Multi-Agent 协作**（至少 2-3 个 Agent 分工，如 Planner/Executor/Critic）
- [ ] **Agentic RAG**（非简单向量检索，需包含查询重构、路由、反思、工具调用）
- [ ] **Function Call / MCP / Skill**（工具调用的具体设计）
- [ ] **记忆与个性化**（短期上下文 + 长期记忆架构）
- [ ] **评估与反馈闭环**（如何监控 Agent 表现、用户反馈如何回流）

## 输出结构（每套方案 20 个模块）

请严格按照以下结构输出，使用 Markdown 表格和分级标题：

### 方案 X：[名称]

1. **一句话定位**：不超过 30 字
2. **目标用户**：具体到角色、行业、公司规模

# PHASE 2: 评审阶段 - 深度事实核查与风险分析（Grok 增强）

生成完 10 套方案后，立即进入评审阶段。对**所有方案**进行以下维度的严格审查，**每条评审意见必须基于 Grok 查询的实时信息**：

## 评审维度 1：技术真实性核查（Anthropic 专家视角 + Grok 验证）

检查每套方案是否**真正符合 AI Agent 定义**：
- [ ] **自主性**：Agent 是否能根据中间结果调整计划，而非固定 Workflow？
- [ ] **工具使用**：是否明确列出 Function Call 的具体函数签名？
- [ ] **反思能力**：是否有 Critic/Evaluator Agent 进行自检？
- [ ] **MCP 集成**：是否明确使用 Model Context Protocol 连接外部数据源？
- [ ] **RAG 质量**：是否有引用验证（Citation Verification）机制？

**Grok 验证查询**：
- "Anthropic AI agent definition autonomous"
- "MCP protocol specification latest version"
- "Agentic RAG benchmark evaluation 2024"

**标记**：如果某方案只是"披着 Agent 外衣的 Workflow"，标记为 ⚠️ **伪 Agent**，并给出修正建议。

## 评审维度 2：商业现实检验（硅谷 PM + VC 视角 + Grok 验证）

**Grok 验证查询**：

- "enterprise AI adoption barriers survey"

## 评审维度 3：用户真实性检验（中美用户代表视角 + Grok 验证）
