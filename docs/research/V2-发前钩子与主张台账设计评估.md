## 1. 问题 + 前置约束

I2 冒烟 Exit 已齐后，下一跳是 V2（ADOPTION）：把「能复验」推进到「要发了还会被闸拦一次」，并让主张作废/续命历史可查。路线图原文 In 极薄（≥1 嵌入钩子；主张 ID 作废/续命列表），但词「Embed」与仓内检索 `embed` 撞车；Client Memo CLI **明确不跑复验**；作废已有 `invalidation_list`，续命只在 `latch_log`。

| 前置 | 来源 | 锁死作用 |
|------|------|----------|
| V2 Goal = 采用；Out = 大图谱 / 全量采编平台 | roadmap | 禁止把 V2 做成旧 Phase C |
| Client Memo 禁商业裁决、禁轨迹 | ADR-0015 | 钩子出口不得写「建议进入市场」 |
| 作废名单单一真相；写路径唯一 = human_latch | ADR-0006 | 台账禁止新表双写 |
| 补丁 ≠ HumanLatch 动词；导出与 Memo 分轨 | ADR-0029 | 台账 ≠ patch_events；补丁包非主钩子 |
| 包结论三值；未收口 stale→勿发 等 | ADR-0027 | 钩子闸读 disposition，不发明第四套词 |
| 生产默认 BM25；Studio 冻结；Hard-Gold 另票 | roadmap / ADR-0003 | V2 不得改臂、解冻 Studio |
| Anthropic：demo≠统计；Exit 预锁禁 HARKing | 纪律清单 | 冒烟采用层；curl ≠ webhook 平台已交付 |

验收层：**冒烟 · 采用层**（非采用率统计、非插件商店、非采编平台）。

## 4. 拍板 + 子决策

1. **产品名**：发前钩子（publish hook）+ 主张台账（claim ledger）；路线图英文 Embed 仅为历史别名，正文以中文为准。  
2. **闸语义**：只读包结论 + T1 checksum/`run_id` 机械新鲜度；**不**在导出路径强制整包再验。  
3. **硬出口**：Client Memo（UI「导出客户备忘」+ CLI `freshlatch.export client-memo`）同闸；**入站** HTTP check（必填 `run_id`；默认 `127.0.0.1`；可选 `X-FreshLatch-Hook-Token`）。  
4. **需补丁**：默认 deny 干净导出；请求/表单带 `ack_needs_patch=true` 才允许，并强制页眉「需补丁」。**勿发**：拒导出、钩子 `allow:false`、不落 Memo 文件。  
5. **加分另票**：内部 sheet / Evidence-bound 补丁包套同一闸函数。  
6. **主张台账**：`invalidation_list` ∪ `latch_log`（discard/renew）只读投影；挂 Run 详情旁路（默认可折叠）+ 可导出 MD；**零新写表**。  
7. **Backlog 备选**：C′ 外部嵌入平台化（Word/PPT/Notion 插件、开放 webhook）；大图谱 / 全量采编 CMS（仍非近端主线）。  
8. **明确弃**：Memo 商业裁决；扩 HumanLatch / renew 改正文；未过 Hard-Gold 改默认臂；解冻 Studio；双写作废表。  
9. **Exit（预锁）**：文首冒烟声明；(1) 样例 Run 人审后 disposition 可知；(2) UI/CLI Memo 闸动作正确；(3) curl 入站 hook allow+deny 各 ≥1；(4) 台账可见本次 discard/renew claim_id；(5) `docs/evidence/v2/ACCEPTANCE.md`。不硬绑「可发」。  
10. **ADR-0031** + 本评估 + CONTEXT + roadmap 完整对齐。

## 6. 面试讲法

**Q: V2 的 Embed 是向量化吗？**  
A: 不是。历史路线图标题叫 Embed + ledger；产品词是**发前钩子**和**主张台账**。检索 embed 仍是 Phase A 评测臂，与 Adoption 无关。

**Q: 你们做了 Notion/Word 插件吗？**  
A: 没有平台化插件。本期只有**入站 check API**（本机 + 可选 token），用 curl 证明外部事件能触发同一闸。Word/Notion/开放 webhook 在 Backlog「C′」，图谱/采编仍非近端。

**Q: 导出前为什么不重新跑一遍 Lead？**  
A: 采用钩子要便宜、确定、可测。读上次包结论 + checksum 漂移拒绝即可；强制整包再验是演示/事故修复（B′）的事，不是打包闸的默认成本。

**Q: 主张台账是不是新数据库？**  
A: 不是。作废名单和 latch_log 早就存在；台账是只读投影。新建双写表会破坏「写路径唯一 = human_latch」。

**Q: 和 Client Memo / 补丁导出什么关系？**  
A: Memo 是对客主出口，挂发前钩子。Evidence-bound 补丁包仍分轨（改稿证据）。台账讲人审历史，不是 patch_events 论文账。

**Q: Exit 怎么算「被工作流点到」？**  
A: 预锁冒烟：Memo 闸正确 + curl allow/deny 各一次 + 台账能列出本次作废/续命。文首声明冒烟层，不报采用率，不宣称 webhook 平台已交付。
