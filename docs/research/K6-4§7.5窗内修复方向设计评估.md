## §候选路线(每个决策维度的全部候选,含被否项)

### D1 主杠杆类别(窗内唯一主修)

- **(a)** 机械闸补洞:block 后未成功受理过 `reverify_claim(fresh)` 前,拒绝 `reverify_claim(unknown)`。(拍板)
- **(b)** 打回后续开会话(#27 A-乙)。
- **(c)** 结构性强制观察(类 auto_critic),仍靠模型自觉申 fresh。
- **(d)** 教义/人格/提示词加厚(无新机械闸)。
- **(e)** 松预检/松双判/改 gold 或通过线。

### D2 「至少一次 fresh」操作定义(D1=a)

- **(1)** block 之后曾成功受理一次 `reverify_claim(fresh)` 才允许 `unknown`。(拍板)
- **(2)** 只要求 block 后再 `retrieve(T1)`。
- **(3)** retrieve + fresh 双条件。
- **(4)** 其他(须不泄锚)。

### D3 次型(c6×1 同维自标错 stale)范围

- **(A)** 只修主因路径;次型不进 #59 必做。(拍板)
- **(B)** 主因+次型同包。
- **(C)** 次型另票但必须同钟并行。

### D4 给 #59 的验收分层(不改通过线)

- **(i)** 同线复验一次;机制读数与行为层分层声明;过线不升格一期闭合。(拍板)
- **(ii)** 另加机制层硬门槛(如 fresh 尝试率 100%)作窗毕业条件。
- **(iii)** 行为过线即可,机制不留档。

### D5 ADR

- **(α)** 增补 ADR-0012(§2 收口次序 + 后果条款)。(拍板)
- **(β)** 新开 ADR-0015。
- **(γ)** 不记 ADR。

### D6 soft_close / 步数耗尽

- **(1)** 维持现状:soft_close → unknown + `mechanical_precheck` 黄卡;闸只挡显式 `reverify_claim(unknown)`。(拍板)
- **(2)** soft_close 另造失败态 / 加步数。
- **(3)** block 后自动加恢复预算。

### D7 「成功受理 fresh」边界(防刷单)

- **(i)** 仅证据校验通过、写入 recorded 的 fresh 计一次;立刻 `error` 返回不计;其后双判/闸打回不影响计数。(拍板)
- **(ii)** 任何 `status=fresh` 调用(含 error)都计。
- **(iii)** 必须双判绿才计。

### D8 机制层留档事件

- **(A)** 实装 `post_precheck_unknown_refusal` + `post_precheck_fresh_accepted`;与行为层分列。(拍板)
- **(B)** 不新事件,事后翻 tool_trace。
- **(C)** 事件进通过线硬门槛。

## §拍板 + 逐项子决策

**拍板:D1-(a) + D2-(1) + D3-(A) + D4-(i) + D5-(α) + D6-(1) + D7-(i) + D8-(A)。**

1. **主修**:本会话曾出现 `dimension_precheck_block` 之后,在尚未**成功受理**过一次 `reverify_claim(fresh)` 之前,机械拒绝 `reverify_claim(unknown)`。错误文案为逐字锁档常量(与预检/额度/finish 三段同族),修改走评审。**不**以教义/人格为修复主力。
2. **成功受理**:证据校验通过并写入 recorded 的 fresh;校验失败的 `error` 返回不计;其后双判/规则闸打回**不**撤销「已尝试」计数,也**不**降双判/闸门槛、不放行。
3. **soft_close**:不变。耗尽仍 unknown + `mechanical_precheck` 黄卡;行为层如实未愈由同线复验抓住。
4. **次型**:不进 #59 必做;窗后若仍见再另票。
5. **#59 验收分层**(方向句,不改通过线):
   - 行为层:同一 K6-4 线(各 ≥2/3 且合计 ≥5/6;n=3、temp=0、qwen-flash;fresh 仅双判一致);must_stale 回归守线不变。
   - 机制层:可引用 `post_precheck_fresh_accepted` / `post_precheck_unknown_refusal` 次数与既有 `dimension_precheck_block`;**不得**把机制读数焊成通过线。
   - 过线不得写成判定层已愈 / 一期评测闭合;再不过 → §13,不得续杯。
6. **禁区兑现**:不改 gold/通过线;不松闸;不以提示词第三次重试凑绿。
7. **ADR / 词表**:增补 ADR-0012;touch-up「同维度复验」(unknown 收口次序)。
8. **本工单**:不实装、不跑 #59、不关地图。

## §面试讲法(grilling 预案)

**Q:开窗了,你们打算改提示词让 Lead 记得去申 fresh 吗?**
A:不。#21 已证人格/提示词 0/6。主修是机械闸:预检 block 之后、成功受理过一次 `reverify_claim(fresh)` 之前,直接拒绝 `reverify_claim(unknown)`。强制性住工具边界。

**Q:这不是逼模型乱申 fresh、变相降门槛吗?**
A:不是。fresh 仍须双判一致 + 规则闸;失败的 fresh 只解锁「可以再走 unknown」,不发绿。成功受理的定义是证据校验通过写入 recorded,空调用刷不开。

**Q:为什么不连 c6 那次错 stale 一起修?**
A:那是 1/6 次型,#52 已定不进处置档。窗内主修单点对准「路径未走」;次型窗后若仍见另票,避免平行根因叙事。

**Q:修完怎么算过?机制层尝试率是不是也要 100%?**
A:行为层仍是同一 K6-4 通过线。机制层事件只供分层声明与归因,不焊进通过线——否则就是事后加判据。过线也不得写成一期评测闭合。

**Q:步数烧光还没申 fresh 怎么办?**
A:soft_close 语义不变,仍 unknown + 机械预检异议黄卡。那是行为层如实未愈,同线复验会抓住;不为恢复去改 soft_close 或加预算旁路。

**Q:为什么增补 0012 而不是新开 ADR?**
A:堵的是 0012 §2 把 unknown 与 fresh 并列合法收口留下的洞,属同一条同维复验契约。难反转、反直觉、真取舍三条件齐,后果条款把「撤此闸」列入拆行为层防线。
