> **决议工单**: FreshLatch #11 — HumanLatch 作废/续命最小交互闭环(W1–W4 版)

## 1. 问题:我们要做什么决策

HumanLatch(人审工作流,六段流程之后的第 7 段)的最小交互闭环怎么设计:人对每条红/黄灯主张点「作废」或「续命(必须带 T1 evidence_id)」,作废 id 进作废名单后该主张重跑不得再绿(代码强制),Agent 不得自己把红灯改回绿灯,Auditor 不得拥有放行权。要拍板的是五个决策维度:

1. **中断/恢复机制**:LangGraph interrupt + SqliteSaver,还是自研门闩(依赖 #7 研究结论);
2. **中断粒度**:每条主张一个 interrupt,还是一轮复验一个 interrupt 批量审批;
3. **作废后的重跑语义**:范围(单主张/整轮)、触发(人点/自动)、展示(void 灰显/时间线);
4. **续命闭环的参数与校验链**:evidence_id 来源(下拉/自由文本)、checksum 语义、生效后写什么、「禁令只约束 Agent」的口径;
5. **W1–W2 与 W3–W4 的切分**:最小版含不含 HumanLatch、含不含续命。

## 3. 候选路线

### 维度一:中断/恢复机制

- **路线 a:LangGraph interrupt + SqliteSaver**(#7 研究推荐):节点内 `interrupt()`,checkpointer 落盘,`Command(resume)` 恢复,图只做人审管道。
- **路线 b:自研门闩**(`blocked_for_human → approve_promotion`,参照 `project 多agent` runner.py):state 序列化 JSON/SQLite + flag + 进程退出重启恢复,零额外依赖。

### 维度二:中断粒度

- **(i) 主张级**:每条红/黄灯主张一个 interrupt、一个 thread_id,复验单卡片显示「待人工」徽章,逐条 resume。
- **(ii) 轮次级**:Scribe 排版后图在收尾节点 interrupt 一次,待审主张清单批量呈现,一次 resume 传整个决定列表。

### 维度三:重跑

- **范围**:(α) 只重跑被作废的主张;(β) 整轮全部重跑。
- **触发**:(α) 人点「重跑作废主张」按钮;(β) 作废即刻自动触发。
- **承载**:(α) 原 thread `update_state` 回退再跑;(β) 新开 thread 跑单主张迷你复验。

### 维度四:续命 evidence 来源

- **(α) 下拉选择**:从本轮 Lead 已检索到的 T1 块里选。
- **(β) 自由文本**:手动输入任意 `doc_id#anchor`。

### 维度五:W1–W2 切分

- **(α) 零 HumanLatch**:W1–W2 纯 Agent 复验单,W3 起接作废。
- **(β) W1–W2 带作废按钮**(无重跑):产品灵魂尽早可见。

## 4. 逐路线评估

### 4.1 中断机制:a vs b

| 维度 | a: LangGraph interrupt | b: 自研门闩 |
|---|---|---|
| 代码量 | 少(3 个 API:interrupt/Command/compile) | 多(state 序列化、flag 管理、恢复入口、重试逻辑自写) |
| 状态一致性 | checkpointer 原子写入,框架保证 | 自保证,写入中途崩溃可能状态损坏 |
| 节点重执行 | ⚠️ interrupt 前代码重跑,需幂等 | 不存在重执行 |
| 回退/倒带 | `update_state()` 原生支持 | 自实现状态回滚 |
| 多 interrupt 串联 | 原生支持 | 状态机自己设计 |
| 依赖与升级风险 | langgraph+langgraph-checkpoint-sqlite,锁 >=1.0,<2.0,用法隔离独立模块 | 零依赖零 API 风险 |
| 调试可见性 | Studio 可视化 checkpoint 历史 | 自己读 JSON |
| 参考先例 | 无现成代码(#7 盘点结论),但官方文档完备 | `project 多agent` runner.py 验证过 |
| FreshLatch 适配 | 「图不是 Agent」下图只做 checkpoint 容器,正中用例 | 也适配,但基础设施重复造轮子 |
| 面试叙事 | 「用行业标准 HITL 原语,Agent 循环跑图外」 | 「零依赖自制门闩」——被追问崩溃一致性时答「写 JSON 前备份」较弱 |

### 4.2 中断粒度:(i) vs (ii)

| 维度 | (i) 主张级 | (ii) 轮次级 |
|---|---|---|
| 与六段流程的契合 | HumanLatch 是第 7 段、Scribe 之后,主张级把第 7 段切碎插进第 2–5 段之间 | 顺序天然:整轮跑完 → 中断 → 人审 → 收尾 |
| thread_id 数量 | 12 主张 = 12 thread,checkpoint 膨胀 | 一轮 1 个,重跑再加 1 个 |
| UI 状态复杂度 | 每卡片徽章 + 各卡独立恢复态 | 单一「待人工」横幅 + 批量表单 |
| resume 次数 | 最多 12 次 invoke | 1 次 |
| 灵活性 | 可逐条先放行的复杂审批流 | 一次性批处理 |
| 本期规模适配 | 过度设计 | 正好 |

### 4.3 重跑三子维度

| 子维度 | 选项 | 评估 |
|---|---|---|
| 范围 | (α) 单主张 / (β) 整轮 | (α) 省 token(只重跑一条)、语义干净(作废是单条主张的人审决定);(β) 浪费且引入「其他主张会不会被人审污染」的无关问题。选 **(α)** |
| 触发 | (α) 按钮 / (β) 自动 | (α) 人保留反悔窗口(点作废后未重跑前可再议——作废已落库但重跑未发生)、W3 演示叙事「人点按钮→看到仍红」更有戏剧性;(β) 自动触发让作废瞬间不可撤。选 **(α)** |
| 承载 | (α) 原 thread 回退 / (β) 新 thread | (α) 依赖 `update_state()` 回退 API,LangGraph 使用面变大、版本升级风险升高,且「回退再跑」违反「一次复验=一个 thread」的干净语义;(β) 新 thread 就是「一次复验=一个 thread」的自然延伸,结果挂时间线。选 **(β)** |

### 4.4 续命 evidence 来源:(α) vs (β)

| 维度 | (α) 下拉选择 | (β) 自由文本 |
|---|---|---|
| 「必须带 T1 evidence_id」的强制 | 选择器天然满足,没得选就不存在违规 | 需后端校验 id 合法性 + 是否 T1 + 是否本轮检索过,错误面大 |
| checksum 校验面对的输入空间 | 有限(已读块) | 任意 doc_id#anchor,失败模式多 |
| UI 实现成本 | 复验单已有 T1 块渲染,下拉选项现成 | 输入框 + 校验错误提示 |
| 灵活性(证据在召回外) | 人不能续命一个 Lead 没找到、但人自己知道的证据 | 可以 |
| 本期取舍 | 续命 W5 才实装,届时 Lead 检索质量已成熟,召回内选择够用 | 多出来的灵活性用不上 |

### 4.5 W1–W2 切分:(α) vs (β)

| 维度 | (α) 零 HumanLatch | (β) W1–W2 带作废 |
|---|---|---|
| 切片权威 | W1–W2 验收清单(无 T1 不得绿灯/无聊天框/无开始调查)明确不含作废 | 与切片冲突,需改切片 |
| W1–W2 生死闸 | 「无 T1 不得绿灯」需要 Lead 循环 + 规则闸打磨到位,人力集中 | 提前铺 HumanLatch 挤占循环打磨 |
| 演示叙事 | W3 才出现「人作废」瞬间 | 更早可见 |
| 依赖就绪度 | 不需要任何 LangGraph 依赖进 W1–W2 | W1–W2 就要引 langgraph 依赖 |

## 5. 最终拍板

**维度一选 a(LangGraph interrupt + SqliteSaver);维度二选 (ii) 轮次级单 interrupt;维度三 = 单主张 + 按钮触发 + 新 thread;维度四选 (α) 下拉选择;维度五选 (α) W1–W2 零 HumanLatch。**

子决策全表:

### 5.1 中断机制子决策

- **锁版本** `langgraph>=1.0,<2.0`;LangGraph 用法隔离到独立模块(如 `src/freshlatch/latch/`),Agent 循环不 import langgraph。
- **checkpointer** = SqliteSaver,文件 `data/checkpoints.db`。
- **thread_id 规范** = `reverify-{claim_id}-{ts}`;一轮复验 = 一个 thread_id;重跑 = 新 thread(见 5.3)。
- **节点幂等纪律**:interrupt 前的代码必须幂等;副作用全部放 interrupt 之后(#7 研究报告关键行为)。

### 5.2 中断粒度子决策

- 图形状:`START → prepare_review → interrupt()(收尾节点) → execute(按决定列表分支) → END`。
- resume payload = 整个决定列表 `[{claim_id, action: "discard"|"renew", evidence_id?, reviewer_note?}, ...]`。
- UI:复验单顶部「待人工」横幅 + 批量审批表单;无逐卡片徽章。

### 5.3 作废闭环子决策(W3–W4 实装)

- 流程:人点「作废」→ 双重确认弹窗(「作废后重跑不得再绿,确认?」)→ `status=void` 灰显 + 作废记录进 `invalidation_list` 表 + `latch_log` 日志。
- **`stale` 与 `void` 并存不互斥**:stale 是 Auditor 的机器判定,void 是人的决定;复验单上一条主张可以同时带两个标记。
- 重跑:人点「重跑作废主张」→ 新 thread 跑只含该主张的迷你复验 → 结果挂该主张卡片时间线(「重跑后仍红(第 N 次)」)。规则闸查作废名单,即使 Lead 判 fresh 也强制打回。
- 不自动触发:作废到重跑之间保留人的反悔窗口。

### 5.4 续命闭环子决策(W5–W8 实装,W3–W4 设计定稿)

- evidence_id 从**本轮已检索 T1 块下拉选择**(非自由文本);按钮无 evidence_id 时 disabled。
- 生效链:checksum 校验通过 → 写**新的 validity_basis(T1 doc+checksum)** → 更新 `last_confirmed_at` → `status=fresh`。
- **禁令口径**:「Agent 不得把红灯改回绿灯」只约束 Agent 侧工具链(白名单 fail-closed 已保证 Agent 无写 void/改判定的工具);人审是 L0 合法出口,规则闸注释写明。
- W3–W4 复验单:续命按钮渲染但 disabled,tooltip「W5 开放:续命必须带 T1 原文证据」——完整闭环形状可见,红线以禁用态可见。

### 5.5 作废名单存储子决策

- SQLite `invalidation_list(claim_id, voided_at, actor, reason?)` 表,**随课题持久**(跨 Run 有效)。
- 与长期记忆「已废 id」是**同一份真相**:W9 记忆模块读这张表,不复制。
- Lead 上下文「作废名单」段与规则闸校验都查这张表——单一真相,读写两处不各自维护。

### 5.6 双保险与人审日志

- **代码层**:写路径唯一 = `gates/human_latch.py`(由它调规则闸);Agent 白名单 fail-closed(ADR-0001 机制);Auditor 无放行权(#10 已定)。
- **交互层**:按钮 disabled 逻辑(无 evidence_id 续命不可用)+ 作废双重确认弹窗。
- **人审日志必做**:`latch_log(ts, claim_id, action, evidence_id?, actor="human")`——审计迹 + 用户作废率(在线指标)取数口。

### 5.7 评测纪律子决策

- 评测模式**代码级跳过 HumanLatch 节点**:eval 模式图直通,interrupt 不触发,所有主张按 Auditor 判定落终态。
- 人审动作不进评测路径;must_stale 由规则闸强制,不依赖人审;作废率统计只来自在线模式。

### 5.8 FastAPI 集成子决策

- HumanLatch 端点(`/api/latch/decide`、重跑触发)写**同步 `def` 端点**,FastAPI 自动线程池执行,同步 SqliteSaver 不阻塞事件循环。
- LangGraph 异步 API(`ainvoke`/AsyncSqliteSaver)本期一律不碰,API 面最小化对冲版本升级风险。

### 5.9 checkpoint 清理子决策

- 同一主张只保留最近 5 个 thread 的 checkpoint,业务侧定期删行;不依赖 LangGraph 内置清理 API(#7 遗留问题 3 的处置)。

### 5.10 拍板方式

纯纸面拍板,不做 POC(与 #6 同一拍板方式):#7 研究已给出可运行最小示例,最大风险(SqliteSaver Windows 文件锁、进程重启恢复)留作 W3 开工第一个任务的顺带验证,不单独占一轮 POC。

## 6. HITL/人审工程手段总登记册(大而全 · 优劣势评估 · 本期处置)

> 用途一:**面试讲解**——「人审机制的手段我全盘点过,本期按纪律与规模取舍」。
> 用途二:**后续扩展可选项参考**(多轮审批、撤销回退、并发人审启用时从这里点菜)。
> 处置词汇表:**【实装】**本期启用 · **【留位】**格子已留本期空实现 · **【承载】**由已定机制承接,不是独立组件 · **【触发】**条件命中后拍板 · **【弃】**本期明确不用。

### 6.1 中断/恢复机制

| 手段 | 一句话原理 | 优势 | 代价/风险 | 参考先例 | 本期处置 |
|---|---|---|---|---|---|
| LangGraph interrupt + SqliteSaver | 节点内 interrupt 暂停,checkpointer 落盘,Command(resume) 恢复 | 3 个 API 搞定;原子写入;多 interrupt/回退原生支持 | 节点重执行需幂等;依赖版本迭代 | #7 研究官方文档 | 【实装】拍板 |
| 自研门闩(blocked_for_human) | state 落盘 + flag,重启后读 flag 继续 | 零依赖;无重执行问题 | 状态一致性自保证;基础设施重复造轮子 | project 多agent runner.py | 【弃】真实取舍,记录于 ADR-0006 |

| WebSocket 长连接等人 | 进程挂起等 UI 消息 | 无持久化概念 | 进程不能退出,关页面即丢状态 | OpenManus app.py | 【弃】中断必须跨进程存活 |

### 6.2 中断粒度与图形状

| 手段 | 一句话原理 | 优势 | 代价/风险 | 参考先例 | 本期处置 |
|---|---|---|---|---|---|
| 轮次级单 interrupt | 整轮跑完中断一次,批量决定一次 resume | thread 少、UI 简单、契合第 7 段定位 | 不能逐条先放行 | 本工单 §5.2 | 【实装】 |

### 6.3 重跑机制

| 手段 | 一句话原理 | 优势 | 代价/风险 | 参考先例 | 本期处置 |
|---|---|---|---|---|---|
| 新 thread 迷你复验 | 重跑=一次新的单主张复验,新 thread_id | 语义干净(一次复验=一 thread);不碰回退 API | 每主张多 thread,需清理策略 | 本工单 §5.3 | 【实装】 |
| update_state 回退再跑 | 回退到旧 checkpoint 重放 | 省 thread | 依赖回退 API,版本风险;语义模糊(这还是同一轮吗) | #7 研究 | 【弃】 |
| 整轮重跑 | 作废后全部主张重跑 | 简单 | token 浪费;引入无关污染问题 | — | 【弃】 |
| 自动触发重跑 | 作废即跑 | 无按钮 | 不可反悔;演示叙事弱 | — | 【弃】 |
| checkpoint 定期清理 | 同主张留最近 5 个 thread | 防 db 膨胀 | 要自己实现删行 | #7 遗留问题 3 | 【实装】 |

### 6.4 续命校验链

| 手段 | 一句话原理 | 优势 | 代价/风险 | 参考先例 | 本期处置 |
|---|---|---|---|---|---|
| evidence 下拉选择 | 从本轮已检索 T1 块选 | 强约束天然满足;错误面小 | 人不能选召回外证据 | 本工单 §5.4 | 【实装】 |
| evidence 自由文本 | 手输 doc_id#anchor | 灵活 | 校验面大(存在性/T1/本轮检索) | — | 【触发】W5 实装时若下拉不够用再议 |
| checksum 校验链 | 读当前文档算 checksum 对比 | 证据未篡改才可续命 | 需定义「对比对象」(新写 T1 validity_basis) | 切片 §8 schema | 【实装】W5 |
| 续命直接置 fresh 无校验 | 人说了算 | 最简 | 违反「checksum 对不上不得续命」切片红线 | — | 【弃】红线 |
| 新 validity_basis + last_confirmed_at | 续命写新证据基础与时间戳 | 审计迹完整,下次复验有锚 | 多一次写 | 切片 §8 schema | 【实装】W5 |

### 6.7 登记册总结:取舍逻辑一句话

> **本期 = LangGraph interrupt + SqliteSaver 的极简人审管道(轮次级单 interrupt、新 thread 重跑、下拉选证据、同步 def 端点)+ 代码层 fail-closed 白名单与写路径唯一 + 交互层 disabled/双重确认 + latch_log 审计;一切扩展(主张级中断、多轮审批串联、自由文本证据、异步 saver、回退 API)统一由「本期规模不够用」触发,触发后在对应工单从本册点菜。** 纪律(图不是 Agent、评测可复现、Agent 不得改回绿灯)决定选极简管道,登记册决定不丢。

## 7. 面试讲法(grilling 预案)

**Q:人在回路里扮演什么角色?什么是 L0/L1?**

> 诚实自治分两层:复验和记忆刑侦是 L1,机器自主跑;作废、续命、隔离确认是 L0,必须人拍板。产品灵魂一句话:过期绿灯不得保持——Auditor 判出 stale/unknown 的机器必须打红,但红灯之后怎么办(作废还是续命)是人的职业判断,Agent 永远替不了,我们把这条写成代码不变量:Agent 没有任何能把红灯改回绿灯的工具。

**Q:为什么用 LangGraph?你们不是说「图不是 Agent」吗?**

> 两句话不矛盾。Agent 循环(Lead/Critic)是裸 chat.completions 自写的 50 行循环,跑在图外——图不承载任何 Agent 智能。LangGraph 在这里只干一件事:checkpoint/interrupt。一轮复验跑完,图在收尾节点 interrupt,状态落 SQLite,进程可以退出;人几小时后回来点按钮,Command(resume) 恢复。这是 LangGraph interrupt 模式的标准用例,我们把它收到最小:锁版本、隔离模块、异步 API 不碰。自研门闩也盘过,零依赖但状态一致性要自保证,且丢掉 checkpoint 回退和多中断串联的原生能力——单人本地项目不值得重造这个轮子。

**Q:作废之后怎么保证「重跑不得再绿」?人能不能徇私?**

> 三层。第一,作废 id 进 `invalidation_list` 表,随课题持久,Lead 每次复验的上下文里都带着这份名单,规则闸在绿灯唯一出口强制校验——就算模型判断失误说 fresh,闸也打回,这是机械执行不是 prompt 祈祷。第二,重跑本身是人的动作:点「重跑作废主张」按钮才跑,只跑那一条,结果挂在复验单时间线上,观众能亲眼看到「重跑后仍红」。第三,审计:每次人审落 latch_log,谁、何时、对哪条、什么决定、带哪个证据,全留痕——作废率本身就是我们的在线指标。人当然可以「徇私」作废一条其实还活着的主张,那是人的职业决定权,产品不裁决,只保证机器不替人做、且做完留痕。

**Q:续命的强约束怎么落?**

> 「续命必须带 T1 evidence_id、checksum 对不上不得续命」是切片红线。交互上,evidence 不是手输的,是从本轮 Lead 已检索到的 T1 块里下拉选——没得选就不存在违规;没选证据续命按钮就是灰的。后端闸再算一遍 checksum,对不上直接拒。生效时写新的 validity_basis 和 last_confirmed_at,下次复验有锚。这套东西 W3–W4 就设计定稿,但按 12 周切片 W5 才实装——W3–W4 复验单上按钮渲染但禁用,tooltip 写明「W5 开放」,演示时完整闭环的形状是看得见的。

**Q:W1–W2 为什么没有人审?产品灵魂不就是「人作废」吗?**

> 切片是排期权威:W1–W2 的生死闸是「无 T1 原文不得绿灯」,那是规则闸的事,不需要人。把 HumanLatch 提前进 W1–W2 会挤占 Lead 循环的打磨时间,而且 W1–W2 引 langgraph 依赖纯属过早。W3 起作废上线,用户旅程的演示叙事——导入 T0→复验单红绿→人作废一条→禁用名单重跑→不得再绿——完整呈现。

**Q:评测怎么对待人审?金标不会被人点按钮搞乱吗?**

> 评测模式代码级跳过 HumanLatch 节点——和「评测期联网代码级禁用」是同一纪律:eval 模式图直通,interrupt 不触发,所有主张按 Auditor 判定落终态,must_stale 由规则闸强制。人审动作根本不进评测路径,金标可复现性不依赖任何人在场。
