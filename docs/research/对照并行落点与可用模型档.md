## 2. LLM 客户端如何选模型;评测对照如何绑死 `qwen-flash`

### 2.1 客户端

`src/freshlatch/llm.py`:

| 项 | 事实 |
|---|---|
| 默认模型 | `DEFAULT_MODEL = "qwen-flash"`;`DecodingParams.model` 默认同此 |
| env | **仅** `DASHSCOPE_API_KEY`、`DASHSCOPE_BASE_URL`(默认兼容模式 URL);**无** `MODEL` / `DASHSCOPE_MODEL` 类 env |
| 调用 | `LLMClient.chat` 把 `decoding.model` 传入 `chat.completions.create` |
| 构造 | `LLMClient()` 只配 key/base_url,不选模型 |

### 2.2 评测对照绑死路径

1. `run_control`:`decoding = decoding or DecodingParams()` → 未传则 `model="qwen-flash"`。
2. CLI `_decoding(args)` **只**传 `temperature` / `seed`,**不**传 `model` → 始终落到 `DEFAULT_MODEL`。
3. `run_w4_acceptance.py` 对照调用不传 `DecodingParams` → 同上默认。
4. 规格/预登记文字层同步钉死:同模型假绿对照 = `qwen-flash`(与 Lead 同档)。来源:`docs/spec/04-评测纪律.md`;`docs/evidence/w4/false-green-control-prereg.md` decoding 表;`docs/spec/06-护栏预算与成本.md` §6.5。

**换模型的现成钩子(事实)**:构造 `DecodingParams(model="...")` 传入 `run_control` / `run_gold`。评测 CLI **目前没有** `--model` 旗标(冒烟脚本 `scripts/smoke_dashscope_tool_loop.py` 有 `--model`,属另一入口)。

## 4. T0 摘录拼装:单锚 vs 多锚/加长钩子

### 4.1 现路径(已存在)

`run_control` L73–79:

1. **遍历** `claim.t0_evidence_ids`(list)
2. 每个 id:`doc_id#anchor` → `store.get_chunk(doc_id, anchor, as_of="T0")`
3. 命中则 append `chunk.text`;`t0_excerpt = "\n\n".join(excerpt_parts)`
4. 未命中静默跳过;全未命中 → 空串仍送模型

因此:**多锚在代码层已是「对 list 逐条 get_chunk 再拼接」**;无需新循环骨架即可消费「多个 evidence id」。

### 4.2 数据层现状(单锚)

`data/t0_docket.json`(及干扰项 docket)每条主张的 `t0_evidence_ids` **均为长度 1**(形如 `t0-…#p2`)。离线同路径摘录长度约 100–116 字、单 clause——见 `docs/research/假绿全unknown诊断事实.md` §3.3。

### 4.3 「加长」相关钩子是否已存在

| 能力 | 是否已存在于对照路径 | 说明 |
|---|---|---|
| 多 `t0_evidence_ids` → 多 chunk 拼接 | **是**(代码);数据未用 | 改 docket 列表即可扩锚,属数据/契约变更,非新 API |
| `get_chunk` 单 clause | **是**;无「相邻 clause / 加长 N 字」参数 | `store` 签名:`get_chunk(doc_id, clause_id, *, as_of)` |
| `read_source(doc_id, as_of)` 全文 | **店面有**;对照路径**未调用** | `sqlite_store` / `base.py`;可作「加长到全文」的另钩,但今日 `run_control` 不用 |
| 对照报告落档 excerpt | **否** | 返回无 excerpt 字段(§1.2 缺口) |
| 红线单测 `_t0_excerpt` | **另一条路径** | 读 `data/corpus/t0/*.md` 前 2000 字,≠ `get_chunk` 对照送入 |

**结论(事实)**:「单锚」是**当前 docket 用法**;「多锚拼接」钩子**已在** `run_control`;「加长到超出已列 evidence 的 chunk 集合」(全文 / 邻块 / 截断长度旋钮)在对照路径上**尚无专用参数**,仅有店面级 `read_source` 可被未来并行路径选用——是否采用由构念票裁,本票不拍。
