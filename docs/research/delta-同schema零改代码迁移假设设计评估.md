## 1. 问题 + 前置约束

针对已选第二课题包 P1，拍板「同 schema 零改代码」迁移假设是否成立；成立则给出操作定义（哪些表/字段/闸/UI 不许动）；不成立则给出最小允许改动面。本票**定假设与证伪方式，不写实现**。

| 前置 | 来源 | 锁死作用 |
|---|---|---|
| 第二课题 = 同构课题包；本批唯一 P1；不改闸语义 | ADR-0019 / #103 | 本假设的被测对象已定 |
| 禁为第二课题改第一课题 gold 凑绿 | 票面；γ 禁改纪律 | FP4 |
| 主张/语料/SQLite/gold 键形状已有单一真相 | `docs/spec/02-数据schema与语料清单.md` | 冻结面对照基线 |
| 不硬等 β/γ | 票面 | 假设可先锁 |
| OUT | 真 SSO/连接器；十垂类；改主闸语义；主会真实对照 | 继承 |

**词表钉清**:

- **硬零改**: `src/` git diff 为空（过脆，本票弃作假设语句）。
- **软 Port**: 冻结面零改；允许平行数据包 + 配置切换 + 只读装载器。
- **同 schema**: gold **键形状**、主张**字段集**、SQLite **表结构**同构；值与行可变；**加键/加列 = 不同 schema**。

## 3. 逐路线评估

| 对照 | 拍板 | 被否 |
|---|---|---|
| 软 Port (B) | 可审计且可落地 | 硬零改逼假零 diff；C 与 ADR-0019 冲突 |
| 冻结 1–7 | 含六维枚举 | 扩第七维 = 改词表迁就 P1 |
| 允许 C | 数据+包名+只读装载器 | 更宽易吞闸；仅数据无法诚实换路径 |
| 隔离 D | 前缀必须、分库允许 | 加 `pack_id` 列削弱「同 schema」 |
| FP1–FP7 | 覆盖闸/schema/gold/UI/维/装载器越界 | 缺任一则事后可狡辩 |
| 装载器钉职责 | 行数可刷 | 硬顶行数不可审计本质 |
| #105 边界 B | 一句 synthetic 不抢释放协议 | 完全不管易漏标 |
| ADR-0020 | 三条件齐 | 只评估不够挂「作废条件」 |

**Anthropic 清单**:

1. 软 Port 跑通 ≠ 多垂类已验证（仍受 #103 backlog 禁升格约束）。
2. 本票无 LLM 采样生死；探针为确定性违例。
3. 「零改代码」不得当默认口语；规格以本评估 + ADR-0020 为准。
4. 探针表与冻结清单留评估/ADR；CONTEXT 只留产品/领域词。
5. 假设与 FP 先于实现；事后改 FP 放水 = 预登记作废。
6. 确定性层 = 冻结面与 FP；装载器属允许面但越界即 FP7。
7. ADR 三条件齐 → 0020。

**被否原推荐气质**: 「字面零 diff 才叫迁移」「为报价加第七维」「表加 pack_id」——前者不可操作，后两者毁同 schema / 词表。

## 4. 拍板 + 逐项子决策

1. **假设成立（软 Port）**，预登记句：  
   > 对 P1 QuoteTTL 薄课题包：在冻结面（闸、主张字段集、gold 键形状、SQLite 表结构、HumanLatch、职人旅程、六维枚举）零改的前提下，仅以平行数据包 + 配置切换 + 只读装载器完成同一旅程；claim_id 命名隔离（必要），每包独立 DB 文件（允许）。FP1–FP7 任一响则本假设作废。

2. **冻结面（不许动）**:  
   (1) `gates/*` 不变量与 error_code 语义  
   (2) 主张字段集——可加行不可加列  
   (3) `gold.json` 键形状——值随包变，键不增删  
   (4) SQLite 表结构——可换库文件或换行，不加列  
   (5) HumanLatch：作废→Stay-Red；续命须 T1 evidence_id  
   (6) UI 旅程：导入→T1 三卡→复验单→作废/续命→Client Memo  
   (7) focus/登记维度六枚举——报价题映射进现有六维，不新开「交期维」

3. **允许改动面**: 平行 `data/packs/<pack_id>/`（或等价）corpus+gold+docket；配置选包；第一课题数据只读不改；UI 可显示包名/问题句（无新主 CTA）；只读装载器（只解析 `active_pack`、拼路径、打开对应 DB）。

4. **隔离**: claim_id 前缀/独立编号（必须）；每包独立 SQLite 文件（允许）。**弃**表加 `pack_id` 列。

5. **证伪探针 FP1–FP7**（实现后打假；任一响 → 不得称本批迁移成功，须重预登记）:

| ID | 触发即伪 |
|---|---|
| FP1 | 为 P1 改 `gates/*` / HumanLatch 语义 / error_code |
| FP2 | 主张 schema 加列，或 gold 加键（非仅平行文件改值） |
| FP3 | SQLite 加列（含 `pack_id` 列） |
| FP4 | 为 P1 改第一课题 `gold.json` / 语料凑绿 |
| FP5 | UI 新主 CTA（比价/字段引擎/自动通知等）或新旅程步 |
| FP6 | focus/登记维扩第七枚举 |
| FP7 | 装载器触及 `gates/`、`roles/` 放行路径、或续命写库语义 |

6. **装载器**: 不钉行数；钉职责与 FP7 禁区。

7. **#105 边界**: 本票不定对外释放；**平行课题包必须标明 synthetic**（一句）；释放协议正文归 #105。

8. 本会话不 `/to-spec`、不 `/implement`。

## 6. 面试讲法

**Q: 你们不是说零改代码吗？为什么还有装载器？**  
A: 假设是软 Port：冻结面（闸/schema/旅程/六维）零改。装载器只换数据路径；一旦碰闸或放行路径，FP7 响，迁移叙事作废。

**Q: 怎么证明没有偷偷改 schema？**  
A: FP2/FP3：加列或 gold 加键即伪。实现后用探针打，不是靠自称。

**Q: 两个课题都用 c1 怎么办？**  
A: claim_id 必须命名隔离；可选每包独立 DB。不加 pack_id 列——那会直接不同 schema。

**Q: 软 Port 过了是不是多垂类 OK 了？**  
A: 否。只证明 P1 包在冻结面下可迁移；backlog 升格禁令仍见 #103/ADR-0019。
