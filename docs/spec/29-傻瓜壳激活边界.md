## Problem Statement

复验界面当前像实验台：协议词（claim / latch / T0 / fail-closed）与控件密度高，新人不知道自己在干什么、下一步点哪。刷新/`boot` 还会洗掉待拍板清单，样例路径也不在主 CTA。没有傻瓜壳激活边界，≤5 分钟上手与面试旁观「产品在拦什么」都立不住；这只抬上手层，不抬 RESULT-Y。

## Solution

在**不改判定逻辑、不改 RESULT-Y、不扩 HumanLatch 动词**的前提下，交付复验页的**傻瓜壳**：默认主 CTA=一键样例；三步主路径（放材料/样例 → 自动复验含白话进度 → 只审待拍板）；三类白话清单映射现四态；协议进「高级/证据」；禁止 boot/import 洗掉勿发/待拍板 sheet；挡续命呈现为成功路径说明。Activation：看到三类清单并完成至少一条 discard|renew。

## User Stories

1. As a 首次使用的知识工作者, I want 打开页就看到一个主按钮「一键样例」, so that 我不先被导入/协议字段吓跑。
2. As a 首次用户, I want 导入文件只是次按钮, so that 主路径保持傻瓜。
3. As a 首次用户, I want 点样例后自动进入复验或明确下一步, so that 我不用猜流程。
4. As a 等待中的用户, I want 复验时看到白话进度「正在用新材料核对旧结论」, so that 我知道系统在干活而不是卡死。
5. As a 等待中的用户, I want 知道大约要等两分钟量级, so that ≤5min 预期不被墙钟打穿。
6. As a 等待中的用户, I want 进度可见且可取消（若已有取消能力则保留）, so that 长等待可退出。
7. As a 复验完成者, I want 看到三类清单：仍可信 / 可能过期 / 要你确认, so that 我用白话理解结果。
8. As a 复验完成者, I want 三类各有一行定义, so that 我不靠猜。
9. As a 复验完成者, I want 「仍可信」对应 fresh, so that 与机器判定一致且不另造状态。
10. As a 复验完成者, I want 「可能过期」对应 stale 与 unknown, so that 材料变了或证据不够归一类白话。
11. As a 复验完成者, I want 「要你确认」对应 latch pending, so that 待拍板集中在一处。
12. As a 决策者, I want 在「要你确认」里用明确动作作废或续命（底层 discard|renew）, so that 我知道怎样算处理完。
13. As a 决策者, I want 处理后该条立刻离开「要你确认」, so that 我看见进度。
14. As a 决策者, I want 无 T1 时续命被挡并看到「挡住=产品在干活」说明, so that 我不把成功拦截当报错。
15. As a 决策者, I want 人审动词仍只有 discard|renew, so that 不破坏 HumanLatch。
16. As a 刷新用户, I want boot/import 不洗掉勿发与待拍板清单, so that Activation 不假失败。
17. As a 刷新用户, I want 样例路径走通后清单仍在, so that 验收可复现。
18. As a 新人, I want 默认界面看不到 claim/latch/T0/fail-closed 等协议词, so that 主路径可读。
19. As an 高级用户, I want 在「高级/证据」里看到协议细节, so that 专家路径仍在。
20. As a 新人, I want 空态说明会出现什么、点哪个、有无样例, so that 空白页可行动。
21. As a 出错用户, I want 错误说明拦了什么以及我能怎么改, so that 不堆 reject_reason 枚举。
22. As a 面试旁观者, I want 60 秒内能说出产品在拦什么, so that 作品叙事像产品不是实验台。
23. As a 产品负责人, I want 主 CTA 文案不是「生成答案」, so that 遵守既有 UI 红线（开始复验/样例语义）。
24. As a 产品负责人, I want 本票不改 RESULT-Y 与成立格数字, so that UI 过线不吹成主实验成功。
25. As a 产品负责人, I want 本票不宣称产品已 L4, so that 范围不漂移。
26. As a 验收者, I want 样例 CTA 一键可走完三类清单路径, so that 演示可重复。
27. As a 验收者, I want 模拟完成率下限 ≥4/5 且 ≤5min（含墙钟）, so that 过线客观。
28. As a 验收者, I want 记下卡在第几步, so that 复测可改。
29. As a 验收者, I want 步骤 1 盲测先吃 playtest 债（copy_wrong_job、CTA、勿发 sheet、Control Δ）, so that 不从空白重编卡点。
30. As a 实现者, I want 判定/API 语义不变只改壳与文案层, so that 回归面可控。
31. As a 实现者, I want 包结论可发/需补丁/勿发 仍按既有语义, so that 发前路径不破。
32. As an AFK agent, I want 本规格可拆成带 Acceptance 的工单, so that Cloud Agent 可实现。
33. As a 文档维护者, I want PRD 与本规格互链, so that 上手目标可追溯。
34. As a 回归守护者, I want 既有 latch decide / reverify / import 契约测试不红, so that 壳改不回退闸。
35. As a 安全意识用户, I want fail-closed 行为保留只是文案改白话, so that 安全语义不松。

## Implementation Decisions

### 主缝与模块

- **主缝**：傻瓜壳激活边界（见文首）。对外可测：样例路径端到端 Activation + boot 不洗待拍板。
- **改动面**：复验页壳与文案层（静态页 + 必要的前端状态）；**禁止**改闸门判定、金标、formal 跑数、RESULT-Y。
- **样例主 CTA**：默认主按钮为一键样例；「开始复验」保留为复验动作语义（可与样例串联）；导入降为次按钮。
- **三类清单**：纯展示映射；状态源仍为 fresh / stale|unknown / latch pending；不新增后端枚举。
- **Boot 防护**：页面加载/`boot`/`import` 不得清除已有勿发 disposition 与 latch pending 待拍板集合（对齐 playtest WIPE_NOTE）；若现 `boot` 调 import 洗内存态，改为幂等加载或显式「重置」高级动作。
- **进度**：复验进行中展示白话进度文案；时长预期写入 UI 或提示。
- **挡续命**：无 T1 / 既有拦截条件触发时，UI 用成功说明样式，不清空清单。
- **两层披露**：默认白话；协议字段进可折叠「高级/证据」。
- **实现派遣**：Cloud Agent 按 Matt `/implement`；主人不经本地 Cursor。

### 测试主缝（对外）

给定：可点的一键样例、可完成的复验、至少一条 latch pending。  
期望：≤5 分钟内用户完成至少一条 discard 或 renew；三类清单可见且定义可见；刷新或等价 boot 后待拍板仍在；默认 DOM/可见文案无协议词堆砌。

## Testing Decisions

- 好测试只测外部行为（用户可见路径与 API 契约结果），不测内部 JS 结构。
- 主缝：端到端/冒烟（样例→清单→decide）；boot 后 pending 仍在。
- 子缝：文案快照或可访问文本断言（三类定义、进度句）；挡续命说明可见。
- Prior art：既有 UI/API 测试、playtest 夹具与 JUDGE 清单；复用勿发 sheet 场景。
- 量化：完成率 ≥4/5、卡点步骤、是否 ≤5min（含墙钟）记入验收笔记，不单靠 CI 绿。

## Out of Scope

- 改乙/丙、RESULT-Y、另跑 formal、改 HumanLatch 动词集  
- 全盘视觉品牌重做、新前端框架迁移  
- 把 UI 过线写成 L4 / 主实验成功  
- 真人盲测（后补）；本票用模拟 playtest  
- 发前钩子 / 补丁改稿逻辑变更（除非壳入口文案）
