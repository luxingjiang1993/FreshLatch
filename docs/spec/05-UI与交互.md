# §5 UI 形态与关键交互

> 出处:#4(选型)、ADR-0002、ADR-0006(#11)、#12(红线)。选型理由:点回原文高亮自由度 + HumanLatch 审批端点对齐 gates/;双糙样存档于分支 `prototype/ui-双糙样`,W1 直接照搬布局。

## 5.1 形态定稿

- FastAPI 服务端 + 手写 HTML/JS **双栏页面**(左:主张复验单卡片列表;右:原文面板)。
- 主界面是**复验单**(claim 卡片:判定灯色 / 理由 / evidence_id / 人审动作),**不是聊天框,也不是记忆列表**;工具轨迹可展开,不是首页。
- 界面标注 **SYNTHETIC**;主按钮文案 = **「开始复验」**。
- `ui/` 是薄壳,核心包零 Web 依赖;HumanLatch 端点写**同步 `def`**(FastAPI 线程池,同步 SqliteSaver 不阻塞事件循环)。

## 5.2 点回原文(W4 生死闸的交互核心)

- 每条主张的 `t0_evidence_ids` / `t1_evidence_ids` 渲染为可点击锚;点击 → 右栏加载对应文档(T0/T1 可切换,as_of 语义可见)→ 滚动定位到 `## p2` 锚点段落并**高亮**。
- 高亮是选 FastAPI+HTML 而非 Streamlit 的核心理由(Streamlit 只有 markdown 片段级高亮);实现自由度必须在 W3 预检前兑现(§7)。

## 5.3 作废闭环(W3 起实装)

1. 人点卡片「作废」→ **双重确认弹窗**(「作废后重跑不得再绿,确认?」);
2. 确认 → `status=void`,卡片**灰显**;作废记录写 `invalidation_list` 表 + `latch_log` 日志(人审日志必做:审计迹 + 作废率取数口);
3. **`stale` 与 `void` 并存不互斥**:stale 是 Auditor/机器判定,void 是人的决定,一条主张可同时带两个标记;
4. **重跑**:人点「重跑作废主张」按钮(不自动,作废到重跑之间保留反悔窗口)→ 新开 thread(`reverify-{claim_id}-{ts}`)跑**只含该主张的迷你复验** → 结果挂该主张卡片**时间线**(如「重跑后仍红(第 N 次)」);规则闸查作废名单,即使 Lead 判 fresh 也强制打回;
5. 复验单顶部「待人工」横幅 + 批量审批表单(W3–W4 单 interrupt 轮次级,无逐卡片徽章)。

## 5.4 续命闭环(W3–W4 渲染但 disabled;W5–W8 实装)

- 卡片「续命」按钮**渲染但 disabled**,tooltip:「W5 开放:续命必须带 T1 原文证据」——完整闭环形状可见,红线以禁用态可见;
- 实装后交互(#11 设计定稿):evidence_id 从**本轮已检索 T1 块下拉选择**(非自由文本),无 evidence_id 按钮 disabled(前端拦截 + 后端闸兜底);生效链 = checksum 校验通过 → 写**新的 validity_basis(T1 doc+checksum)** + 更新 `last_confirmed_at` → `status=fresh`。

## 5.5 HumanLatch 审批端点(ADR-0006)

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/latch/decide` | POST(同步 def) | 传整个决定列表 `[{claim_id, action: "discard"\|"renew", evidence_id?, reviewer_note?}, ...]`;`Command(resume=...)` 恢复 interrupt;空列表 = 全部搁置合法形状 |
| `/api/latch/rerun` | POST(同步 def) | 触发单主张重跑(新 thread 迷你复验) |
| `/api/latch/status` | GET(同步 def) | 人审轮状态查询;进程重启后凭 thread_id 从 checkpoint 恢复待审清单(#11 §5.10) |

- 一轮复验 = 一个 thread_id;写路径唯一 = `gates/human_latch.py`(由它调规则闸);checkpoint 文件 `data/checkpoints.db`,同一主张留最近 5 个 thread,业务侧定期删行。
- 图形状:`START → prepare_review → interrupt()(收尾节点)→ execute(按决定列表分支)→ END`;interrupt 前代码必须**幂等**,副作用全部放 interrupt 之后(1.0.x 节点重执行语义)。

## 5.6 主界面四条红线(#12)

| # | 红线 | 自检方式 |
|---|---|---|
| 1 | 无聊天主框 | 代码单测进 CI(防回归)+ 人看录屏复核 |
| 2 | 主按钮不得叫「生成答案」 | 同上(文案白名单单测:主按钮 ∈ {开始复验}) |
| 3 | 不得出现「开始调查」 | 同上(违禁词源码扫描 grep 测试,只防手滑) |
| 4 | 不得被复述成「又一个 EvidenceOS」 | **只有复述测试能判**(§7),代码测不出界面气质 |

- 前三条:DOM/源码断言是**必要不充分**,每条仍须人看录屏复核;第四条机器不可测。
- 止损条款高于验收通过:任何「为了过验收」修改主按钮/主界面的动作判定为违规(ADR-0007 §3)。
