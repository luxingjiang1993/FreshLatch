## Problem Statement

审计当时的结论是：核心闸与离线测仍干净，但外围难讲——`check_x1` 单函数过长、草稿生成挤在 `scripts/`、三份 `parse_evidence_id` 对多 `#` / 非法 `as_of` 行为不一致、`ui/app.py` 近两千行且半为内嵌 HTML、缺少 `pyproject.toml`。根目录与连接泄漏已先清。

2026-10-07 的 main 已经不是写初稿时的树。生产默认臂是 `hybrid+rerank`，精排是本地 `BAAI/bge-reranker-base`（只重排 hybrid 的 top-10），`fastembed==0.8.1`，并且新增了 `src/freshlatch/store/neural_rerank.py` 与 `src/freshlatch/store/local_embed.py`。若按初稿里「外围还停在 bm25 / fastembed 0.7.1」的印象去做卫生，会把已经拍板的检索臂和依赖钉「收拾」回去。本波只钉可维护边界，禁止借重构改检索臂、改 gold、改评测口径。

## Solution

做一次 **工程卫生整改（Hygiene Phase）**，拆成 HYG-01…05，按下面的依赖顺序分会话实施。editable 包与 CI lint 收束导入面；合并三份 `parse_evidence_id`；在签名冻结下拆薄 `check_x1`；把 `gen_x1_drafts` 核心迁入 `src/freshlatch/eval/` 并保留薄 CLI；将 UI 的 HTML 抽出 `app.py`。本期不做 `create_app` 去全局。改解析或拆 `check_x1` 时，用预锁的金标差异表证明 x1 作答臂 224 题指标逐位不变。每一票在重构前和重构后各跑一次全量 pytest，两次都要全绿。

## User Stories

1. As a 新克隆者, I want `pip install -e ".[dev]"` 后无需手设 `PYTHONPATH` 即可 `pytest` 与跑薄 CLI, so that onboarding 不被 path hack 绑架。
2. As a CI 守护者, I want workflow 用 editable 安装再跑测试, so that CI 与本地权威路径一致。
3. As a CI 守护者, I want CI 有一步 lint（默认 ruff，规则先松）, so that 明显脏导入能被拦住，又不一次炸光历史风格债。

## Implementation Decisions

### 现状（main `0e185d7`，本波冻结，不是待改目标）

- `PRODUCTION_RETRIEVAL_MODE = "hybrid+rerank"`。精排是本地 `BAAI/bge-reranker-base`，只重排 hybrid 的 top-10。一键回退 BM25 是 `set_retrieval_switch("bm25")`。词重叠精排是 `set_retrieval_switch("hybrid+rerank_lexical")`。缺向量记 `bm25_fallback`。reranker 失败记 `last_rerank_mode=lexical_fallback`。
- 生产依赖钉 `fastembed==0.8.1`（`requirements.txt`）。embedding 模型 id 仍是 `BAAI/bge-small-zh-v1.5`。`0.7.1` 没有 `TextCrossEncoder`，本波不得把它写回依赖。
- 生产精排模块是 `src/freshlatch/store/neural_rerank.py`。本地 embedding 模块是 `src/freshlatch/store/local_embed.py`。评测侧纯函数在 `src/freshlatch/eval/neural_rerank.py`。这三份都不在卫生票的改写范围内。
- 三份名为 `parse_evidence_id` 的函数仍在，切法仍不一致：
  - `eval/checks.py`：`rsplit("@", 1)` 再 `rsplit("#", 1)`，非法则 `None`，`as_of` 只认 `T0|T1`。
  - `gates/human_latch.py`：`rpartition("@")` 再 `partition("#")`（第一个 `#`），非法则 `None`。注释写「与 checks 同一套」，切法并不是同一套。
  - `eval/x1_checks.py`：最后一个 `#` 与最后一个 `@`，失败返回 `("", "", "")`，不拒绝非法 `as_of`。`check_x1` 用它取出 multi_hop 的 `doc_id`。
- `check_x1(corpus_dir, traps_dir, questions, config, *, floor_overrides=None) -> CheckResult` 仍在 `eval/x1_checks.py`。每题记录行是 `q <id> r8=… lcs=… lcs_flag=… decontam=… score_role=…`。
- `scripts/gen_x1_drafts.py` 仍是脚本巨石（约 2100 行），文件头有 `sys.path.insert`。
- `src/freshlatch/ui/app.py` 仍内嵌 `HTML_PAGE` 与 `PREPUBLISH_HTML`，并有模块级 `_state` 与一处 `sys.path.insert`。
- 尚无 `pyproject.toml`。CI 仍是 `pip install -r requirements.txt` 再 pytest，无 lint 步。`.cursor/environment.json` 的 `install` 同样只装 `requirements.txt`。`pytest.ini` 的 `pythonpath = .` 是为了 `from tests...`，与 src 导入 hack 不是同一件事。
- x1 作答臂仍是 `score_role=arm` 的 224 题。检索四臂的逐题排名已在 `docs/evidence/fastembed-081-recheck/per-query.json`。金标口径不变：模型双标加代审，人工只审过 DECISION-16 的 16 题。

### 主缝与策略

- **主缝**：文首五条。测的是导入边界、解析一致性、公开 API 稳定、224 题指标不变、路径红线、UI 静态分离。
- **权威序**：已接受 ADR + `CONTEXT.md` 产品词 + 2026-10-07 已合入的检索拍板 > 本规格卫生契约 > 2026-10-06 审计建议。本波不得反向改闸、gold、默认臂、精排模型或指标函数来方便重构。
- **已落地、本规格不重复**：根目录过程文档外移、README Snapshot、sqlite `close` 归零。
- **不新拍产品板**：续命语义、evidence_id 时点只认 T0|T1、UI 红线、CI 零 LLM、现行检索臂，全部沿用既有 ADR 与已合入决定。本规格只钉工程边界，外加一处解析切法对齐。

### 拍板：`parse_evidence_id` 单一语义（预锁，禁止事后改）

| 维度 | 拍板 |
|---|---|
| 权威实现 | 一处纯函数。模块名实现自洽（例如 `freshlatch.evidence_id`，或并入无环依赖的现有模块）。`eval/checks.py` 与 `gates/human_latch.py` 改为调用或 re-export。`eval/x1_checks.py` 删除本地副本 |
| `#` 切法 | **最后一个** `#` 分隔 `doc_id` 与 `anchor`（对齐现行 `eval/checks.py` 的 `rsplit("#", 1)`）。改正 `human_latch` 的「第一个 `#`」 |
| `@` 切法 | 最后一个 `@` 取 `as_of` |
| `as_of` | 仅 `T0` \| `T1`。其余为不可解析 |
| 失败契约 | 统一返回 `None`。x1 调用处改为判空，不再依赖 `("", "", "")` |
| `None` / 非 str 入参 | 视为不可解析，返回 `None` |
| 解析契约行（先于实现写入测试，禁事后改期望） | `doc-a#p2@T1` → `("doc-a", "p2", "T1")`；`a#b#c@T1` → `("a#b", "c", "T1")`；`doc#p2@T2` → `None`；缺 `#` 或缺 `@` → `None`；空 doc 或空 anchor → `None` |

**止损：** 若实施中发现已入库或金标 evidence_id 依赖「第一个 `#`」，并且下面的 224 题表会出现非空 diff，**停**。另开决议票。不得改 gold、不得改预锁表、不得改指标函数来消掉 diff。

`runner.py`、`roles/forensic.py`、`gates/policy_gate.py` 里还有内联的 `#` / `@` 切分，它们不是这三份命名函数。HYG-02 不改这些调用点。要收口另开票。本五批不借那张票改检索或角色行为。

### 金标差异表（HYG-02 与 HYG-03 的硬验收）

表在改实现之前写入本票，路径 `docs/evidence/hygiene/x1-arm-224.json`。先写表和生成它的命令，再改 `parse_evidence_id` 或拆 `check_x1`。事后改表等于验收作废。

范围：`data/exp/x1` 现行题集里 `score_role=arm` 的题。条数必须是 224，否则停，不得改题集凑数。

表内两块，重构后都要逐位相同：

1. **check_x1 记录。** 对现行语料跑现行 `check_x1`。每题保存 `r8`、`lcs`、`lcs_flag`、`decontam`、`score_role`，以及该题相关的 messages（排序后的列表）。另存整次 `exit_code`。消息字符串本波默认不改，所以 messages 也在 diff 里。
2. **检索三指标。** 读取已入库的 `docs/evidence/fastembed-081-recheck/per-query.json` 里四臂（bm25、hybrid、hybrid+rerank_lexical、hybrid+rerank）的 `ranked` 与 `relevant`。用现行 `recall_at_k`、`mrr_at_k`、`ndcg_at_k`（k=10）重算。不重新 embedding，不调用付费 API，不重计 p95。每题每臂三个数写入表。

重构后再跑同一套导出。diff 必须为空。非空则停。禁止为了消 diff 而改 gold、`LOCKED_CONFIG`、指标函数、检索臂或这张表。

HYG-03 的基线是它自己的 base（HYG-02 已合入之后的树），不是 #296 当时的旧文件。开工前在该 base 上重导出，再拆函数，然后再导出。两次都要零 diff。

p95、加载时间不进这张表。它们是单次墙钟，不是评测口径。

### HYG-01 — editable 包、去掉 src 导入 hack、CI lint

- **Destination：** `freshlatch` 以 editable 安装为权威导入。CI 与 Cloud `install` 走同一条。为导入包而写的 `sys.path.insert(.../src)` 删除。`fastembed==0.8.1` 与 `hybrid+rerank` 保持不动。
- **Acceptance：**
  - Given 未设置 `PYTHONPATH` 的环境，When `pip install -e ".[dev]"` 之后执行 `python -c "import freshlatch"` 与 `python -m pytest tests/ -q`，Then 两次退出码都是 0，且 `tests/conftest.py` 不再把 `src` 插入 `sys.path`。
