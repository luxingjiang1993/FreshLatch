# §4 评测纪律

> 出处:#9(评测 harness)、#8(金标哲学)、#12(复现两层、decoding 记录)、ADR-0005、ADR-0007。第一原则:**评测的是你真卖的东西**——runner 必须跑端到端真主链,不跑替身。

## 4.1 评测设施落点与命令

- `src/freshlatch/eval/` 包:`runner.py`(金标对账)/ `control.py`(假绿对照)/ `matrix.py`(混淆矩阵纯函数)/ `report.py`(报告)。
- 命令:`python -m freshlatch.eval run --gold data/eval/gold.json [--runs N]`、`control`、`report`。
- 端到端 = 真实 Lead 循环 + Critic 派驻 + 规则闸,与复验单 UI 同一入口,无人审。**只实装端到端一档**;「只跑 Auditor+闸」的快档不测真身(检索 miss 这个最大失败源被绕过),被否。

## 4.2 无工具假绿对照(control.py)

- **同模型(qwen-flash)不带工具**,只读 T0 摘要 + 主张,问「现在是否仍成立」;已死主张必须判「成立」(假绿),本产品必须红——对照成立才说明复验环节真在起作用。
- 输出契约:**JSON mode** 三档 `{"verdict": "alive"|"dead"|"unknown"}`,机械解析对账(DashScope JSON mode 兼容性 W3 开工顺带冒烟)。
- **prompt 红线:不得透露 T1 存在、不得透露金标**——泄一句对照即废。
- 假绿来源完整性靠 must_unknown 档:基线不只「该红的判绿」露馅,「没源的也敢判绿」同样露馅。

## 4.3 报告与混淆矩阵口径

- **双产出**:console 摘要表(当场看)+ `reports/report-<date>.md` 进 git(留存、可 diff、面试引用)。
- 混淆矩阵 3×3(预测 fresh/stale/unknown × 期望三档),按 must_stale/must_fresh/must_unknown 各报**命中/漏判条数,不报百分比**——12 条小样本,百分比遮丑(#8 口径)。
- **失败归因本期只存原料**:每条 run 的 trajectory(messages JSONL + 步数/预算遥测)落盘 `reports/trajectories/`,失败条目附轨迹指针 + 人工定性;机械归因 harness(检索 miss / 推理错 / 闸门绕过)是 W5–W8,本期只留原料落点。

## 4.4 统计纪律接口 `--runs N`

- 接口本期实装、默认 N=1:每条主张跑 N 遍,报 per-claim 命中次数/N;**报告格式按 N>1 设计**(per-claim pass@k 表),N=1 退化为单列——接口不留遗憾。
- 成本账:12 主张 × N=10 × ≈¥0.001/主张 ≈ ¥0.12/轮全量,可忽略。
- N≥5 方差报告归 W5–W8(差距清单第 1 条归属,不重复建设);W4 的 3 遍 × 3 seed 是 #12 独立拍板的验收冒烟,不走 runner(§7)。

## 4.5 双 gate 测试与 CI(ADR-0005)

| gate | 目录 | 内容 | 触发 |
|---|---|---|---|
| gate 1 | `tests/unit/` | 纯函数单测:`rule_gate`、混淆矩阵、白名单矩阵、Guardrails、skill 一致性 4 断言 | **CI 每次提交** |
| gate 2 | `tests/eval/` | gold.json 驱动闸单测:「stale/unknown 不得绿灯」「无 `t1_evidence_ids` 不得 fresh」「checksum 对不上不得 fresh/续命」 | **CI 每次提交** |

- `conftest.py` 只做 sys.path 注入,不堆 fixture;断言直接 new 服务对象查 error_code,不 mock 大山。
- CI = GitHub Actions,job 只跑 `pytest tests/`,**零 LLM 依赖**。
- LLM 金标 runner **手动 + milestone 触发**,报告进 git;CI 全量 LLM 回归被否(烧额度、DashScope 抖动假红灯、prompt 迭代期恒红,违背「CI 红灯即回归」语义)。两个绿灯语义分离:CI 绿 = 代码不变量没破;评测报告绿 = 模型表现没破。
- **不引入** LangSmith/deepeval/openevals 依赖;**不做评测页 UI**(评测是开发纪律,不是用户功能;W5–W8 消融表页届时再议)。

## 4.6 评测模式两道代码级开关

1. **跳过 HumanLatch**:eval 模式图直通,interrupt 不触发,所有主张按 Auditor 判定落终态;人审动作不进评测路径,must_stale 由规则闸强制(与联网禁用同一纪律)。
2. **禁用联网**:运行时纯本地;`web_search` 仅架构插座,评测模式代码级禁用(联网破坏 must_stale 金标可复现性)。

## 4.7 复现纪律(两层 + decoding 留档,#12/ADR-0007)

- **复现两层**:闸层(must_* 零违例)是给定解码参数下的确定性结果,AFK 冷启动重跑必须**逐位复现**;判定层(混淆矩阵条数)按**文档化容差**;违例级背离(must_stale 被判 fresh 等)触发人查。
- **decoding 参数显式记录**:temperature、seed、模型版本、日期逐运行入报告;托管端点在漂移,跨会话复现只能是近似的,此限制写入留档。temp=0 时 seed 无采样意义(3 个 seed 跑出相同结果 = 假信心)——凡采样场景须显式非零温度(§7 的 W4 冒烟即如此)。
- 语料 checksum 三处留位本期为空(§2.4);W5–W8 做「同 seed 重跑对照」时补纪律。
