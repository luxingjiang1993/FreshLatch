# 正式论文开工闸

> 来源：main `101c81e`。`/to-spec`。本页不是论文，不是预注册，不回写 `PREREG.md`，不填 `RESULT.md`。
> 基线：`formal-generations.jsonl` 已有 120 行。C、T、B1 是 rewrite 的 `after_text`。B2 只有 claim 的 `claim_text`。`compare_primary` 在 B2 为零行时拒绝，理由是主比较缺臂 B2。
> 测试主缝（预锁）：已经存在的正式比较缝。它按现有顺序调用四臂记录、`verify_edit`、主比较行收集、`compare_primary`。不新写放行函数，不从主比较拿掉 B2。
> 语言：中文。技术词保留 English 原词。

## Problem Statement

正式论文还不能开写。120 行生成记录已经在 main 上，核验和放行判定也已经写在仓库里，但三条主比较 T-C、T-B1、T-B2 算不出来。B2 的 diff 段提示词是明确留空，记录里没有 diff 的 `after_text`。现有函数把缺 `after_text` 记成生成失败，不记成放行，于是 B2 臂是空的，主比较直接拒绝。

另外几处也还空着：高分代表放行还是拒绝没有一句；抽检一致率和用户对评委的 Cohen's κ 没有收成可执行的一对标签；README 导语、架构图、demo、简历一行、mastery pack 在真实主指标数字出现之前都不能改。这些空着的时候去写论文，或把 `claim_text` 当成 `after_text`，或从主比较拿掉 B2，都会把没测量的东西写成已经测量。

## Solution

本规格把开写正式论文之前的每一处缺口收成一条决定和一条验收。决定只使用已经写好的放行规则和已经写好的主比较。新句子只作为本页里的补定 draft，不在本轮写进提示词或代码。

允许开写论文的条件只有一条：`compare_primary` 对同一批 n=30 给出 T-C、T-B1、T-B2 三条 false-accept rate 的点估计、95% 区间和分母，B2 的记录数等于 30，数字来自函数输出，不是编出来的。在此之前，README 导语、架构图、demo、简历一行、mastery pack 保持不动。

## Implementation Decisions

下面每一条都是：缺口、关掉它的决定、验收时要看见的行为。本轮不实现。

### 已经锁定、本规格不改写

这些句子保持原样。补定不是预注册原文。不得把它们再写成预注册原文。

- 生成温度只读 `default_llm.temperature`。现在的值是 0。补定，2026-10-08。评委温度不在这条里。
- 四臂共用的改写一句，原文一字不改：「根据下面给出的 before_text，改写一句纯文本。」补定，2026-10-09。
- C 的提示词不放 evidence。
- T、B1，以及 B2 的 claim，附上请求里已经有的 `evidence_text`。提示词不再检索。
- `verify_edit`：`after_text` 去掉首尾空白后，与 `evidence_text` 逐字相同才算一致。`evidence_text` 不去掉空白。`score` 为空。支撑和矛盾不另判。
- B2 的 diff 段提示词当前就是留空。留空这句本身先保留，直到下面的补定 draft 在以后的实现票里被抄进提示词，并标明不是预注册原文。

### 缺口 1：B2 的 diff 没有提示词

120 行因此给不出三条主比较。B2 的 30 行是 `claim_text`。现有生成步骤在 diff 没有 `after_text` 时记生成失败。主比较收集到空的 B2 臂就拒绝。

决定：不把 `claim_text` 写入 `after_text`。不从 `compare_primary` 拿掉 B2。不把生成失败记成放行或记成 0。以后的实现只为这 30 个已经有 claim 的 `claim_id` 补 diff，模型输出的纯文本写入 `after_text`。claim 行保留。写完一条再发下一条。同一 `claim_id` + B2 + diff 已有 `after_text` 则跳过。

补定 draft。不是预注册原文。本轮不写进提示词文件，不发给模型。以后抄进提示词时必须带着「补定 draft。不是预注册原文。」这句标记：

根据下面给出的 before_text、上一阶段的 claim_text，以及请求里已经有的 evidence_text，改写一句纯文本。这一句是 after_text。claim_text 不是 after_text。不要输出 diff 标记。提示词不再检索。

值的顺序是 `before_text`，然后 `claim_text`，然后 `evidence_text`。末尾仍只用已经锁定的三句：模型输出是纯文本；生成模型只读 `DEFAULT_MODEL`；温度只读 `default_llm.temperature`。不新加角色，不新加评分规则。

验收：只有 `claim_text`、没有 diff 的 `after_text` 时，主比较拒绝，并且拒绝理由包含 B2。`claim_text` 与 `after_text` 同时存在且字符串不同时，B2 记录数为 30，三条比较的名字依次是 T-C、T-B1、T-B2。把 `claim_text` 原样抄进 `after_text` 的映射视为不合格。

### 缺口 2：高分方向是空白

现在没有一句规定高分代表放行还是拒绝。这一空白挡住把 `score` 当结果。

决定：补定 draft。不是预注册原文。本轮不写进核验代码：

高分不代表放行，也不代表拒绝。score 继续为空，不把 score 当结果。放行只使用已经写好的 decision。

已经写好的 decision 是：C 生成成功即放行；T 未绑定已入库 T1，或核验不过，则拒绝；B1 核验不过则拒绝；B2 在 diff 已给出 `after_text` 时放行，核验只记 `reverify_ok`。这不是新的放行定义。

固定放行率的选取沿用预注册：有分从高到低，同分 `claim_id` 字典序在前。C 仍无验证分数，仍用 `coverage_c`。缺分数时沿用现有实现，排在有分数之后。四臂 `score` 全空时，有分数的臂退回 `claim_id` 顺序。不新编 0 到 1 的刻度。

验收：进入主比较的四臂记录里 `score` 都是空。没有任何记录因为一个高分或低分被改成放行或拒绝。

### 缺口 3：抽检一致率与用户对评委 κ 没有可执行的配对

预注册已有一句：一致率等于两边标签相同的条数，除以两边都有标签的条数；另报用户对每一位评委、每一题的 Cohen's κ。仓库里没有把「两边」收成一对标签的函数。三家之间的 Cohen's κ 和 Fleiss' κ 已经按现有 `agreement` 写入结果表，本规格不重算、不改那些格子。

决定：不改 `PREREG.md`。不新编公式。把「两边」收成：用户抽检写下的标签，对每一位评委，题目 A 与题目 B 分开。一致率用上面那句除法。Cohen's κ 复用评委两两已经在用的同一算法，每个评委、每一题各报一个 κ 和条数。缺失不插补。用户不进入三家的 Fleiss' κ。没有用户标签时，结果表这两格保持未填。不得编数字，不得写成真人盲审。

验收：用夹具标签调用这个配对时，一致率等于相同条数除以两边都有标签的条数，κ 的条数等于该对两边都有标签的条数。没有用户标签的正式入口不写这两格。

### 缺口 4：对外表面被主指标挡住

README 导语、架构图、demo、简历一行、mastery pack 在真实主指标出现之前不能改。主指标是三条主比较的 false-accept rate，不是抽检一致率，不是评委 κ，不是延迟，不是成本。

决定：这五处在本规格期间不改。以后只有当 `RESULT.md` 的 T-C、T-B1、T-B2 三行 false-accept rate 来自同一次 `compare_primary` 输出时，才允许改它们。改的时候必须引用同一组点估计、区间和分母 k。k 是 T 的自然放行数。误放率的分母是该次固定放行的条数。k 为 0 时不得把误放率写成 0，也不得改这五处。

验收：主指标三行仍是未填时，这五处相对本规格的基线 `101c81e` 没有 diff。

### 缺口 5：120 行还不能直接喂给主比较

C、T、B1 的 `after_text` 可以回到现有四臂记录和 `verify_edit`。B2 在缺口 1 的 diff 完成之前不能。回放不调模型。回放使用已经锁定的温度 0，以及已经锁定的种子 20261007，只为了不触发「种子缺省则作废」。保存的请求没有发出种子。论文不得把那次请求写成带了种子。

决定：回放按 `claim_id`、臂、阶段取保存的文本。rewrite 的文本只进入 `after_text`。claim 的文本只进入 `claim_text`。diff 的文本只进入 `after_text`。延迟和成本若记录里没有，结果表保持未填，不填 0。消融只重放 T 的 `after_text`，判定用已经写好的消融开关。生产检索默认保持 hybrid+rerank。BM25 只出现在检索消融的名字里。`hybrid+rerank` 列不进入三条主比较。

验收：回放测试不构造会发请求的客户端，不读取三把 API 密钥，不改 120 行里已有的任何一行。B2 diff 补齐之前，主比较拒绝。补齐之后，三条比较都存在，且 B2 的 `after_text` 不等于该条的 `claim_text`，除非模型输出碰巧相同；测试夹具必须使用两个不同的字符串来证明映射没有把 claim 抄进 after。

### 缝

只留一条缝：现有的正式比较。测试从这条缝外面喂入保存的生成记录和夹具，断言三条比较的名字、B2 是否缺臂、`score` 是否为空、以及 `claim_text` 没有被抄进 `after_text`。不给核验或主比较再包一层新的放行定义。

## Testing Decisions

好的测试只看缝外面的行为：给定记录，要么得到名为 T-C、T-B1、T-B2 的三条比较，要么因为缺 B2 而拒绝。不把内部循环次数写成测试对象。

要测的是这条正式比较缝，外加抽检配对的夹具。先验是现有的正式 n=30 测试、生成器不发请求的测试，以及评委 `agreement` 的夹具测试。新测试同样替换传输，拦住连接，并在读到三把 API 密钥时失败。不执行会发请求的正式入口。不使用真实 n=30 去打模型。

本轮不新增这些测试。验收句写在上面各缺口里，留给以后的实现票。
