## 1.2 模块职责与角色禁止事项(角色诚实表 → 代码结构)

> 原则:角色禁止事项必须能在**代码结构上被看见**,不是藏在提示词里(ADR-0001)。被否方案是「引擎 + 角色配置」——角色边界只存在于配置时,禁止事项可被一次配置改动悄悄绕过。

| 角色/模块 | 类型 | 职责 | 禁止(代码强制方式) |
|---|---|---|---|
| `runner.py` | Workflow | 预算、步数、作废/隔离名单注入、导入 T0、轨迹落盘、模式开关 | 编造仍成立(无写判定工具);最终商业裁决(产品红线,prompt+闸双层);新调查(导入不做调查) |
| `roles/lead.py` | 真 Agent | 自主规划复验(ReAct 逐轮决策,无独立规划器);决定是否派 Critic | 无 T1 原文把 stale 改 fresh(规则闸强制);放行(无放行 API,绿灯唯一出口在 gates/) |
| `roles/critic.py` | 真 Agent | 只找「主张已死」的反证;动态决定检索 | 强化原主张(白名单无 `reverify_claim`);放行(同上);再派驻(白名单无 spawn,深度恒 1) |
| `roles/auditor.py` | 短循环判定 SOP | 判 fresh/stale/unknown(单轮 structured-output) | 改主张正文(无写工具);放行(唯一出口 `verdict` 进规则闸校验;**不得拥有放行权**) |
| `roles/forensic.py` | 真 Agent | 审本课题长期记忆(死事实/互斥/无源) | 改主张正文;删除文件;放行(W9–W12,本期不挂载) |
| `gates/rule_gate.py` | Workflow(纯函数) | stale/unknown 不得绿灯;无 T1 不得 fresh;checksum 对不上不得 fresh/续命;作废名单打回 | 扮演调查(纯函数无检索能力) |
| `gates/human_latch.py` | Workflow | 作废、续命、重跑触发(写路径唯一) | 自动续命;自动抹记忆(全部须人触发) |

**三层分离**(任一实现不得混淆):prompt 管任务(skill 文件)、白名单管禁止(roles 构造时的工具清单)、规则闸管放行(gates/)。「Agent 不得把红灯改回绿灯」只约束 Agent 侧工具链;人审是 L0 合法出口,此口径写入 `rule_gate.py` 注释(ADR-0006 §4)。

**阶段挂载说明:** 现行默认 Lead 白名单为 `LEAD_TOOLS_W3`(含 `spawn_critic`,不含 `spawn_auditor`)。`spawn_auditor` 已由 ADR-0009 废止;Auditor 走闸路径单轮判定。记忆卫生工具仍不在默认 Lead 白名单。未挂载 = 模型物理上不可见。

## 1.3 `gates/rule_gate.py` 接口形状(规格级,实现自由)

```python
def rule_gate(claim: Claim, decision: GateDecision, ctx: GateContext) -> GateResult:
    """绿灯唯一出口。任何 status=fresh/续命 的写都必须经过本函数。
    校验项(全部机械执行,违例即打回并附结构化原因):
      1. stale / unknown 不得绿灯
      2. 无 t1_evidence_ids 不得 fresh
      3. checksum 对不上不得 fresh / 不得续命
      4. claim_id ∈ invalidation_list 不得 fresh(重跑打回)
    GateContext 注入:作废名单、checksum 计算函数、eval 模式开关。
    """
```

- 纯函数、零 I/O(名单/checksum 由调用方注入),pytest 直测。
- gold.json 直接驱动本函数进 `tests/eval/`(#8 三道验收之三:金标就是测试数据,一份两用)。
- `gates/human_latch.py` 是唯一允许写 `status=void` / 触发续命写路径的代码;它内部调 `rule_gate`。

## 1.4 `store/` 检索层职责(ADR-0003)

- `base.py`:`RetrievalStore` 接口(retrieve/read_source/ingestion)+ 内存假实现,供单测与 gates 测试零 LLM、零磁盘。
- `sqlite_store.py`:chunk 一行,`as_of=T0|T1`、`source_type`、`doc_id`、`checksum` 全是列,过滤 = WHERE 子句;四张表见 §2.5。
- `pipeline.py`:`recall(BM25Okapi+jieba) → vector 融合 → rerank`(评测臂已可跑,不是现在时空实现);生产默认 BM25。`vec` 列已在 schema。无增益不得改生产默认臂。

## 1.5 `eval/` 与 `ui/` 职责边界(ADR-0005、ADR-0002)

- `eval/` 是 CLI(`python -m freshlatch.eval run|control|report`),端到端跑真主链,**不做评测页 UI**;评测展示 = 终端 runner + 复验单 UI 逐条点回,两个现成界面拼完整叙事。
- `ui/` 是薄壳:复验单页 + HumanLatch 审批端点;`ui/app.py` 同步 `def` 端点(FastAPI 线程池执行,同步 SqliteSaver 不阻塞事件循环;不碰 `ainvoke`/AsyncSqliteSaver)。
