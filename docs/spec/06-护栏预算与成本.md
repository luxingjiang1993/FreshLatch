# §6 护栏、预算与成本

> 出处:#6(护栏与派驻)、#2(模型与成本)、ADR-0004。Guardrails 集中为 dataclass 由 Runner 注入,评测 harness 可代码级覆盖——金标可复现的工程手段。

## 6.1 Guardrails 参数(定稿)

| 参数 | 值 | 强制层 | 语义 |
|---|---|---|---|
| `lead_max_steps` | 18 | 循环层 `while` 条件 | 归零不硬断,注入「预算已尽,基于现有证据下结论」系统消息软收尾——**护栏管天花板,不管结论** |
| `critic_max_steps` | 8 | 同上 | Critic 派驻实例预算 |
| `auditor_max_steps` | 6 | 同上 | Auditor 实装后生效(W5–W8);单轮 SOP 形态下为保险上限 |
| `forensic_max_steps` | 8 | 同上 | W9–W12 |
| `retrieval_budget` | 24 / Run | Run 级共享计数器(retrieve 外包计数装饰器) | Lead 查多了 Critic 就剩得少,倒逼珍惜查询;超限返回结构化「预算已尽」(fail-soft) |

- 重试计步:非法工具调用(含 focus 非法值)的每次重试消耗 Lead 步数预算(#14)。
- token 限额熔断:本期上下文小(单主张),用不上【触发:语料/记忆变大后启用】;工具失败重试 N 次【触发:联调观察失败率后定 N】。

## 6.2 循环形态(ReAct,ADR-0004 子决策⓪)

- 单循环内 think → act(tool_call) → observe(tool_result) 交错,每轮由模型基于最新观察决定下一个工具或收尾;**无独立规划器**。
- Plan-and-Execute 弃用(登记在册):复验是发现式调查,先出的计划会被第一步检索结果推翻;「自主规划」= 逐轮决策,颗粒度是「下一步」不是「全程」。
- 固定 workflow 编排(节点顺序代码写死)立项即排除——那是假 Agent。
- Reflexion 不实装:「找反证」由 Critic 派驻承载,不让 Lead 自产自验(不变量 I1)。

## 6.3 动态派驻(#6 子决策②)

- `spawn_critic` 是 Lead 白名单里的普通工具,模型自己决定何时调;
- 命中后同进程**同步**起全新循环实例:新会话(消息历史不共享)、换人格系统提示词、换白名单、换预算;
- 只传「主张原文 + focus + 相关 evidence_id 列表」——激励隔离(Critic 不被 Lead 思路带偏)+ 省 token + 评测可复现;
- **深度恒 1(硬约束)**:Critic 白名单无 spawn 工具,控制流永远 Lead 一个中枢。

## 6.4 轨迹与遥测(评测一等公民)

- 每圈 messages 存 JSONL(`reports/trajectories/`),含步数/检索预算遥测;轨迹 = 评测回放 + 面试演示 + 复现三合一。
- 结构化轨迹断言进 `tests/unit/`(如「Lead 第 N 圈应调 retrieve」),护栏与白名单的可测性兑现。

## 6.5 模型与成本(#2,成本注记格式定稿)

- **开发期统一 qwen-flash**:Lead 循环、Critic、假绿对照同模型(对比公平);每主张复验 ≈ ¥0.001,一次完整 12 主张 Lead 复验 ≈ ¥0.01–0.02,加 Critic 全链路 ≈ ¥0.02–0.03;评测 100 次全量 ≈ ¥2–3,可忽略。
- 文档统一标注:**「开发用最便宜模型压成本,真实业务可换更好模型」**。
- 真实业务升档建议:Critic / Auditor 升 qwen-plus 档,Lead 保持 flash;升档后假绿对照仍须与 Lead 同档，或同时跑两档对照。
- 已知模型事实:不假设并行 tool_calls(qwen-flash 冒烟实测 0 次并行);中文工具描述 + 中文语料下循环判定准确率 ~0.79,错误集中在多文档时间线推理——Critic 派驻与规则闸正是对此的架构级对冲。
- API key:`.env` / `DASHSCOPE_API_KEY`;OpenAI 兼容 base_url 环境变量;额度已验证足够。
