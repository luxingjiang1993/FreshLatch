# §15 整仓分层验收（Full-repo layered verification）

> 性质：**编排规格**（如何把本仓已有权威命令、evidence、评测纪律一次跑齐并诚实出结论），**不含新功能决策**。与产品 Phase 规格冲突时，以各 Phase 规格 + ADR + `docs/evidence/*/ACCEPTANCE.md` 为准。  
> 词表：`CONTEXT.md`  
> 评测纪律母本：`docs/spec/04-评测纪律.md`、ADR-0005、ADR-0007  
> 编排技能（headcount）：`implementation-planning` → `completion-verification` →（红）`technology--systematic-debugging` →（缺测）`technology--test-driven-development` →（结）`technology--code-review`；L3 加 `ai-ml-governance` / `experimentation`；触安全面加 `security-architecture-review`  
> **判据锁定日**：2026-09-30（pre-registration）。事后改「什么叫完整通过」= 本次整仓验收作废（HARKing）。  
> 状态：alive — 垂直包新增关单后只**追加 L2 勾选行**，不回改已锁层级定义。

---

## Problem Statement

仓库已有多套测试与验收入口（`pytest`、垂直包 ACCEPTANCE、LLM 金标 runner、历史 `scripts/w12_*`），但缺少一份**单一编排规格**：什么叫「对整个项目做完整测试」、各层命令是什么、哪一层绿能声称什么、哪一层未跑必须显式写「未跑」。没有分层与预锁，容易把全量 `pytest` 绿误读成 Hard-Gold / 安全认证 / 统计测量通过。

## Success measure（先于跑测锁定）

一次整仓验收产出一份**分层结论报告**（建议路径：`docs/evidence/full-repo/REPORT-<YYYYMMDD>.md` 或会话内等价结构），且同时满足：

1. **L0 + L1 必过**（确定性；零 LLM）。  
2. **L2 按本规格勾选表逐项勾完**（已关门垂直包复验；档位保持冒烟/采用层，不升格）。  
3. **L3 状态显式**：`已跑`（含 decoding 留档）或 `本轮跳过（原因）`；跳过不得写成「评测通过」。  
4. **报告文首声明**：演示/冒烟可过 ≠ 测量可信；禁止把本轮结论报成 Hard-Gold、渗透认证、采用率或 W12「已通过」统计证明。

目标日期：按当次会话执行；不以日历 KPI 代替分层诚实。

## Scope

### In

- L0 静态可编、L1 全量确定性测试、L2 已登记垂直包硬 Exit 复验勾选、L3 LLM 金标/假绿（可选里程碑）、报告与技能编排。  
- Windows 默认命令（PowerShell；`PYTHONPATH=src`）。  
- 与 README / AGENTS 权威命令对齐：`compileall`、`pytest`。

### Out（本期拒绝）

- 把整仓验收升格为 Hard-Gold 或 Phase-1 测量关门。  
- CI 强制全量 LLM 回归（ADR-0005 已否）。  
- 新造评测页 UI、引入 LangSmith/deepeval/openevals。  
- 改金标 / 改 ACCEPTANCE 判据以凑绿。  
- 默认重跑全部历史 `scripts/archive/w12_comprehensive_*` / 专项 harness（仅里程碑或票内点名时另开，不进本规格默认「完整」定义）。  
- 真人盲看 / 录屏点回作为本规格自动闸（可记 L2 人工可选；缺席标「未做」）。

### Deferred（推迟，非拒绝）

- retrieve 轨与主张金标分列的 Hard-Gold 增益门（见 accounting-card / ADR-0026）。  
- N≥5 方差报告作为整仓默认（归评测里程碑，见 §4）。  
- UI 人点回全量金标锚点（W4 J1 类）作为整仓必过。

## 层级定义（行为保证）

| 层 | 名称 | 保证什么 | 不保证什么 | 触发 |
|----|------|----------|------------|------|
| L0 | 静态 | `src` 可编译 | 行为正确 | 每次整仓必跑 |
| L1 | 确定性回归 | 闸/单测/垂直包已入库自动化不变量未破 | 模型语义、生产渗透、Hard-Gold | 每次整仓必跑；≈ CI gate |
| L2 | 垂直包硬 Exit | 已关门包的 ACCEPTANCE 仍可勾；档=各包原文 | 统计通过率、未列包已交付 | 每次整仓必勾 |
| L3 | LLM 金标/对照 | 真主链 vs gold（及可选 control）按 §4 | 跨会话逐位复现；temp=0 多 seed 假信心 | 有 key 的里程碑；否则显式跳过 |
| L4 | 结论文档 | 分层可读、未声称写清 | 替代人工 Gate 合并 | 每次整仓必出 |

**两个绿灯语义（必须分写）**

- **不变量绿** = L0+L1（+L2 确定性勾选）通过。  
- **表现绿** = L3 报告通过（若跑）。二者不得合并成一句「项目测试全部通过」。

## 命令与入口（可执行）

环境前置（Windows）：

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new()
cd <repo-root>
# 已激活 .venv 且 pip install -r requirements.txt
$env:PYTHONPATH = "src"
```

### L0

```powershell
python -m compileall -q src
```

通过：exit code 0，无报错输出。

### L1

```powershell
python -m pytest -q
```

通过：全绿。失败 → 停整仓「完整通过」声称；进入调试技能，禁止改判据。  
说明：`pytest.ini` 已设 `pythonpath = .`；与 CI「`pytest tests/`、零 LLM」同语义。含 `tests/unit/` 与 `tests/eval/`（金标驱动**闸**单测，非 LLM runner）。

### L2 勾选表（预锁 · 2026-09-30）

每项：对照 ACCEPTANCE / DoD 原文勾「复验命令绿」或「证据仍有效 + 关联 pytest 绿」。不得把档位改写成 Hard-Gold。

| ID | 包 | 证据 / DoD | 关联自动化（非穷尽） | 档位 |
|----|-----|------------|----------------------|------|
| L2-V15 | V1.5 Evidence-bound | `docs/evidence/v15/ACCEPTANCE.md` · `V15-DoD-CLOSE.md` | `tests/unit/test_evidence_bound_*.py` 等 | 冒烟 |
| L2-I2 | I2 安全三例 | `docs/evidence/i2/ACCEPTANCE.md` · `I2-DoD-CLOSE.md` · `docs/security.md` | `tests/unit/test_i2_*.py` | 冒烟；≠渗透认证 |
| L2-V2 | V2 发前钩子+台账 | `docs/evidence/v2/ACCEPTANCE.md` · `V2-DoD-CLOSE.md` | `tests/unit/test_v2_*.py` · `test_publish_hook*.py` | 冒烟/采用层 |
| L2-V1 | V1 发前闭环 | `docs/evidence/v1/ACCEPTANCE.md` · `V1-DoD-CLOSE.md` | `test_prepublish_*.py` · `test_v1_mck_soai_pack.py` · `test_disposition.py` 等 | 按该包原文 |
| L2-α | α 不变量 | `docs/evidence/batch1/` 等 · `scripts/run_alpha_inv_acceptance.py` | `test_alpha_inv_acceptance.py` | demo/不变量 |
| L2-其它 | i0/i1/batch3–5/β+ 等 | 各 `docs/evidence/**/ACCEPTANCE.md` | 对应 `test_*acceptance*` | 按原文；未复验标「本轮未勾」 |

**L2 最低完整线（本规格默认「完整」）**：L2-V15、L2-I2、L2-V2、L2-V1、L2-α 五项勾完；其余 evidence 目录允许「本轮未勾」但必须在报告列出。

### L3（可选 · 里程碑）

需根目录 `.env` 中可用的 `DASHSCOPE_API_KEY`（或等价）。命令母本见 §4：

```powershell
python -m freshlatch.eval run --gold data/eval/gold.json
python -m freshlatch.eval control
python -m freshlatch.eval report
```

通过线：

- **跑通**与**分数/矩阵**分开写。  
- N 默认按调用参数；N 小只报条数/命中，**不报方差、不报通过率伪装**。  
- decoding：temperature、seed、模型、日期写入报告；声明托管端点漂移 → 跨会话仅近似复现。  
- prompt 红线：control 不得泄 T1/金标。  
- 本轮跳过：报告写 `L3=SKIPPED` + 原因（无 key / 成本 / 非里程碑）。

### L4 报告最低字段

1. 执行日期、git HEAD（短 hash）、Python 版本。  
2. L0/L1 命令、exit、摘要（失败用例名若有）。  
3. L2 勾选表逐行：过 / 未勾 / 红。  
4. L3：RAN + 报告路径，或 SKIPPED + 原因。  
5. **未声称**清单（至少含）：非 Hard-Gold；非渗透认证；非付费客户验证；README Known gaps 仍成立者点名。  
6. 技能链实际使用记录（便于复盘）。

## Acceptance Criteria（可真假判定）

| # | 判据 | 层级 |
|---|------|------|
| A1 | L0 `compileall` exit 0 | demo |
| A2 | L1 全量 `pytest -q` 全绿 | demo |
| A3 | L2 最低完整线五项均已勾「过」，或整仓结论明确降级为「不完整（缺 L2-x）」 | demo |
| A4 | L3 要么 RAN 且 decoding 入报告，要么 SKIPPED 且原因非空；无第三种含糊状态 | 冒烟/声明 |
| A5 | L4 报告存在且含「未声称」节；无「项目已 Hard-Gold / 安全认证通过」类句子 | demo |
| A6 | 未为凑 A2/A3 修改 `data/eval/gold.json` 或任何 ACCEPTANCE 硬判据 | 纪律 |
| A7 | 红测处理路径：先根因再改代码；禁止删测/扩 skip 充当整仓绿 | 纪律 |

**整仓「完整通过」公式**：A1∧A2∧A3∧A4∧A5∧A6∧A7。  
缺 A3 → 最多声称「L0+L1 回归绿，垂直包勾选不完整」。  
L3 SKIPPED → 仍可「完整通过」（A4 满足），但报告不得暗示金标表现已验证。

## 技能编排（执行协议）

1. **`implementation-planning`**：开跑前写出当次计划（层、命令、是否跑 L3、报告路径）。  
2. **`completion-verification`**：逐层真跑、读输出；未绿不宣称该层过。  
3. 失败 → **`technology--systematic-debugging`**；确认缺测 → **`technology--test-driven-development`**（另票/本轮修复须声明）。  
4. 大矩阵可拆 → **`parallel-agent-delivery`**（写面互斥；禁止两会话改同一测试文件凑绿）。  
5. L3 → **`ai-ml-governance`**（判据层声明）+ 需要采样时 **`experimentation`**。  
6. 安全相关失败或 L2-I2 → **`threat-modeling` / `security-architecture-review`**（评价，不替代红测根因）。  
7. 收尾 → **`technology--code-review`** 写分层评价；可选 **`benefits-realization`** 对照立项切片「承诺 vs 本轮验证」。

对 Cursor 的默认口令：

> 按 `docs/spec/15-整仓分层验收.md` 执行：先 `implementation-planning` 出当次计划，再用 `completion-verification` 跑 L0→L1→L2（L3 按计划）；结束后 `technology--code-review` 写 L4 分层结论，遵守未声称清单。

## 失败与降级

| 情况 | 处置 |
|------|------|
| L0/L1 红 | 整仓「完整通过」失败；修或停；出部分报告 |
| L2 单项红 | 标该包回归；完整通过失败，除非降级范围并改报告标题为「部分验收」 |
| L2 未勾（时间不够） | 不得默认为过；降级或不完整 |
| L3 红 / 抖动 | 不归因到 L1；单独记表现层；不改金标 |
| 无 API key | L3=SKIPPED，不阻塞完整通过公式中的 A4 |
