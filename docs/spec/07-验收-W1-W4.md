## 7.4 W4 末终审:锁定判据(四件套证据链)

**判定人**:开发者本人按检查表逐项自验 + 1 名真人盲看复述测试;W4 末一次性判定。单人开发的三个自监督机制:判据 pre-registration、复述测试必须真人盲看(自己测自己不算数)、AFK 会话冷启动复现抽查。

### J1 点回判据(demo 层)

- 金标内所有有 `t1_evidence_ids` 的主张(**预计 8 条**;must_unknown 无 T1 原文天然豁免)逐条点回,落在 gold.json 登记的 anchor 段落;
- T0 点回同机制顺验,但不进停止条件;
- **全量,不抽样**(停止条件是生死线,抽样 = 给失败留侥幸);
- 一镜到底录屏。

### J2 有效反证判据(冒烟层)

- 硬判据(机器可查,三硬):① 可点回 t1 证据;② 理由文本含显式因果句(指出 T1 原文哪一句推翻主张哪个前提,不得只写「与最新文档不符」类空话);③ 引用 span 与金标 `causal_chain` 登记的致死段落对齐;
- 软复核:真人抽 2 条复述(降级抽测,不作硬判据——「可理解」的硬判据必须机器可查,不同读者的复述判定不可复现);
- **计数口径:按主张计**。must_stale 4 条;**3 遍 × 3 seed、显式非零温度**(temp=0 时 seed 是摆设,三遍跑出相同结果 = 假信心);停止条件达成 = ≥2/3 遍出现 ≥1 条有效反证;4/4 全覆盖 = 质量目标,非停止条件;
- **反向护栏**:must_fresh 不得出现有效反证;
- n=3 无统计功效,诚实框定为**冒烟检查**,不报方差;正式多运行(`--runs N≥5`)归 W5–W8。

### J3 四条红线(demo 层)

- 前三条(聊天框/「生成答案」/「开始调查」):代码单测进 CI(防回归)+ 人看录屏逐条复核;DOM/源码断言是必要不充分;
- 第四条(不得被复述成「又一个 EvidenceOS」):**复述测试**——不给任何介绍,真人盲看 3 分钟后写一句话「这个产品是做什么的」+ 回答探针「它和文档搜索工具有什么区别」;判定原话留档;判据 = 不得被复述成「第二个 EvidenceOS」。

### J4 复现抽查(冒烟层)

- AFK 会话冷启动重跑金标 runner:**闸层(must_* 零违例)逐位复现;判定层(矩阵条数)按文档化容差**;违例级背离(must_stale 被判 fresh 等)触发人查;
- 模型版本 + 日期 + decoding 参数入档;qwen-flash 是活托管端点,跨会话复现只能近似,此限制写入留档。

## 7.5 未过处置:分级止损预案(ADR-0007 §2,写进规格即生效)

| 失败类别 | 判例 | 处置 |
|---|---|---|
| **定位红线失败** | 界面已是聊天框;复述测试成立(EvidenceOS 化);主按钮违禁 | **不可修,直接停**(立项失败) |
| **工程失败** | 点回不达标;Critic 反证不达标(J2 未达);其他可修技术问题 | **一次性 2 周修复窗口**,到期用**同一份检查表、同一批判据**复验一次,只换新证据;**窗口不得续杯**;复验再不过 = 立项失败 |

- 判据事后修改 = 验收作废(HARKing):可编辑 ≠ 可逆;
- 「迭代到达标为止」被否:停止条件名存实亡;
- 止损优先于演示打磨:为过验收而改产品定位/主按钮/主界面 = 违规(宁可验收不过)。

## 7.6 与 W12 的关系

复述测试是共用仪器:W4 验收(不得被复述成「第二个 EvidenceOS」)与 W12 停止条件(两次纠正无效)共用;W4 的记录格式即 W12 的底稿。
