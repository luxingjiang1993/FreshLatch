## 0. 目的

同一周报窗口、同一行，同时看见端到端有多慢，以及检索有多少次走了回退。只看见毫秒数，读不出「快是因为整窗都退回了词法路径」。

| 要看见的 | 不在本页交付 |
|----------|----------------|
| 同一行：（a）`e2e_p95_ms`；（b）`retrieval_fallback_rate` | 只报 P95，把这一行当成放行成功 |
| 分母（a）成功完成请求；（b）检索调用次数 | 用离线检索臂的单次 p95 填本周生产格 |
| 回退分子：`bm25_fallback`，以及 `lexical_fallback`（rerank 缺失回退） | 把显式切到 BM25 或词重叠精排记成回退 |
| cost 留在 phase-2，备注里写明 | 把 cost 升成第三个主字段或本波主 SLI |
| 对照 NVIDIA / Phoenix 的字段习惯 | 新建 Phoenix-*、Confident-* 或 NVIDIA-* 主 KPI 名 |

## 1. 同一行两字段与分母

周报与机检输出都使用同一行。两列必须同时在场。缺一列 = 本协议违例。

| 列 | SLI 角色 | 操作定义 | 分子 / 分母 | 单位 |
|----|----------|----------|-------------|------|
| `e2e_p95_ms` | （a） | 窗口内成功完成的生产请求，墙钟时长的第 95 百分位 | 样本 = 成功完成请求；分母记为 `N_request_ok` | 毫秒 |
| `retrieval_fallback_rate` | （b） | 检索调用里触发回退的比率 | `fallback_n / N_retrieve` | 次数比 |

机检一行（占位，禁止填假数字）：

```text
e2e_p95_ms=<毫秒|未计|样本不足> retrieval_fallback_rate=<fallback_n/N_retrieve|未计|样本不足> notes=cost→phase-2；P95不单独构成放行成功
```

人读表格与上面这行是同一组数，不是两套 KPI。

### 1.1 分母（a）：成功完成请求

`N_request_ok` = 窗口内、生产路径上已经走完并留下可核对终态的请求数。终态指复验单上写出了主张落档，或发前出口写下了 allow / deny。

不进入这个分母：

- 中途退出，或预算耗尽且没有终态  
- 评测 gold 跑、冻结金标 canary（那是 SLI 6，金标不进生产 score）  
- 只发生了检索、还没有终态的半截请求  

时长是该请求从受理到写下终态的墙钟，单位毫秒。本票不新增计时字段，不改 `src/`。当周账本没有逐请求墙钟时，`e2e_p95_ms` 写「未计」。`N_request_ok` 仍可按终态计数；数不出来就连分母一起走 §4。

有 n 条请求且每条都有墙钟毫秒时：把毫秒升序，取下标 `ceil(0.95 * n) - 1`（从 0 数）的那一条，作为 P95。n=1 时 P95 就是这一条，notes 写明 n=1。这是冒烟读数，不报总体方差，不锁通过线。输入已经是毫秒，不再乘 1000。

n=0，或窗口划不出来：写「样本不足」。禁止写 0、0.0 或 0 ms。

离线检索计时在 `src/freshlatch/eval/retrieve_eval.py`（样本是秒；空样本的返回值不用于本页）。`docs/evidence/retrieval-decision.md`、各处 `cost.json`、#283 / #285 / #293 里的检索臂 p95 或重排 p95，是当时的单次对照，留在那一页。禁止抄进本周 `e2e_p95_ms`。

本行不记录 temperature、seed 或模型版本。那些不是 SLI 5 的参数。托管模型会漂移，本页不把某次生成复现写成 P95。

### 1.2 分母（b）：检索调用次数

`N_retrieve` = 窗口内生产路径上已经完成的检索调用次数。一条调用对应 `try_retrieve` 走到 `store.retrieve` 之后写下的事件：`type=retrieve`，并带 `retrieval_mode` 与 `rerank_mode`（`src/freshlatch/runner.py`）。`InMemoryStore` 与 `SQLiteStore` 都写这两个标记。

不进入这个分母：

- `type=budget` 且 `kind=retrieval_exhausted` 的耗尽事件。它不是一次完成的检索，也不是回退  
- 评测臂强制 `retrieval_mode` 的 gold / canary 跑。生产路径不能指定 `retrieval_mode`  
- 尚未形成 `type=retrieve` 事件的失败  

`N_retrieve` 为 0，或窗口划不出来：fallback rate 写「样本不足」。禁止写 0、0.0 或 0%。

### 1.3 分子：回退调用

`fallback_n` = `N_retrieve` 里满足下列任一记录的调用数。一条调用至多计一次。

| 记录 | 含义 | 计入 |
|------|------|------|
| `retrieval_mode=bm25_fallback` | 请求的是 dense / hybrid / hybrid+rerank，但查询侧或池内没有可用向量，整次退回 BM25。缺向量不得标成 hybrid 或 hybrid+rerank | 回退 |
| `rerank_mode=lexical_fallback` | rerank 缺失回退。生产精排是本地 `BAAI/bge-reranker-base`。权重缺失、推理失败，或进程处于 `FRESHLATCH_NEURAL_RERANK=0` 时，退回 `rerank_lexical`，检索臂仍可记 `hybrid+rerank`，精排标记必须是 `lexical_fallback`，并打 warning | 回退 |

下面这些是显式开关或成功路径，**不**进 `fallback_n`：

| 记录 | 含义 |
|------|------|
| `retrieval_mode=bm25` 且 `rerank_mode=none` | `set_retrieval_switch("bm25")`。不改 `PRODUCTION_RETRIEVAL_MODE` |
| `retrieval_mode=hybrid+rerank_lexical` 且 `rerank_mode=lexical` | `set_retrieval_switch("hybrid+rerank_lexical")`。词重叠是显式开关，不是缺失回退 |
| `retrieval_mode=hybrid+rerank` 且 `rerank_mode=bge-reranker-base` | 神经精排成功 |
| `retrieval_mode=hybrid` 或 `dense`，且 `rerank_mode=none` | 该臂按请求完成，没有走上面的两条回退 |

比率 = `fallback_n / N_retrieve`。两个字段使用同一个窗口。只输出 P95、删掉 fallback 列 = 本协议违例。

分母大于 0 且确实数到 `fallback_n=0` 时，比率写 `0 / N_retrieve`。notes 写明：这是回退计数，不是放行已经成功，也不是 P95 已经过线。

## 4. 样本不足与未计

| 情形 | `e2e_p95_ms` | `retrieval_fallback_rate` |
|------|----------------|----------------------------|
| 窗口不可划定 | 样本不足 | 样本不足 |
| `N_request_ok=0` | 样本不足 | 按检索事件另判；检索也没有则同样样本不足 |
| 有终态但没有逐请求墙钟 | 未计 | 检索事件可计则照实填写 |
| `N_retrieve=0` | 请求侧照实填写或未计 | 样本不足 |
| 两侧都能计 | 毫秒 | `fallback_n / N_retrieve` |

任何一格都不许用 0、0.0、0% 或 0 ms 代替「样本不足」或「未计」。

两侧都不足时的句式：

```text
本周样本不足：成功完成请求 N_request_ok=0（或窗口不可划定），检索调用 N_retrieve=0（或窗口不可划定）。e2e_p95_ms 与 retrieval_fallback_rate 都写「样本不足」。不把 P95 写成 0 ms。cost 仍在 phase-2。本行不是放行成功。
```

有 P95、fallback 未计时的句式：

```text
e2e_p95_ms 有读数，retrieval_fallback_rate=未计。同一行仍保留两列。未计的回退率不能当成 0。本行不是放行成功。
```

## 5. P95 与放行成功

本行是观测 / Watch。生产放行是否成立，仍看既有硬闸（无证拒拦、未确认不出门、自红转绿、无 T1 绿灯）。那些谓词的语义在 ADR-0042，本页不改 `src/` 闸。

同时成立的读法：

- 同一行必须同时有 `e2e_p95_ms` 与 `retrieval_fallback_rate`（值可以是毫秒、比率、未计或样本不足）。  
- 毫秒数小，只说明这批成功完成请求的墙钟尾部。它单独不构成放行成功。  
- `fallback_n = N_retrieve` 且 `N_retrieve > 0` 时，notes 写「全在 fallback」。这时 P95 无论多小，本行都按「全在 fallback」读，不按放行成功读。快，可能只是整窗退回了 BM25 或词重叠精排。  
- fallback 率为「未计」或「样本不足」时，同样不能把旁边的 P95 读成放行成功。  
- 部分回退也要和 P95 一起读。禁止在叙事里删掉 fallback 列。

本页不把 fallback rate 升成新的放行硬闸，也不把某一毫秒数写进 [`生产补丁放行SLO.md`](生产补丁放行SLO.md) §4 的预注册门槛。

## 8. 叙事

可接受的观测叙事：

- 「同一窗口同一行：e2e_p95_ms 与 retrieval_fallback_rate=fallback_n/N_retrieve；cost 在 phase-2」  
- 「N_request_ok=0，P95 写样本不足，不报 0 ms」  
- 「有终态、没有墙钟，P95 写未计；fallback 按检索事件另填。本行不是放行成功」  
- 「fallback_n=N_retrieve，notes 写全在 fallback」

不可接受的叙事：

- 「P95 是 80 ms，所以这趟放行成功」  
- 「P95 好看」而同一行没有 fallback rate  
- 「全在 fallback，但 P95 很低，所以检索是健康的」  
- 用 retrieval-decision 或 cost.json 的历史毫秒填本周生产格  
- 把显式 BM25 开关记成 `bm25_fallback` 来压低或抬高回退率  
- 任何把本页数字写成实验成立、或拿来改判路线 Y 的句子

本波 SLI 5 为观测/Watch。把 P95 或 fallback rate 升成 Gate，须另决议，并事先锁定判据。
