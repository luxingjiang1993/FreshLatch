## 0. 目的

每次周报行、每次 canary 执行、每条协议发布记录，都能读出当时用的是哪一版代码、哪一版数据集。针变了，旧值还在。

| 要看见的 | 不在本页交付 |
|----------|----------------|
| 可机读针族：必填 `code_pin` · `dataset_pin`；可扩 `model_pin` / `prompt_pin` / `index_pin` | 把填了针读成 canary pass |
| 未跑写「未跑」 | 未跑写成 0、0%、100% 或 pass |
| 只读继承 SLI 6 的占位针 | 回写 `gold.json` 或任何金标文件来凑一根新针 |
| 变更另起记录，旧记录保持原样 | 与 pin 平行的营销版号主 KPI |
| 成绩仍只指向 SLI 6 | 在本页计算或存放 pass rate |

SLI 6 的跑法仍是 [`冻结金标canary跑法.md`](冻结金标canary跑法.md)。占位针仍是 [`docs/evidence/slo-min6/canary-pin.md`](../evidence/slo-min6/canary-pin.md)。本页不改那两页的集、门、pass rate 列和预锁表。

## 1. 与 SLI 6 分列

SLI 6 回答：冻结 canary 集上，过门遍数占 N 的多少。  
本页回答：这一行记录对应的代码、数据集，以及可选的模型、提示、索引，身份是什么。

| | SLI 6 | 本页 · P4 |
|--|-------|-----------|
| 身份 | min-6 主行 | phase-2 周报附录 |
| 主数字 | frozen gold canary pass rate | 无。针不是分 |
| 必填针 | 成绩行上的 `canary_pin` 与 `code_pin` | 同一对，键名 `dataset_pin` 与 `code_pin` |
| 可扩针 | 调用既有 LLM 金标入口时，逐遍另记 model、temperature、seed、日期 | `model_pin` / `prompt_pin` / `index_pin`。温度、seed、日期是伴随项，不是针，也不是主 KPI |
| 未跑 | pass rate 与 `code_pin` 写「未跑」 | 本记录的 `code_pin` 与 `dataset_pin` 写「未跑」。预锁只出现在 `sli6_dataset_prelock` |
| 所在表 | [`docs/evidence/slo-min6/周报骨架.md`](../evidence/slo-min6/周报骨架.md) 的 SLI 6 格 | [`docs/evidence/slo-phase2/周报附录骨架.md`](../evidence/slo-phase2/周报附录骨架.md) 的 P4 行 |

### 1.1 有针 ≠ canary pass

下面五条同时成立：

1. **针证明可追溯，不证明过门。** `code_pin` 与 `dataset_pin` 都写成了具体值，只说明这一行声称读过什么。过门与否只看 SLI 6 的 pass rate。  
2. **本页不存放率。** `canary_status` 只有两个合法值：`未跑`，或 `见 SLI 6`。`见 SLI 6` 的意思是去读 SLI 6 那一格，不在本页推断过或没过。  
3. **禁止的状态词。** `pass`、`fail`、`3/3`、`0`、`0%`、`100%`、`1`、`true`、`false` 都不是 `canary_status`，也都不是任何一根针的值。  
4. **预锁不是成绩。** `sli6_dataset_prelock` 抄的是占位页上的 blob。它出现，不表示 canary 已跑，也不表示 pass。  
5. **填了可选针同样不是 pass。** `model_pin`、`prompt_pin`、`index_pin` 有值，只多三个身份。不新开一条主 KPI，不代替 pass rate。

本页当前没有 canary 执行。因此本页交出的记录里，`canary_status` 是 `未跑`，不是 `见 SLI 6`。SLI 6 自己的 pass rate 仍是「未跑」。

### 1.2 对照

arXiv 2608.26385 的习惯是：冻结 canary 集、写下版本针、再单独报 pass rate。本页只取「版本针与成绩分开」这一句。不把该文的指标名抄成第二套主 KPI，不新建 Confident-* 主名，不把该编号写成一份 URL。

## 2. 可机读针族

一块记录是一组固定的行。每行一个键。键与值之间是 `: `（ASCII 冒号，后接一个空格）。值取该行剩余的全部字符，不再拆分。

缺键、多键、空值、乱序，这一块作废。作废之后不自动补成「未跑」。要保留的话，另写一块完整的记录。

### 2.1 键（顺序固定）

| 序 | 键 | 是不是针 | 合法值 |
|----|----|----------|--------|
| 1 | `record_id` | 否 | 非空标识。不是产品版号，不是主 KPI |
| 2 | `record_kind` | 否 | `weekly`、`canary_run`、`protocol_release` 三者之一 |
| 3 | `window` | 否 | 起止或发布日，写明 Asia/Shanghai |
| 4 | `code_pin` | 是 · 必填 | 实际执行的 git sha，40 位小写十六进制；否则 `未跑` |
| 5 | `dataset_pin` | 是 · 必填 | 实际读到的 `40位blob\|must_stale`；否则 `未跑` |
| 6 | `model_pin` | 是 · 可扩 | 实际调用的模型身份；不适用写 `—`；适用但没记下写 `未跑` |
| 7 | `prompt_pin` | 是 · 可扩 | 实际使用的提示身份；不适用写 `—`；适用但没记下写 `未跑` |
| 8 | `index_pin` | 是 · 可扩 | 实际使用的索引身份；不适用写 `—`；适用但没记下写 `未跑` |
| 9 | `canary_status` | 否 | `未跑` 或 `见 SLI 6` |
| 10 | `sli6_dataset_prelock` | 否 · 继承 | 固定为 §3 的预锁。不是本记录的 `dataset_pin` |
| 11 | `sli6_code_pin` | 否 · 继承 | 占位页的周报 code pin。当前是 `未跑` |
| 12 | `sli6_pass_rate` | 否 · 继承 | 只抄 SLI 6。当前是 `未跑`。本页不计算 |
| 13 | `sli6_source` | 否 | `docs/evidence/slo-min6/canary-pin.md` |
| 14 | `doc_baseline_sha` | 否 | 本协议落盘基线，40 位。不是 `code_pin` |
| 15 | `doc_baseline_role` | 否 | 固定句：`协议落盘基线，不是 code_pin，不是 canary 执行` |
| 16 | `model_temperature` | 否 · 伴随 | 有模型调用时照实写；否则 `—` 或 `未跑`。不是针 |
| 17 | `model_seed` | 否 · 伴随 | 同上。`temperature=0` 时 seed 不构成独立样本 |
| 18 | `model_date` | 否 · 伴随 | 同上。时区 Asia/Shanghai |
| 19 | `supersedes` | 否 | 前一条 `record_id`；没有前条写 `—` |
| 20 | `layer` | 否 | `观测/Watch` |
| 21 | `notes` | 否 | 最后一行。说明针≠分。不写 pass rate |

`—` 是 U+2014 这一个字符。连字符 `-` 与全角 `－` 不是这个值。

`code_pin` 与 `dataset_pin` 不允许写 `—`。这两根要么是具体身份，要么是 `未跑`。

### 2.2 三种记录

| `record_kind` | 什么时候写 | 本票 |
|----------------|------------|------|
| `protocol_release` | 本协议或它的后继文本落盘 | 写一块。针是 `未跑` / `—`。这不是一次 canary |
| `weekly` | 一份 phase-2 周报附录成形 | 本票不另写。成形时用同一套键。没跑则两根必填针仍是 `未跑` |
| `canary_run` | 有一次冻结金标 canary 执行 | 本票不写。未跑就不造这块 |

`weekly` 与 `canary_run` 使用同一套键。不要为它们另起一套字段名。

### 2.3 可选针何时用 `—`，何时用 `未跑`

- 这条记录没有模型调用、没有单独的提示身份、没有单独的索引身份：对应键写 `—`。  
- 这条记录声明自己有该调用或该身份，但当时没记下来：写 `未跑`。  
- `—` 不是 0，不是 pass，也不是「未跑」。  

本票的 `protocol_release` 不调用模型，不单列提示，不单列索引。三根可选针都是 `—`。温度、seed、日期同样是 `—`。

伴随三项只在 `canary_run` 且确实调用了既有 LLM 金标入口时照实填写。本协议不发起这种跑，不改 `src/freshlatch/eval/`。托管端点会漂移；若将来有这种跑，限制写在该记录的 `notes`，不写进生产 score。

## 4. 未跑

没有 canary 执行时，`code_pin`、`dataset_pin`、`canary_status`、`sli6_code_pin`、`sli6_pass_rate` 都写 `未跑`。可选针按 §2.3 写 `—`。

禁止把未跑写成 0、0.0、0%、100% 或 1。禁止省略这些键。

周报附录 P4 行抄下面这句：

```text
本周未跑：code_pin=未跑，dataset_pin=未跑，canary_status=未跑。sli6_dataset_prelock 只是占位继承，不是本行的 dataset_pin，也不是成绩。pass rate 仍只在 SLI 6，并且那里同样是未跑。有针不等于 canary pass。禁止写成 0% 或 100%。
```

## 5. 变更可追溯

记录一旦写出，就不改这一块的任何一行。后发生的事写成新的 `record_id`。

新记录如果替换旧记录，`supersedes` 写旧的 `record_id`。针的值有变时，再附一块 `pin_change`。没有替换对象时，`supersedes` 写 `—`，并且不写 `pin_change`。

`pin_change` 的键，顺序固定：

| 序 | 键 | 说明 |
|----|----|------|
| 1 | `change_id` | 这一条变更的标识。不是产品版号 |
| 2 | `record_id` | 新记录的 id，不是被替换的那条 |
| 3 | `field` | `code_pin`、`dataset_pin`、`model_pin`、`prompt_pin`、`index_pin` 之一 |
| 4 | `value_from` | 旧记录上该键的值 |
| 5 | `value_to` | 新记录上该键的值 |
| 6 | `reason` | 一句。禁止写「为了过门」或「为了凑针」 |
| 7 | `recorded_at` | Asia/Shanghai |

`value_from` 必须等于旧记录该键的原文。对不上，这一条变更作废，旧记录保持原样。

一根针变了，不改变 `canary_status` 的含义，也不在变更块里写 pass rate。`canary_status`、`doc_baseline_sha`、伴随三项的变化不占用 `field`。它们只出现在新的整块记录里。

本票没有变更。不追加一块填了占位符的 `pin_change`。没有块，就是没有变更。

跑完之后不得回头改已写出的执行针。要更正，只能新记录加变更块，旧块仍可读。

## 7. 不发明营销版号主 KPI

针族是身份。身份之外，不再设一条叫「版本」的主 KPI。

下面这些键一旦出现，整块记录作废，不另计成功：

- `version`
- `release_version`
- `marketing_version`
- `product_version`
- `semver`

`record_id` 里可以含日期，用来指认记录。周报不得把这个字符串当成主指标，也不得用它代替 `code_pin`。notes 里可以有人读的日期。那一句不是 KPI。

禁止的叙事包括：「版本是最新的，所以可以发车」「版号涨了，所以 canary 过了」。

## 8. 叙事

可接受的观测叙事：

- 「P4 记录 p4-protocol-2026-10-12：code_pin 未跑，dataset_pin 未跑，canary_status 未跑」  
- 「sli6_dataset_prelock 是占位 blob 加 must_stale；它不是本记录的 dataset_pin，也不是 pass」  
- 「doc_baseline_sha 是协议落盘基线，不是 code_pin」  
- 「将来若有 canary_run，pass rate 仍只写在 SLI 6；本页 canary_status 最多写见 SLI 6」  
- 「没有 pin_change 块，就是本票没有针的变更」

不可接受的叙事：

- 「针已经写上了，所以 canary pass」  
- 「预锁 blob 在，所以 3/3」或「所以可以发车」
