## 0. 目的

同一周报窗口里，在 SLI 5 那一行之外，单独看见这一窗花了多少 token、有没有人民币账单、有没有 GPU 时间。两行用同一个窗口，读者可以并排读。cost 的数字不写进 SLI 5 的备注格。

| 要看见的 | 不在本页交付 |
|----------|----------------|
| 与 SLI 5 相同的 `window`（Asia/Shanghai） | 另开一窗把 cost 凑齐 |
| 独立行上的 `token_in` / `token_out` / `token_total`，单位 `token` | 把 token 写进 SLI 5 主行第三格 |
| 独立行上的 `api_cny`，单位 `CNY` | 用估价常数乘出本周账单 |
| 独立行上的 `gpu_s`，单位 `gpu_s` | 用 `cost.json` 的秒、字节或 `cuda: false` 填这一格 |
| 样本不足或未计时的诚实句 | 把缺样本写成 0；把 cost 下降写成放行成功 |

SLI 5 的协议仍是 [`延迟与检索回退周报.md`](延迟与检索回退周报.md)。那一页的主行只有 `e2e_p95_ms` 与 `retrieval_fallback_rate`。本页不改那一页 §1 的两字段，也不在那一页 §9 的备注格填写 token、CNY 或 gpu_s。

| 窗口 | 过去 7 个自然日，或本发布列车窗口。时区 Asia/Shanghai | 抄 SLI 5 的同一串 `window`。对不齐则本页不报数 |
| 所在表 | [`docs/evidence/slo-min6/周报骨架.md`](../evidence/slo-min6/周报骨架.md) 的 SLI 5 格 | [`docs/evidence/slo-phase2/周报附录骨架.md`](../evidence/slo-phase2/周报附录骨架.md) 的 P5 行 |

### 1.1 不占第三格

SLI 5 人读表是三列：`e2e_p95_ms`、`retrieval_fallback_rate`、备注。第三列是备注，不是 cost 的数值列。

备注里写的句子保持那一页的原句：「cost → phase-2」。机检行的 `notes` 保持「cost→phase-2；P95不单独构成放行成功」。

本页的五个字段只出现在 P5 行。把其中任何一个数写进 SLI 5 的备注格，视为本协议违例，也视为 SLI 5 那一页的违例。

### 1.2 同窗怎么并排读

周报成包时，先放 SLI 5 的两字段行，再放本页的 P5 行。两处都写出同一串 `window`。P5 行可以只读抄下 `N_request_ok` 与 `retrieval_fallback_rate` 的当周原文，便于对人。抄下来的这两格不回写 SLI 5，也不代替本页的分母。

P95 的毫秒、fallback 的比率，都不是本页的单位。本页不重新计算 P95，不重新计算 fallback rate。

## 2. 单位钉死

单位列只允许三个字符串：`token`、`CNY`、`gpu_s`。

出现 `ms`、`s`、`bytes`、`kb`、`USD`、`token_equiv`，或把「规范化」写成一个单位名，这一周的 P5 作废。作废之后不自动改写成 `token`。要保留的话，另写一周，五格按本节重填。

索引里的「token / API / GPU 或规范化单位」在本页收成下面三族。本波不设第四个混合单位。三族各自钉死，不加成一个无单位的「成本分」。

| 族 | 字段 | 单位列 | 数的形状 |
|----|------|--------|----------|
| token | `token_in` | `token` | 非负整数。对应账本里的 `prompt_tokens` |
| token | `token_out` | `token` | 非负整数。对应 `completion_tokens` |
| token | `token_total` | `token` | 非负整数。入出都是整数时等于二者之和 |
| API | `api_cny` | `CNY` | 人民币元。可以有小数。不是分，不是美元 |
| GPU | `gpu_s` | `gpu_s` | GPU 秒。可以有小数。不是利用率百分比，不是字节 |

`token_total` 是 token 族内部的和，不是把 CNY 或 gpu_s 折进来的规范化单位。三族都有数的那一周，仍然是五行，不合成一行。

### 2.1 token

生产路径上，LLM 用量的字段形状以 `src/freshlatch/llm.py` 的 `TokenUsage` 为准：`prompt_tokens`、`completion_tokens`、`total_tokens`。本页对外的列名是 `token_in`、`token_out`、`token_total`。不把 `llm.token_count.prompt` 一类平台属性名写成周报主名。

计入 `n_usage` 的，是窗口内、能够归到生产终态请求上的用量记录。终态的含义与 SLI 5 的 `N_request_ok` 相同：复验单写下了主张落档，或发前出口写下了 allow / deny。

不进入 token 三格：

- 评测 gold 跑、冻结金标 canary、`src/freshlatch/eval/` 下的 `token_usage` 快照。金标不进生产 score  
- 按字符估算并标了「估」的 embed token（`CHARS_PER_TOKEN` 那条路径）  
- SQLite 块上的 `tokens`。那是分词个数，不是 LLM 的 prompt / completion  
- `cost.json` 里的任何键  

`token_in` 与 `token_out` 都是整数时，`token_total` 必须等于二者之和。和不等于：这一周 token 三格写「分列不一致」，不报这三个数，也不手改账本把它们凑平。

账本只给出合计、没有入出拆分：`token_in` 与 `token_out` 写「未计」，`token_total` 可以写那个整数，备注写「入出未分列」。

### 2.2 API（CNY）

`api_cny` 只接受窗口内已经发生的人民币账单或供应商用量账单。单位是元。

不进入这一格：

- `src/freshlatch/eval/retrieve_typed.py` 的 `CNY_PER_MILLION_TOKENS`  
- `src/freshlatch/eval/x1_drafts/batch.py` 的 `_cost_cny` 以及任何 `input_cny_per_million` / `output_cny_per_million`  
- 标了「估」的预跑金额  
- 用 token 乘一个单价现算出来的数。没有账单，这一格写「未计」  
- 美元或其他币种的账单。本波不设汇率。备注可以写明币种，格子仍是「未计」  

无账单不是 0 元。0 元只在 `n_bill` 大于 0、并且账单金额确实为 0 时书写，备注写明：这是账单金额，不是放行成功。

### 2.3 GPU（gpu_s）

`gpu_s` 是窗口内 GPU 计量给出的秒数。单位字符串就是 `gpu_s`，避免和 `cost.json` 里的墙钟秒混用。

不进入这一格：

- `load_s`、`model_load_s`、`index_build_s`、`query_embed_s`、`embed_chunks_s`、`embed_queries_s`、`neural_load_s`  
- `weight_bytes`、`vec_bytes`、`rss_*_kb`、`hwm_kb`  
- `p95_ms`、`p95_ms_k10`、`p95_ms_k30`、`p95_retrieve_ms`、`p95_rerank_only_ms`  
- `cuda: false`。它说明那次离线跑没有 CUDA，不是本周 `gpu_s=0`  

没有 GPU 计量：写「未计」。不要为了填满这一格去读离线 JSON。

### 2.4 规范化单位（本波钉死为：不设）

三族已经各有一个单位。本波不再设一个把 token、CNY、gpu_s 折在一起的规范化单位，也不设 `token_equiv`。

「规范化」在本页的意思是：每一格的单位列只能是 §2 表里的那三个字符串之一，数和单位成对出现，缺数写「未计」或「样本不足」，不混单位。

## 3. 分母

三个分母都落在与 SLI 5 相同的窗口里。它们不是 SLI 5 的第三格。

| 分母 | 服务哪一格 | 计数 |
|------|------------|------|
| `n_usage` | token 三格 | 窗内可归到生产终态请求的 LLM 用量记录数 |
| `n_bill` | `api_cny` | 窗内人民币账单或供应商用量账单的条数 |
| `n_gpu` | `gpu_s` | 窗内 GPU 计量样本数 |

`N_request_ok` 仍只由 SLI 5 定义。本页可以只读抄它，用来核对窗口。token 能够按请求归位时，`n_usage` 与 `N_request_ok` 可以相同，也可以更小（有终态但没有用量记录的请求不进 `n_usage`）。禁止用 `n_usage` 回填 `N_request_ok`，也禁止用 `N_request_ok` 直接当成 token 合计。

用量只有进程级合计、拆不开到请求：允许报窗口合计，备注写「窗口合计，未按请求拆开」。此时 `n_usage` 是快照条数，不是 `N_request_ok`。

本页不新写聚合脚本，不改 `src/`，不改 `TokenUsage` 的字段，不改生产放行谓词。当周没有可核对的生产用量记录时，走 §4，不从评测报告或 `cost.json` 借数。

## 4. 样本不足与未计

| 情形 | token 三格 | `api_cny` | `gpu_s` |
|------|------------|-----------|---------|
| 窗口不可划定，或与 SLI 5 的 `window` 对不齐 | 样本不足（对不齐时写「窗口不一致」） | 同左 | 同左 |
| 窗口可划定，`N_request_ok=0` | 样本不足 | 无账单则未计；有账单流且 `n_bill=0` 则样本不足 | 无计量则未计；有计量且 `n_gpu=0` 则样本不足 |
| 窗口可划定，`N_request_ok>0`，请求上没有 token 账 | 未计 | 按上一行 | 按上一行 |
| 入出之和不等于合计 | 分列不一致 | 账单照实 | 计量照实 |
| 该族有账且分母大于 0 | 整数 `token` | 元 | `gpu_s` |

任何一格都不许用 0、0.0、0 token、0 CNY、0 gpu_s 或 0% 代替「样本不足」或「未计」。

窗口不可划定，或 token 因分母为 0 而不足时，整句抄下面这一段。尖括号换成当周窗口；窗口不可划定则写「窗口不可划定」。

```text
本周样本不足：窗口与 SLI 5 相同（<起止 · Asia/Shanghai>），或窗口不可划定。成功完成请求 N_request_ok=0（或窗口不可划定）。token_in、token_out、token_total 写「样本不足」。api_cny 与 gpu_s 无账单、无 GPU 计量时写「未计」；窗口不可划定时这三族都写「样本不足」。不写成 0 token、0 CNY 或 0 gpu_s。不抄 cost.json。不把本行写入 SLI 5 的备注格。本行不是放行成功。
```

token 有读数、账单和 GPU 都没有计量时，整句抄：

```text
token_in、token_out、token_total 有读数，单位是 token。api_cny=未计，gpu_s=未计。未计不是 0。token 下降不构成放行成功。本行与 SLI 5 同窗，不进入 SLI 5 第三格。
```

窗口可划定、成功完成请求大于 0，但三族都没有账时，整句抄：

```text
窗口与 SLI 5 相同（<起止 · Asia/Shanghai>）。N_request_ok 大于 0，但请求上没有 token 账，也没有人民币账单，也没有 GPU 计量。token_in、token_out、token_total、api_cny、gpu_s 都写「未计」。未计不是 0。不抄 cost.json。不把本行写入 SLI 5 的备注格。本行不是放行成功。
```

本页当前没有生产周报账本。样例字段因此不预填整数、不预填金额、不预填 gpu_s。见 [`docs/evidence/slo-phase2/P5-样例字段.md`](../evidence/slo-phase2/P5-样例字段.md)。

## 5. cost 降与放行成功

本行是观测 / Watch。生产放行是否成立，仍看既有硬闸（无证拒拦、未确认不出门、自红转绿、无 T1 绿灯）。那些谓词的语义在 ADR-0042，本页不改 `src/` 闸。

同时成立的读法：

- P5 五行与 SLI 5 的两字段行使用同一个 `window`，分属两张表。  
- `token_total`、`api_cny` 或 `gpu_s` 低于上一窗，只说明该单位的计数变少。  
- 变少不构成放行成功，不把旁边的 P95 读成过线，也不把 fallback 读成健康。  
- SLI 5 写了「全在 fallback」时，本页的 cost 无论多低，仍按「全在 fallback」旁边的成本读，不按放行成功读。  
- 本页不把某一 token 数、某一元、某一 gpu_s 写进 [`生产补丁放行SLO.md`](生产补丁放行SLO.md) §4 的预注册门槛。

事后补一条「cost 低于 X 即通过」来凑绿 = 本页作废，须另决议。

## 8. 叙事

可接受的观测叙事：

- 「同一窗口：SLI 5 仍是 e2e_p95_ms 与 retrieval_fallback_rate；P5 另起一行写 token / CNY / gpu_s」  
- 「N_request_ok=0，token 三格写样本不足，不报 0 token」  
- 「有终态、没有 token 账，token 写未计；api_cny 与 gpu_s 无计量也写未计。未计不是 0」  
- 「cost.json 的秒和 p95_ms 留在原页，不进本周 P5」  
- 「token_total 比上周少。这不是放行成功」

不可接受的叙事：

- 「token 下降了，所以这趟放行成功」  
- 「P95 好看，再把 cost 填进同一行第三格」
