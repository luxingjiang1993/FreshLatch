# ADR-0021: Batch 4（δ）合成数据释放协议草稿 ≠ 已释放

- **状态**: Accepted
- **日期**: 2026-09-23
- **相关**: `docs/research/C4-合成数据释放协议草稿.md`、`docs/research/δ-合成数据释放协议是否本批出草稿设计评估.md`、ADR-0019/0020、地图 #96 / 工单 #105

## 背景

Batch 4 需要合成数据释放的文档纪律，供作品集/评测引用，但易把「写了协议」误读成「数据集已对外可用」，或把未建的 backlog 包写进释放范围造成多垂类假话。许可在未审前钉死也有锁错风险。

三条件齐备：

- **难反转**: 「已释放」门闩与范围一旦绑对外话术，事后放宽等于污染引用链。
- **反直觉**: 仓内有 C4 卡 / 数据进 main 常被当成已开源。
- **真实取舍**: 先锁草稿 vs 本批真发布；许可占位 vs 提前钉死 SPDX。

## 决策

1. **本批落盘** `docs/research/C4-合成数据释放协议草稿.md` 为释放规矩单一真相（草稿层）。
2. **默认未释放**。「已释放」须同时：§3 填入 SPDX；人在工单/PR 显式批准并给语义化版本号；分发物与卡一致。推进 `main` ≠ 已释放。
3. **范围**: 第一课题合成包 + P1 QuoteTTL 薄（同一骨架）。δ backlog 不进本卡释放范围；不得宣称多垂类数据集已发布。
4. **许可**: 草稿阶段占位、未授权再分发；对外释放前必须选定 SPDX。
5. **本 ADR 不授权** wayfinder 会话内 `/implement`，不授权本批执行对外发布。

## 后果

- Batch 4 `/to-spec` 可引用 C4 卡作文档交付，不得把「卡已存在」写成验收「数据已公开」。
- 真释放另开工单，按 C4 §6 门闩执行。

## 替代方案（被否决）

- **仅 RESEARCH/HOLD 指针**: δ 缺文档纪律，事后补协议难辩。
- **本批直接对外发布**: 许可/脱敏未审，越权票面验收层。
- **push main 即释放**: 误触发。
- **范围含 backlog**: 多垂类升格。
