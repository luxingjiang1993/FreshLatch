# 复验单 UI 技术形态:FastAPI+HTML,弃 Streamlit

复验单(W4 生死闸的交互核心)采用 FastAPI 服务端 + 手写 HTML/JS 双栏页面,弃 Streamlit 报告式方案。

**为什么**:决策标准是点回原文的自由度与 HumanLatch 的对接形态,不是开发速度。W4 生死闸要求点主张 → 点回 T0/T1 原文段落并高亮,Streamlit 只有 markdown 片段级高亮;HumanLatch 要暴露作废/续命审批端点,FastAPI 的 `/api/latch` 形态与 `gates/human_latch.py` 模块天然对齐,Streamlit 的 st.button rerun 模型会把审批逻辑漏进 UI 层。Streamlit 赢在 W1 出活快,是真实但被否决的取舍。双糙样对比存档于分支 `prototype/ui-双糙样`,对应工单 [#4](https://github.com/luxingjiang1993/FreshLatch/issues/4)。

**后果**:`src/freshlatch/ui/` 薄壳按 FastAPI 实现;主界面红线(无聊天框、主按钮「开始复验」、SYNTHETIC 标注)已体现在糙样中,W1 直接照搬布局。
