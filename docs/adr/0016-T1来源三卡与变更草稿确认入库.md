# ADR-0016: T1 来源三卡与变更草稿确认入库

- **状态**: Accepted
- **日期**: 2026-09-22
- **相关**: grill-with-docs Batch 0+1、docs/research/C1-Batch0-1预登记卡.md、CONTEXT「T1 来源三卡」

## 背景

职人痛点是「T1 从哪来」。若默认假设语料已在库，或粘贴变更立刻进检索，会把未确认文本当成 ground truth，破坏 fail-closed。满足 ADR 三条件：难反转（绑 T1 Clarity / 续命锚定）、反直觉（「粘贴即入库」更快）、真取舍（激活摩擦 vs 证据诚实）。

## 决策

复验前 UI 提供且仅提供三种合法 T1 来源（T1 来源三卡）：

1. **上传 T1 语料包** → ingest 后可检索  
2. **粘贴变更要点** → 先成**草稿**，人点「确认入库」后才 ingest；未确认不得被 retrieve / 不得作续命证据  
3. **内置合成评测包** → demo/评测用，界面标明 synthetic  

未选定合法来源不得假装已有最新事实。联网插座若存在则默认关，不进 Batch 1 主路径。

## 后果

- DEM-2（T1 Clarity）以「确认入库」为硬条件。
- 与规则闸「无 T1 不得 fresh」一致；不引入自动盯梢叙事。

## 替代方案（被否决）

- **粘贴立即 ingest**：未确认文本进入 ground truth。
- **粘贴只当 UI 备忘、永不入库**：职人无法完成「可锚定续命」作业。
- **默认联网拉新闻**：超出 Batch 1；主链 fail-closed 叙事被稀释。
