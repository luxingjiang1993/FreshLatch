# ADR-0027: V1 顾问报告垂直、包结论新层与薄 URL 白名单

- **状态**: Accepted（2026-10-18 修订：I-09 四档词表，决议 #688 / 票 #694，supersede 原三档「禁止第四套」→ 封闭四档）
- **日期**: 2026-09-29
- **相关**: `docs/_archive/2026-10/research/V1-发前闭环垂直与包结论设计评估.md`、`docs/grill-prep.md` §2d、roadmap Phase V1、ADR-0016（T1 三卡；本 ADR 增量薄 URL）、决议 #688（I-09）、#694（四档实装）

## 背景

V1 要交付可演示发前路径（入库→Gate→包结论→人审→两屏），但垂直、包级 disposition、T1 是否接 URL 未钉死时，易并行多垂直、发明第四套状态词，或做成开放爬虫/采编平台。

三条件齐备：难反转（垂直与映射一经 demo/论文引用）；反直觉（有对比臂仍默认 BM25 之外，还有「全 fresh 无人审也可发」）；真取舍（顾问真实材料 vs 仅合成；薄 URL vs 只粘贴；包结论新层 vs 复用主张 status）。

## 决策

1. **单一垂直 = 顾问报告**。样例主包：McKinsey State of AI（T0≈2025-03 rewiring 波 → T1≈2025-11 agents 波）。仓内只存主张清单、摘录块、来源 URL/日期；**禁止**整本 PDF 当开源数据集再分发。thesis-1 / QuoteTTL 可留回归，**不算**第二垂直。
2. **两屏 IA**：新建「发前列表」（标题/来源、包结论、更新时间、Run 状态）；「Run 详情」= 现有复验单 **增量**加包结论条（不作第三套详情 UI）。
3. **包结论（disposition）为新聚合层**，词表固定为 **封闭四档**：**可发（全部仍成立）/ 可发（含作废）/ 需补丁 / 勿发**（2026-10-18 修订，I-09 拍板；原三档「可发 / 需补丁 / 勿发」+「禁止第四套」由本四档 closed set 取代）；底层主张态 `fresh`/`stale`/`unknown`/`void` 与人审 `discard`/`renew` **不改名**。聚合优先级：
   - 任一条未收口 `stale`（未 discard/renew）→ **勿发**（字面绝对保留）
   - 无未收口 stale，但有 `unknown`/缺口 → **需补丁**（闸门语义不变）
   - 否则按有无作废拆两档可发：包内存在任一作废（voided / `discard` / `status==void`）→ **可发（含作废）**（只因 voided 拆档；renew 续命不算作废）；无作废 → **可发（全部仍成立）**（全 fresh 无人审、或红灯均 renew 收口）
   - 发前钩子（ADR-0031）：两档「可发」导出同权放行；「需补丁」须显式 ack 且强制页眉；「勿发」deny
4. **T1 入口**：保留 ADR-0016 三卡；V1 增量 **薄 URL（c′）**：仅白名单域名 **`www.mckinsey.com`** 单条抓取→落盘再验。失败四态（非白名单 / 超时或网络错 / 非文本或空正文 / 落盘前校验失败）→ **不入库**，可回落粘贴确认。不做开放爬虫；PDF URL 自动解析另票。
5. **`patch_events`**：自 V1 起 JSONL 落 `data/patch_events/`；字段至少含 roadmap 所列 + `ts`/`actor`。C vs T **只后台/脚本**记账，不进正式发前 UX。
6. **V1 不做薄对话**；对话不得改正式 disposition（厚对话改裁决仍 Out）。

## 后果

- to-spec / 实现须引用本 ADR；UI 禁止第五套近义状态词（原「禁止第四套」随四档拍板升级为「封闭四档」）。
- 联网抓取仅白名单域；扩大域名或 PDF 自动入库须另决议。
- Evidence-bound 补丁 UX 属 V1.5，本 ADR 不授权实装。
- 作废拆档（含作废 vs 全部仍成立）只改报告级出口词，不改主张级 `void`/`discard` 词表与 HumanLatch 动词。

## 替代方案（被否决）

- 仅用合成 thesis-1 对外冒充已选垂直（用户要求顶咨级真实材料）。
- 包结论复用主张 status 词或另造「通过/待改/拦截」等第四套正式词。
- 全 fresh 强制人签才可发（V1 过重；可后置）。
- 开放多域名 URL / 多源采编平台（d）。
- C/T 对照进发前 UI；V1 做薄对话改裁决。
