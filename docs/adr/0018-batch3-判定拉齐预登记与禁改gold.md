# ADR-0018: Batch 3（γ）判定拉齐预登记卡为判据单一真相

- **状态**: Accepted
- **日期**: 2026-09-23
- **相关**: ADR-0009–0012、`docs/research/C3-判定拉齐预登记卡.md`、`docs/research/γ-判定拉齐预登记与禁改gold设计评估.md`、地图 #96 / 工单 #100

## 背景

Batch 3 将做 Auditor/维度加固。若不先锁通过线、失败态与「禁改 gold 凑绿」的操作定义，实现过程中极易用改金标或放宽闸换绿灯，事后再改判据（HARKing）。地图已禁「改 gold 凑绿」，但缺少可审计的操作化条款与单一真相文件。

三条件齐备：

- **难反转**: 判据一旦绑验收，事后改卡或偷偷改 must_* 会使本批测量作废。
- **反直觉**: 「改一条 gold 就能绿」看起来便宜且常被当成无害。
- **真实取舍**: 交付速度 vs 测量可信；预登记摩擦 vs 可引用结论。

## 决策

1. **`docs/research/C3-判定拉齐预登记卡.md` 是 Batch 3（γ）判据的单一真相**（范围、分层、通过线 γ-INV/SMOKE、失败态、采样口径、禁改 gold 四条款）。
2. **改本卡判据或为凑 γ 通过而改 `gold.json` must_***：须另开工单，并声明 Batch 3 预登记作废且重登；静默修改 = 本批验收作废。
3. **消融/多 seed 规格与实跑、假绿仪器分条措辞**不在本 ADR 展开（分属决策票 #101 / #102）。
4. **本 ADR 不授权** wayfinder 会话内 `/implement`，也不授权把 γ-SMOKE 升格为统计证明或「假绿已根治」。

## 后果

- Batch 3 `/to-spec` 必须引用本卡与本 ADR。
- C1 预登记卡范围不变；γ 不塞进 C1。
- CONTEXT 仅保留指针，不复制通过线表。

## 替代方案（被否决）

- **无独立卡、实现时再写通过线**: 必然 HARKing。
- **软性「尽量别改 gold」**: 不可审计。
- **把 γ 判据写入 C1 卡**: 污染 Batch 0+1 已锁范围。
- **本卡重审假绿对照是否成立**: 越权；分条见 #102。
