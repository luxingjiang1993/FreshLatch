# 仓库目录结构与模块划分

FreshLatch 工程采用 src layout:`src/freshlatch/` 下按角色分模块(`roles/lead|critic|auditor|forensic`,一角色一文件),`gates/` 独立成模块承载规则闸与 HumanLatch 状态机,角色禁止事项靠「工具白名单」在代码结构上表达——绿灯唯一出口是 `gates/rule_gate.py` 纯函数,Auditor 物理上拿不到放行 API。

**为什么**:角色诚实表(切片 §7)的禁止事项(Critic 不得强化原主张、Auditor 不得拥有放行权、Agent 不得把红灯改回绿灯)必须能在代码结构上被看见,而不是藏在提示词里。被否方案是「引擎 + 角色配置」:角色边界只存在于配置中时,禁止事项可以被一次配置改动悄悄绕过。

**取舍**:`store/` 与 `ui/` 在 #5(Chroma vs SQLite)、#4(FastAPI vs Streamlit)拍板前先定抽象——`store/` 只放 RetrievalStore 接口 + 内存假实现,`ui/` 是薄壳、核心包零 Web 依赖。护栏参数(Lead 18 / Critic 8 / Auditor 6 / 检索 24)集中为 `Guardrails` dataclass 由 Runner 注入,评测 harness 可代码级覆盖,保证金标可复现。

新目录全部建在蓝海项目5 仓内,不改前四轮仓库。对应工单 [#3](https://github.com/luxingjiang1993/FreshLatch/issues/3)。
