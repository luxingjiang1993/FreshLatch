## 1. 问题 + 前置约束

Batch 4（δ）在「卖作废」主叙事不变前提下，拍板**第二课题选题**：选题判据、与第一课题同构的最小可演示故事、明确不选哪些题——避免第二课题变成换皮搜索、自动裁决、或另开产品线。

| 前置 | 来源 | 锁死作用 |
|---|---|---|
| 品类：复验闩 / 卖作废；不自动商业裁决；不接 Mem0 | 三曲线设计 §0；地图 Notes | 选题不得改主叙事 |
| δ = 第二课题**模板**（G7 / Second-thesis Port） | 三曲线蓝图方案 δ | 证 Port，非十垂类验证 |
| 第一课题 | `data/eval/gold.json`：东南亚 SMB AI 客服市场进入 | 第二课题须题材可区分 |
| 12 周不做 QuoteTTL/CommitWatch/LivingBrief **产品** | W12 / 立项切片 | 本批允许的是课题包，不是独立产品表面 |
| 不硬等 Batch 2/3 | 票面 | δ 决策可先行 |
| OUT | 真 SSO/连接器；十个垂类；改主课题闸语义；论文主会真实对照 | 本票继承 |

**词表钉清（domain-modeling）**:

- **第二课题** ≠ 另开 QuoteTTL 等产品线；= FreshLatch 内第二份同构合成课题包。
- **监管口径课题** ≠ 再加一个 `regulatory_stance` 枚举；= 以监管变更为主叙事的整包故事（第一课题里监管已是维度之一，如 c2）。
- **垂类课题包** = 换故事/语料/gold，闸与旅程不动；**另一条产品线** = 新入口/新工具面/新主按钮。

## 3. 逐路线评估

| 维度 | 拍板 | 被否理由 |
|---|---|---|
| 形态 A | ✅ | B 扭成第二产品立项，与卖作废/OUT 冲突；C 过不了过拟合攻击 |
| 判据 A+B+C | ✅ | D 把「垂直」绑成「可改工具面」，伪命题；垂直可以开发，但判据不能是变现到改闸 |
| 扩池 C | ✅ | 硅谷惯例：候选最大化、交付最小化；扩大池 ≠ 本批交付多垂类 |
| 本批唯一 + backlog | ✅ | 并行多包踩 OUT「十个垂类」且 Port 不可测；无序浪费已扩池 |
| 唯一 = P1 | ✅ | 与保质期隐喻最紧；票面点名；claim 级不逼新工具面。P3 为明确第二名 |
| P10/P11 本图出池 | ✅ | 面试/工程向易抢主叙事或变观测台；Mem0 误读。登记为**未来另图备选**，非本图 δ 交付 |

**Anthropic 清单命中与修正**:

1. **演示≠测量**: 「P1 跑通」≠「多垂类已验证」；backlog 项不得进「已 Port」话术。
2. **单次随机判生死**: 本票不涉 LLM 采样；下游 gold 实跑仍分层（#104/#105 / to-spec）。
3. **默认≠规格**: 最小故事骨架写入本评估；实现不得默默加字段引擎。
4. **词表上下文无关**: Port 通过线操作定义与 backlog 表在本评估；CONTEXT 只留产品可见词。
5. **预登记**: 选题与不选清单先于语料/实现锁死；事后改唯一选题 = 本批迁移预锁作废重登。
6. **复现两层**: 闸语义不改为确定性层前提；#104 锁零改代码假设。
7. **ADR 三条件**: 课题包≠产品线、本批唯一 Port、backlog 不升格——难反转+反直觉+真取舍 → ADR-0019。

**被否的原推荐路径**: 「变现优先选完整 QuoteTTL 产品」「本批把入池全做完」——前者改品类，后者毁 Port 测量与 OUT。

## 4. 拍板 + 逐项子决策

1. **形态**: FreshLatch 内第二份同构合成课题包（非独立产品、非假换皮）。
2. **判据**: 同构最小故事（≥1 must_stale 且作废后 Stay-Red、≥1 must_fresh、≥1 must_unknown；T1 可点回）+ 题材可区分 + 不改主课题闸/词表语义。
3. **入池（扩池 C）**: P1, P2, P3, P4, P5, P8, P9。  
   **弱备胎（Port 证明力弱）**: P6 渠道分成、P7 成本模型刷新（第一课题已覆盖近邻）。  
   **本图出池 / 未来另图备选**: P10、P11（见 §4.3）。
4. **本批唯一进平行 gold**: **P1 QuoteTTL 薄切片**。
5. **δ backlog 序**（Port 通过后才开动；不进本批「已 Port」话术）:  
   **P3 → P5 → P2 → P8 → P4 → P9**
6. **P1 最小可演示故事骨架**（迁移预锁，非实现规格）:
   - 问题句取向：外贸/SaaS「9 月 1 日供应商报价是否仍可在 9 月 18 日转报客户？」
   - 主张 = claim 级（金额有效性、交期、运费/附加、报价有效期等）
   - **禁止本批**: `reverify_field`、含税守恒引擎、ERP、真连接器、自动对外通知
   - 金标最小桶：≥1 must_stale / must_fresh / must_unknown；因果链锚 T1；`must_quarantine` 可空（不抢 R1）
   - 戏剧：T1 更新函改交期/运费 → 人作废 → Stay-Red；至少一条仍成立；一条无覆盖 → unknown
   - UI：与第一课题同一旅程；配置/数据切换
7. **本会话不** `/to-spec`、不 `/implement`；不改第一课题 `gold.json` 凑第二课题。

## 6. 面试讲法

**Q: 为什么第二课题是报价，不是直接做 QuoteTTL 产品？**  
A: 要证的是 FreshLatch rails 能换题（Port），不是再立一条报价保质期产品线。claim 级薄切片过 Port；字段引擎/守恒/ERP 是产品表面，W12 已禁、本图 OUT。

**Q: 候选池写了七八个，是不是已经多垂类验证了？**  
A: 没有。池是选题用的；本批唯一 P1 进 gold。backlog 是排队，口述成「已支持多垂类」= 演示升格测量，不合格。

**Q: 为什么不把监管口径当第一第二课题？**  
A: 第一课题已有 `regulatory_stance` 维度（c2）。整包监管主叙事可以进 backlog（P2），但须换行业故事才过「题材可区分」；不宜当第一次 Port（易被说成换皮）。

**Q: P10/P11 都丢了吗？**  
A: 本图 Destination 不含；登记在评估 §5 与地图 Out of scope「未来另图备选」。要做时另开 wayfinder 图，不要塞进 Batch 4 假装 Port 更大。

**Q: 改闸让第二课题更好跑可以吗？**  
A: 不可以还叫迁移。改闸 = 新系统，须重预登记（#104 将钉零改代码假设）。
