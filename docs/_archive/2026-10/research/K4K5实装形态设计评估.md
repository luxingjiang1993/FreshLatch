## §候选路线(每个决策维度的全部候选,含被否项)

### D1 K4 导出入口

- **(a)** 只做 CLI。(拍板)
- **(b)** 只做 UI 按钮/下载。
- **(c)** 双入口共用导出函数。

### D2 K4 对账真源

- **(α)** 核心包共享投影(`Claim` ⊕ 审计表);UI/导出/对账单测同吃。(拍板)
- **(β)** 导出只读 UI 序列化路径。
- **(γ)** 导出只读 SQLite(会丢未落库机器 status)。

### D3 K5 累计桶

- **(1)** `LLMClient` 单桶全局 prompt/completion。(拍板)
- **(2)** 分角色桶 + 合计。
- **(3)** 只记 Lead。

### D4 K5-2 是否进本图 Destination

- **(i)** 本图含 K5-1 + K5-2。
- **(ii)** 本图只做 K5-1;K5-2 进雾/另票。(拍板)

### D5 Markdown 字段档

- **(A)** 对齐 UI 卡片投影(含 voided、evidence、reason、人审/重跑时间线);写 `voided`,不伪造 `status=void`。(拍板)
- **(B)** 更瘦:无完整时间线。
- **(C)** 更肥:加 dissent / validity_basis / 轨迹摘要。

### D6 CLI 挂载点

- **(1)** `python -m freshlatch.export sheet …`(与 eval 评测报告分离)。(拍板)
- **(2)** 挂进 `freshlatch.eval` 新子命令。
- **(3)** 仅库函数、无真实 CLI。

### D7 K5 报告用量块

- **(α)** 顶层 `token_usage: {prompt_tokens, completion_tokens, total_tokens}` + `per_run[i].token_usage`。(拍板)
- **(β)** 只挂 `per_run`,无顶层。
- **(γ)** 塞进 `decoding` 对象。

### D8 pytest 边界

- **(i)** 夹具对账 + mock usage;禁网;不改 gold、不跑金标实网。(拍板)
- **(ii)** K5 要求真网金标落盘进 git 才过。
- **(iii)** 抽样人工看 MD。

### D9 CLI 取数面

- **(a)** 读复验单快照 JSON(claims + store 路径)再投影导出。(拍板)
- **(b)** CLI 自己跑复验再导出。
- **(c)** 仅库函数示意、无入参 CLI。

### D10 共享投影落点

- **(1)** 核心包(如 `freshlatch/sheet.py`);UI `_claim_to_dict` 对齐/委托。(拍板)
- **(2)** 投影留 `ui/`,export 依赖 UI。
- **(3)** export 内复制一份,与 UI 漂移自负。

### D11 K5 写入范围

- **(α)** 只保 `run_gold` 金标 raw(+ md 若渲染用量节);control 非本期必过。(拍板)
- **(β)** gold 与 control 都写。
- **(γ)** 各调用方自行决定。

### D12 ADR / 词表

- **(ρ)** 新开 ADR 锁导出/token 形态。
- **(σ)** 不新开 ADR;评估 + 决议评论;词表不加过程词。(拍板)

## §拍板 + 逐项子决策

**拍板:D1-(a) + D2-(α) + D3-(1) + D4-(ii) + D5-(A) + D6-(1) + D7-(α) + D8-(i) + D9-(a) + D10-(1) + D11-(α) + D12-(σ)。**

1. **K4 入口**:仅 CLI `python -m freshlatch.export sheet …`;读复验单快照 JSON(claims + store 路径),不现场跑复验。
2. **真源**:核心包共享投影;`ui` `_claim_to_dict` 对齐/委托;MD 字段对齐 UI 卡片;导出写 `voided`,不伪造 `status=void`。
3. **K5**:`LLMClient` 单桶累加 prompt/completion;金标 raw 顶层 + `per_run[i]` 的 `token_usage`;只保 `run_gold`;control 非必过。
4. **K5-2**:不进本图 Destination;雾区另票。
5. **pytest**:夹具对账 + mock usage;禁网;不改闸/gold/K6-4。
6. **词表 / ADR**:不加过程词;不新开 ADR。
7. **本工单**:只决议,不写产品代码(实装交 #63/#64)。

**给 #63 的依据句**:

> K4:CLI `freshlatch.export sheet` 读快照 JSON;核心包共享投影对齐 UI 卡片字段(含 voided 与人审/重跑时间线);对账单测吃同一投影;禁网夹具;不改闸/gold/K6-4。

## §面试讲法(grilling 预案)

**Q:为什么不做 UI 导出按钮?**
A:规格是「命令或 UI」。CLI + 共享投影就能过 K4-1/K4-2 机器对账;UI 后加只是调同一函数。本期双入口是范围膨胀。

**Q:库里没有 claims 表,导出对的是什么账?**
A:真源是内存 `Claim` 加上 SQLite 审计表——和复验单 UI 同一投影。快照 JSON 把内存态显式化,单测不触网。

**Q:为什么作废不写成 status=void?**
A:产品词表和代码都是 `voided` 与机器 status 并存;HumanLatch discard 不改机器 status。导出伪造 void 会让对账通过、演示撒谎。

**Q:token 为什么不分 Lead/Critic/Auditor?**
A:K5-1 要的是遥测块里的 prompt/completion 合计。分角色是增强,要改调用面;demo 层单桶先绿。

**Q:K5-2 成本注记为什么不做?**
A:施工图 Destination 是「token 入报告」。K5-2 是写进 spec 06 的文档注记,不挡 pytest;进雾另票,避免施工图偷换成文档工程。

**Q:为什么不要求金标实网跑一发把 usage 落进 git?**
A:那是把 demo 单测绿绑到托管端点漂移上(清单 #1/#2)。过线 = 夹具 + mock;真网落盘若要,另票,不进本形态必过线。
