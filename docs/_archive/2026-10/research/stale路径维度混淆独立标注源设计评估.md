## §1 问题与前置约束

**问题**:#26 行为验收通过线①未达成(c5/c6 合计 1/6 < 4/6),#25 预登记锁死判别触发:

**#26 读数 + 代码勘察给出的七个硬事实**(均可在仓内复核):

1. **双层语义同错成立**:Auditor 在场钩子全程触发(5/5 auto:true),但对 c5 维度混淆
   反证 `dimension_match=true` 与 Lead 同错;闸不变量 7 零触发;dissent 全程 null。
   第二判与第一判共享盲区(同端点同源),丙′机制对该失效形态无效——锁死判别的事实基础。
2. **签发侧零维度**:主张签发 = 手工编辑 `data/t0_docket.json`(每条仅
   `claim_id/statement/t0_evidence_ids` 三字段)+ `load_docket()` 只读导入
   (runner.py:85-95);`Claim` dataclass(models.py:12-26)与 SQLite 均无维度字段。
   「签发时登记维度」是**新增签发字段**,无存量可复用。
3. **维度知识三处不同构**:focus 六枚举(tools.py:9-16,仅存于 spawn_critic 调用边界)、
   金标 §2.6 表的维度列(c6/c7 用「干扰」标签而非枚举值)、Auditor 的 dimension_match
   布尔(自由语义,无维度词表)。要做机械跨检,登记字段必须锚定 focus 六枚举这一
   唯一封闭词表。
4. **无 migration 框架**:仓内惯例 = 直接改 SCHEMA 字符串 + `IF NOT EXISTS` 幂等
   (rerun_log 先例);唯一版本化先例是 Auditor 证据包
   `EVIDENCE_PACKET_SCHEMA_VERSION` 常量(纯登记不演算)。
5. **金标不记 focus**(spec 02 §2.6 显式纪律)——登记维度是产品签发 schema
   (住 docket),gold.json 保持无维度,两者不冲突;验收时闸的比对锚来自 docket
   登记值(c5 = 成本模型,依据规格 §2.6),不碰金标。
6. **error_code 词表 8 值**(`DIMENSION_MISMATCH` 已被不变量 7 占用;
   rule_gate.py:85-98 顺序清单)。机械跨检要归因可读,不能复用旧值。
7. **stale 分支闸序现状**:不变量 5 → 6(元陈述闸)→ Auditor 缺席兜底 → 7(维度异议);
   `arbitrate_stale_mark`(rule_gate.py:50-79)已定义 unknown + 异议记录的仲裁形态,
   新不变量路由可整段复用。

**前置约束(不得触碰)**:

1. **判据锁定**:checklist.md 判分口径、W4↔W12 同尺。
2. **#26 结论不翻案**:双层语义同错(同端点同源)是已锁事实;丙′机制本身不被否定,

4. **Auditor 无放行权**(词表):任何机制不得让 Auditor 或闸把任何状态改绿;

5. **#25 前置约束 5 / #19 §4.4**:独立标注源机器跨检 = 机器闸③的诚实形态复活,

6. **#25 §4.6-6 预登记**:本单是锁死判别的执行,判据本体(c5/c6 拦截口径、

乙(机器闸③)被否的机制死因是「让模型自报与主张的维度关系,锚在模型自己身上,
『错误的维度一致申明』原样变身『错误的维度字段』」。本次落地的四差异,
缺一即是乙重演:①**比对锚外部化**——登记维度来自签发时的人工结构标注,不经任何
复验模型之手;②**问法换锚**——字段问的是「反证自身攻击的维度」,模型声明的是
可独立验证的证据属性,不是不可验证的「关系」;③**锚对模型不可见**(B1)——

不等于独立标注源这一层生效,当场验证而不是讲故事。

共六项推荐,清单自挑**无否决项**;两处诚实降级已合入拍板——B1 的「不可见」只防
「照锚填字段」一种对策,不防「故意填错维度值」,该残余盲区进 §4 子决策 6 与验收
归因读数;Q3 增补「机械层零触发不算赢」判别,防「bundle 绿 = 机制生效」假结论
(清单 #1)。#25 登记的两项原推荐被否(复活③、Auditor 仅在场)不重复登记。

## §4 拍板 + 逐项子决策

**拍板:独立标注源机器跨检落地——签发时登记维度(docket 新字段,人工标注,六枚举
封闭,对复验模型不可见)+ 反证强制携带维度字段(mark_stale 必填,问法 = 反证自身
维度)+ 规则闸不变量 8(登记维度 ≠ 反证自标维度 → 机械打回 unknown + 机械比对
异议记录,error_code `DIMENSION_CROSSCHECK_MISMATCH`)。ADR-0010 并轨:不变量 7
保留兜底未登记主张。记 ADR-0011(#25 前置约束 5 / #19 §4.4 pre-registered 条款的
当场执行)。**

逐项子决策:

1. **签发维度登记(C1)**:t0_docket.json 每条增 `dimension` 字段,封闭枚举同
   `FOCUS_DIMENSIONS`;`Claim` dataclass 与 `load_docket()` 同步增字段,
   `load_docket` 对非法值硬拒绝(签发即校验,坏卷宗不进系统)。**人工编辑卷宗 =
   人工标注**,这正是「独立标注源」的实体形态——标注者是签发人,不经复验模型之手。
   schema 版本化:照仓内惯例直接改 + 本评估登记,不造迁移框架(承载)。
2. **反证维度字段(D1)**:mark_stale 两侧镜像(Critic critic.py:157-174 /
   Lead lead.py:212-235)同步增必填参数 `dimension`,六枚举硬校验**整段复刻 focus
   形态**(lead.py:293-305:非法值整 call 拒绝、回列词表、重试计步)。字段语义 =
   「本反证自身攻击的维度」,Critic 侧中文映射复用 `FOCUS_ZH`(critic.py:22-25)。
3. **闸不变量 8(E1)**:位置 = stale 分支内不变量 6 之后、Auditor 依赖项之前
   (与 6 同属「反证包质量」机械预检);比对 = 纯字符串(`claim.dimension ≠
   stale_dimension` → 打回);**两维任一缺失 → 跳过 8 回落不变量 7**(fail-soft
   回落到丙′,不是裸奔);打回路由整段复用 `arbitrate_stale_mark` 形态——
   unknown + 异议记录,但异议内容 = **机械比对事实**(登记维度 X vs 反证自标
   维度 Y,纯结构、零模型意见),随黄卡进 HumanLatch;fresh×stale 平行路径
   (runner.py:190-199)走同一闸自动覆盖。GateDecision 增两字段(登记维度、
   反证维度);Auditor EvidencePacket **不动**(fallback 走语义核对,不需要机械字段)。
4. **error_code**:新增 `DIMENSION_CROSSCHECK_MISMATCH`,与 `DIMENSION_MISMATCH`
   并存——归因登记要求两来源可读可区分(E2 被否)。
5. **ADR-0010 并轨(A1)**:不变量 7 全条款保留,职责收窄为「未登记主张的维度
   防线」;#26 实装的 Auditor 维度核对一行不拆。同错论据的合法推论是「不当唯一
   防线」,不是「拆除」。
6. **行为验收 pre-registration(判定人触发,事后改 = 作废)**:
   - 样本:c1/c2/c3/c7(must_stale 4 条)+ c5/c6(定向)+ c13/c14(干扰项附表,
     读数登记);must_unknown 不跑(同 #26 口径);
   - 采样:n=3、temp=0、qwen-flash 显式锁定、版本当场登记;n=3 按 #19 的 1/3
     单跑翻转基率框定为冒烟读数,不报方差(清单 #2/#3 继承);
   - 通过线①(拦截线):c5/c6 合计 6 遍 ≥4 遍非 stale 落档(#25 §4.6-6 口径继承);
   - 通过线②(回归守线):c1/c2/c3/c7 各 3/3 落 stale(真反证不得被跨检误伤);
   - 通过线③(一票否决):无双判一致的 fresh 落档;
   - **归因登记(读数纪律,不是通过线)**:每次拦截必须落 error_code,区分
     `DIMENSION_CROSSCHECK_MISMATCH`(机械)与 `DIMENSION_MISMATCH`(语义);
     **判别增补:①达成但机械层零触发(拦截全走 Auditor)→ 判「候选机制未生效」,
     不宣告胜利**——demo 可过 ≠ 测量可信,bundle 绿 ≠ 独立标注源这一层生效;
   - **锁死判别(预登记终点,F1)**:①未达成 → 停止机器防线第四次重试,维度防线
     终点移交 HumanLatch(黄卡强制展示维度对照),评测侧按 c9 同款形状登记为
     「该端点维度混淆不可机器修复」已知边界,不再开新机器候选单;
   - **诚实框定(防 HARKing 继承)**:本修复**不背负** c5/c6 ≥2/3 fresh 金标线
     (同 #25 §4.6-6 理由:fresh 只能来自 Lead 真做同维度复验后过双判一致,
     那是 #27 Lead 复验行为层的账)。
   - **前置依赖**:验收跑前 docket 存量主张必须完成维度回填(子决策 7),
     否则不变量 8 无锚、全量回落 7,候选落空。
7. **回填口径**:存量主张**人工一次性标注**,依据 = 规格 §2.6 维度列 +
   gold `why_fresh` 叙述;**c6/c7 的「干扰」标签需人工判读其真实维度**
   (c6 锚客单价/定价类,判读依据 why_fresh 的因果叙述);标注人与判读依据进
   本评估留档。回填完成是验收运行的硬前置(子决策 6)。
8. **生产侧效应登记**:假 stale 被机械跨检拦成 unknown 后,HumanLatch 人审看到的
   黄卡携**结构事实**(登记维度 vs 反证自标维度),零模型意见污染——与 #25 §4.6-8
   同构,是评测读数之外的真实目标。
9. **实装归属**:新实装单(签发字段 + 反证字段 + 闸不变量 8 一个 bundle),
   行为验收独立触发(同 #25 不攒批纪律);实现层单测覆盖确定性层(签发校验、
   边界硬校验、闸字符串比对,逐位可复现)。

### §4.4 ADR 三条件自检(为何记 ADR-0011)

- **难反转?** 规则闸新增不变量 8 + 签发 schema 新增字段,W5–W8 及后续验收建其上;
  事后放宽 = 在「独立标注源已验」叙事下拆机械防线,破坏实验意义(清单 #7 追问通过;
  同 ADR-0010 后果条款同构)。
- **反直觉?** 是——#25 刚把机器闸③否掉(第二次),本单落地其「字段化」形态;
  未来读者必问「为什么这次不是乙」,答案(§3 四差异:外部锚/问法换锚/锚不可见/
  归因预验,缺一即是乙重演)必须落档才答得上。
- **真实取舍?** 签发侧新增人工标注成本(一次性 + 每条主张签发时多一个字段)vs
  防线独立性(比对锚完全脱离复验模型);以及每条 stale 的 Auditor 调用保留
  (并轨)vs 裸奔窗口。
三条件齐备;且 #25 前置约束 5 / #19 §4.4 明确 pre-registered「复活③诚实形态须当场
补 ADR」——记 `docs/adr/0011-独立标注源维度跨检与签发维度登记.md`。

### §4.7 词表处置(四件套 #3)

新增产品术语 **登记维度**(签发 schema 字段,非评测口径——闸生产路径同样消费),
入 CONTEXT.md;**规则闸** 词条不变量清单 touch-up 增第 8 条指针。「反证维度
字段」「机械跨检」是机制描述不是新词(住 ADR-0011);「归因登记」「拦截线」是
评测模式加严判据,按纪律 #4 归本评估文档,不进 CONTEXT.md。

## §6 面试讲法(grilling 预案)

**Q:#25 刚把机器闸③否了,这单又把字段化形态装回来,为什么不是乙重演?**
A:乙的死因不是「字段」两个字,是**锚在模型自己身上**——让模型自报「与主张的维度
关系」,声明对象不可验证,#21 的 reason 就是现成演示:模型敢写「均为单会话服务成本的
市场对标」。本次四个差异,缺一即是乙:①锚外部化——登记维度是签发时人工标注的结构
字段,不经复验模型之手;②问法换锚——字段问「反证自身攻击的维度」,声明的是可独立
验证的证据属性;③锚对模型不可见——Critic 填字段时不知道登记值,照锚填字段的对策
不成立;④归因预验——验收判别写明「机械层零触发不算赢」,bundle 绿不等于独立标注源
这层生效,当场读数而不是讲故事。

**Q:Critic 故意填错维度值(明知是定价填成本)怎么办?机械层不就穿透了?**
A:这是本候选的残余盲区,评估文档如实登记,不假装不存在。三道诚实的回应:①机制上,
字段问法把「诚实采样」和「照锚对策」分开了,#26 的失效形态是自信地**论证**维度一致,
不是故意撒谎——结构化枚举下的诚实错标正是机械层要抓的对象;②验收的归因读数就是来
验这个的:若字段被对策化,拦截不会落到 `DIMENSION_CROSSCHECK_MISMATCH`,「机械层
零触发不算赢」的判别当场识破;③若①未达成,预登记终点锁死:维度防线移交 HumanLatch,
不再第四次机器重试——拍板带诚实的退出条件,同 #25 的作风。

**Q:Auditor 反正与 Lead 同错,为什么不顺手拆掉/换个端点?**
A:两个不同的问题。「拆掉」:同错论据支持「不当唯一防线」,不支持「拆除」——存量
主张回填完成前,机械跨检无锚可比对,不变量 7 是那段窗口的唯一维度防线;拆已验防线
还触发 ADR-0010 后果条款的明示义务,收益是零(调用成本 #20 已拍过)。「换端点」:
异源端点只解「端点漂移相关错误」,不解同语料、同任务框架的共享盲区——#25 §6 已诚实
框定双判的局限;且第二端点的额度与可用性从未论证,偏离 #25 预登记方向。它不坏,只是
未论证,他日走独立工单。

**Q:金标不记 focus,登记维度会不会变相渗进金标、污染「评测不测调度品味」的纪律?**
A:不会,两道结构分开:登记维度住产品签发 schema(t0_docket.json),是主张的结构
元数据,生产路径同样消费(闸跨检);gold.json 一行不动,验收时闸的比对锚来自 docket
登记值(c5 = 成本模型,依据规格 §2.6),不碰金标。「金标不记 focus」纪律的原意是
金标不评价 Lead 的调度选择;签发登记维度不评价任何人,它是主张自身的属性标签。

**Q:缺失登记维度回落不变量 7,会不会把真 stale 也淹了?**
A:回落是回到 #26 前的丙′机制(Auditor 语义核对在场),不是回到单层裸奔——与拆掉 7
(A3)有本质区别。且 must_stale 回归守线(各 3/3 落 stale)在验收里原样保留,误伤
当场暴露。c1–c7 的反证是真维度反证,跨检比对结果自然是「相符」,机械层对它们零
动作,回归风险主要来自 Auditor 误标——那是 #25 已拍过账的既有风险,不是本单新增。

**Q:机械打回的异议记录没有模型意见,人审看什么?**
A:看结构事实:「主张签发登记为成本模型,本反证自标维度为竞品价格」。这恰是本设计的
生产收益——#26 的问题正是人审收到**带自信模型意见的红卡**;机械比对事实零模型意见
污染,人审自己做维度判断,黄卡成为 HumanLatch 的合法高质量输入。

**Q:n=3 是不是又拿小样本拍板?**
A:冒烟读数,继承 #19/#25 的 1/3 单跑翻转基率框定:判的是「防线存在性」不是统计
功效,n=3 足够暴露「机制完全不触发」级别的失效(#26 的 1/6 就是这么读出来的)。
要更高置信是 W12 复盘时的采样设计议题,已在地图 Fog 登记,不在本单。

**Q:人工标注的登记维度,凭什么可信?**
A:标注者是签发人——主张本来就是人签发的,维度标签是签发动作的自然延伸,标注依据
(§2.6 维度列 + why_fresh 因果叙述)留档可复核。这正是「独立标注源」的定义:标注
不经复验模型之手。评测期 12 条主张是一次性工作量;生产侧签发本就是人的动作,
成本是每条主张多一个下拉字段。

**Q:打回 unknown 而不是 fresh,还是老问题——为什么不一步到位?**
A:同 #25 §6 的答案,一个字不改:放行权不在闸也不在 Auditor,fresh 的唯一合法路径是
Lead 基于 T1 原文同维度复验后过双判一致——主张是真的,正确结果就该是 Lead 认真复验
后判 fresh,那是 #27 的账。unknown + 机械比对异议是诚实落点:不撒谎,把主张连同
结构事实一起交还复验流程和人审。
