## 2. 候选路线

### 维度一：主激活档

- **A. 档 2**：ingest 现算 sha256 + 真 `checksum_fn`（读语料现算）+ renew 半边确定性负例；**fresh 半边仍结构性空转**
- **B. 档 3a**：在 A 上，fresh 路径补构造 `validity_basis`（单 doc vs 多证据 list 的 schema 取舍）
- **C. 档 3b**：跨轮重检（谁比、何时比、不符降级）——改产品行为
- **D. 仍全留位**：只钉定义与攻击面清单，不接线、不重灌

### 维度二：「激活」操作定义（invariant）

- **A. 接线 + 负例过**：真 `checksum_fn` 已挂；篡改语料文件 → renew `CHECKSUM_MISMATCH` 可复现；套套逻辑书面钉死
- **B. 正路径也强制 basis**：renew/fresh 凡过闸必带非空 `validity_basis` 且与现算一致（实质吞 3a）
- **C. 只文档**：定义写清即可，代码可仍空转

### 维度三：「结构性空转」与验收失败边界

- **A. 分层诚实**：未激活半边可明示空转；**已宣称激活**半边负例打不响 = 假激活 = 验收失败
- **B. 全链或空**：fresh 或 renew 任一空转 = 整条不过
- **C. 演示过关即可**：单测绿即可，不管生产是否构造 basis

### 维度四：档 3a/3b 在本图处置

- **A. 升格为本图独立 grilling 票**（后置可取）
- **B. 留「Not yet specified」**
- **C. Out of scope**（踢出第一曲线后半）

### 维度五：预锁 invariant 可引用句形态

- **A. 长句**：含非空转条件、禁读库列、fresh 空转明示、禁升格 latch 证明
- **B. 短句**：renew 负例打得响；fresh 空转诚实登记
- **C. 长句 + 灌库非空行数进通过线**

### 维度六：是否新开 ADR

- **A. 开短 ADR**（推翻「档 2 不单做」：尺子从演示价值换成 invariant）
- **B. 不开 ADR**，只扩评估 + CONTEXT
- **C. 只补丁旧契约文件**

## 4. 拍板 + 逐项子决策

1. **主激活 = 档 2（renew 半边）**；fresh 半边**明示结构性空转**（runner 仍不构造 `validity_basis`）。
2. **不进本批**：档 3a、档 3b → 本图升格独立 grilling（见关单后子票）。
3. **激活 =** 真 `checksum_fn`（对 `data/corpus/{as_of}/{doc_id}.md` 现算 **sha256**）已接到 renew/闸路径 + 确定性负例可复现。
4. **硬约束**：`checksum_fn` **禁止**读取 `chunks.checksum` / `documents.checksum` 等同库列（套套逻辑）；basis 仍可写入库时指纹，比对对象必须是现算。
5. **结构性空转**：允许登记未激活半边；已宣称激活半边负例打不响 = **假激活** = Batch 2 验收失败。
6. **预锁 invariant 可引用句**（实现前锁死；事后改句 = 验收作废）：

   > Batch 2：renew 半边 checksum **非空转**——真 `checksum_fn`（语料现算 sha256，**禁读库列**）已接线；确定性负例（篡改语料文件 → renew 得 `CHECKSUM_MISMATCH`）可复现。fresh 半边**明示结构性空转**（不构造 `validity_basis`）。本句不得升格为「checksum 已证明 latch」。

7. **落点**：ADR-0017 + 本评估 + CONTEXT 规则闸措辞更新；**本会话不 `/to-spec`、不 `/implement`、不改 gold**。
8. **下游**：#98 攻击面用例、#99 renew 交界在本票关单后解锁；其细节不在本评估展开。

## 6. 面试讲法（grilling 预案）

**Q:契约写「档 2 不单做」，为什么 Batch 2 又做档 2？**
A:旧句的尺子是**演示价值**——静态合成语料下，renew 半边抓不到真实竞态。Batch 2 验收层改成 **invariant**：我们要的是「宣称启用的半边，负例打得响」。尺子换了，结论换；不是偷偷推翻事实盘点。

**Q:那现在「checksum 对不上不得 fresh」是真的在拦吗？**
A:**renew 半边**在 Batch 2 激活后应能拦（接线 + 负例）。**fresh 半边**仍结构性空转——runner 不构造 `validity_basis`，闸那行 `if decision.validity_basis:` 对 Agent fresh 恒假。我们把这半边写进预锁句，而不是假装全链已启用。

**Q:打开开关不就行了？**
A:开关之前先判 `checksum_fn` 读什么。读库列 = 拿 basis 来源比自己，恒等，留下永远绿的假不变量，比没有更糟。必须语料现算 sha256。

**Q:为什么不直接做跨轮重检（3b）？那才是 validity_basis 的牙齿。**
A:同意价值在那边，但那是**产品行为变更**，判据必须预登记（Anthropic #5），不能塞进「让 invariant 非空转」的实装单。本图已升格独立票，不叫「以后再说」的口糊。

**Q:负例过了是不是证明了 latch？**
A:不是。预锁句末尾写死：不得升格为「checksum 已证明 latch」。Void→Stay-Red / 人审作废才是品类证明；checksum 只是机械一致性闸。

**Q:和改 gold 凑绿有什么关系？**
A:无关且禁止。本票不碰 `gold.json`；攻击面用例走 #98 预登记用例表，用放宽闸/改金标冒充激活 = 违例。
