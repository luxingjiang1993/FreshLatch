## §问题 + 前置约束

**问题**:c9(must_unknown,T1 仅有「本轮未复测……该指标不再列入跟踪项」元陈述)在复现 2 / run2 两次被 Lead 以元陈述为唯一依据判 stale。人格显式规则(lead.py:25、critic.py:29「未复测=证据缺口,走 mark_gap+unknown,不得判 stale」)在案仍被违反——**提示词层防线已被实践证明可被端点漂移击穿**(W4 窗口三次运行,c9 两次 unknown、一次 stale,非确定性)。

**前置约束(已被先前工单/签认钉死,不得违反)**:

1. W4 验收已签认达成(2b98bc6);c9 背离一记背离不升级,定性「判定逻辑边界案例 + 端点漂移组合」——本工单不改该定性、不翻案。
2. 判据锁定:checklist 判据未动一字;harness 缺陷修复为工程修复、非判据修订(repro-check 签认口径)。
3. 规则闸定位:纯函数/Workflow 层、零 I/O、绿灯唯一出口(CONTEXT.md「规则闸」,ADR-0001/0006)——闸拿不到证据正文,只能看注入的 id 与理由文本。
4. 评测可复现性:评测期联网代码级禁用;任何新机制不得引入非确定性(LLM judge 出局)。
5. must_unknown 的既有防线「无 t1_evidence_ids 不得 fresh」不变;本闸只作用于 stale 方向。
6. 不对称安全原则:闸的误伤只允许把 stale 压成 unknown,绝不向绿灯方向开口(stale/unknown 本就不得绿灯,不变量 1 兜底)。

## §拍板 + 逐项子决策

**拍板:D1-a + D2-a + D3-a/D3-b 叠加 + D4-a**,即规则闸新增不变量 6,机制为确定性句法启发式。

子决策:

1. **GateDecision 增加 `stale_reason: str = ""` 字段**。runner._finalize 的 stale 分支把 decision.reason 注入。向后兼容:默认空串不过元陈述校验(空理由不是「纯元陈述」,理由存在性是工具层 ≥20 字校验的职责,闸不重复管)。
2. **判定算法**(钉死,先于测试):

   ```text
   输入: stale_reason 文本
   1. 按 [，。；、,.;:!?！？\n] 切子句
   2. 含任一「元陈述标记」的子句记为元子句:未复测/不再列入跟踪/不再跟踪/不再列入/无新数据/暂无新数据/没有新数据/待发布/尚未发布/未入账/未保留/无法确认/未能确认/尚不能确认/待核实/本期未/本轮未
   3. 若无任一元子句 ⇒ 非纯元陈述(放行)
   4. 存在「实质子句」⇒ 放行:含阿拉伯数字且本身不是元子句
   5. 全无实质子句 ⇒ 纯元陈述,打回 META_ONLY_DISPROOF
   ```

   用两次实录形状验证:c9 run2 全文理由(「本轮未复测……该指标不再列入跟踪项,因此主张失效」)与复现 2 理由(「无法确认其是否仍不低于 70%,原主张前提已失效」)均被打回;合法 stale 实录(c3/c7:含数值锚的反证)放行。
3. **error_code = `META_ONLY_DISPROOF`**;闸层打回消息明示「元陈述(未复测/不再跟踪等)是证据缺口不是推翻,请走 mark_gap + unknown」。
4. **工具层提前反馈**:Lead._t_mark_stale 与 Critic._t_mark_stale 调用同一纯函数(单一真相在 gates/meta_gate.py),命中即返回同口径错误,引导模型走 mark_gap+unknown——D3-a(闸兜底落 unknown)与 D3-b(工具层引导)叠加。
5. **不对称安全**:打回只发生于 stale 分支;stale/unknown 不得绿灯(不变量 1)天然兜底,误伤最坏结果 = 该主张本轮 unknown,HumanLatch 人审仍可见,绝不向绿灯开口。
6. **金标/判据/语料一律不动**;历史三次运行的记录与背离登记原样留档,不重跑、不改写。

**已知边界登记(预登记,事后不得「跑完再修」)**:

- B1:合法 stale 理由形如「本期未复测,但 T1 明确宣布取消该牌照制度」(实质反证无数值)会被本闸误伤 → stale 压为 unknown。**不对称安全接受**:人审仍可见该主张;W12 前工程债方向:实质子句判定扩「变化动词 + 实体」词表(无数值锚时)。

## §面试讲法(grilling 预案)

**Q:为什么不选 LLM judge?**
A:两条硬约束。第一,评测可复现性:评测期要求确定性,judge 引入第二次非确定性,而且 judge 和被判者同源——c9 的失败本身就是端点漂移,用同一个会漂移的东西去防漂移是循环论证。第二,闸的架构定位是纯函数零 I/O,可审计性来自「每条不变量逐位可复现」。句法启发式看起来笨,但笨得可证。

**Q:启发式误伤合法 stale 怎么办?**
A:先给原则:闸的误伤只允许单向——把 stale 压成 unknown,绝不向绿灯开口,这是不对称安全。误伤的最坏结果是该主张本轮挂黄灯进人审,人审工作流本来就要处理黄灯。其次我们有预登记:B1 边界在跑任何测试之前写死,不允许「跑完再修判据」;修词表扩「变化动词」走新评审工单。最后,误伤率本身是可测量的——每次打回落档都带 error_code,抽样人工复核就能给出误伤率估计,而不是拍脑袋。

**Q:这和 c5 二修、人格规则什么关系?是不是提示词不管用了才堆闸?**
A:c5 二修(d91a41e)是维度锚定,管「反证锚错维度」;本闸管「拿证据缺口当反证」。人格规则管的是模型的行为倾向,闸管的是落档不变量——这是 FreshLatch 的一贯架构:激励隔离 + 规则闸唯一出口,Agent 自律是第一层,闸是兜底。实证也支持分层:c9 人格规则在案仍被击穿两次,所以兜底从「提示词」升级成「机械不变量」。我们不能让产品正确性依赖「模型这回听不听话」。

**Q:为什么判据(金标)不动?这算不算变相改验收?**
A:不算。must_unknown 的判据从第一天就是「T1 无原文覆盖必须判 unknown」,c9 的 T1 只有元陈述,没有关于渗透率 70% 的实质内容,判 stale 本来就是错的——是 harness 没拦住错误,不是判据要改。修复方向是把 harness 的行为对齐到既有判据,而不是把判据对齐到 harness 的错。这就是 repro-check 签认里「工程修复 ≠ 判据修订」的口径,本次严格执行。

**Q:三次运行 c9 两 unknown 一 stale,怎么确定修好了?**
A:诚实回答:单次运行判生死不合格,这是 Anthropic 清单第 2 条。本次交付的确定性证据是:两次实录失败 reason 注入闸层单测,逐位判 unknown——这不是统计结论,是机制级验证。行为层(端到端 12 主张重跑)c9 收敛到 unknown 需要采样多跑, honest framing:那是 W12 前的冒烟层验证,n 小就报方向不报方差。

**Q:打回后模型会不会换个说法绕过标记词表?**
A:会,这是 B2 登记的边界。防线的正确预期是分层的:标记词表抓已知形状,人格规则 + mark_gap 工具引导管语义理解,闸兜底纯元陈述落档,人审兜底一切残余。任何单层都被假定会失效,这是激励隔离架构的基本世界观;本闸的价值是把「已知形状」从随机失败变成确定性打回——c9 这类边界案例从此不再是漂移的函数。
