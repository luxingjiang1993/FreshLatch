## 2. 候选路线(维度 × 全部候选,含被否项)

### D1 判定人与判定流程
- (a) 开发者本人自验,无外部环节
- (b) 开发者自验 + ≥1 名真人盲看复述(可复用同一人)
- (c) 找第二位工程师交叉评审(被资源约束否)

### D2 「能点回 T1 原文」通过判据
- (a) 全量:金标内有 T1 证据的主张 100% 可点回且 anchor 命中,录屏一镜到底
- (b) 抽样:随机抽 3 条点回(被「停止条件是生死线,抽样留侥幸」否)
- (c) 机器单测代替人工点:DOM 断言锚点存在(被「测通过≠演示得出」否,Demo 层必须人判)

### D3 「可理解的已死反证」操作定义
- (a) 三条判据:可点回 t1 证据 + 显式因果句 + **真人能复述**(原推荐)
- (b) 三条判据:可点回 t1 证据 + 显式因果句 + **引用 span 与金标 causal_chain 对齐(硬)**;真人复述降级为抽测(软)(Anthropic 修正后拍板)

### D4 反证计数与运行次数
- (a) must_stale 4 条单次运行 4/4 覆盖(原推荐)
- (b) must_stale 切片 3 遍 × 3 seed,停止条件 = ≥2/3 遍出现 ≥1 条有效反证;4/4 降为质量目标(拍板)
- (c) 直接上 `--runs 5`(被 #9 推迟决议钉死:W5–W8)
- (d) 按反证条数计数(被「停止条件关心的是主张覆盖,不是反证产量」否)

### D5 主界面四条红线自检分工
- (a) 前三条代码级 CI 单测判通过(原推荐)
- (b) 四条全部有人审兜底,代码单测只防回归;复述测试加探针「与文档搜索工具有什么区别」(Anthropic 修正后拍板)

### D6 验收材料清单与留档
- (a) 全部 commit 进 git(被 mp4 体积否)
- (b) 文本/截图 commit,录屏本地留档 + 检查表记路径(拍板)
- (c) 全部本地不进 git(被「作品集需要可展示的验收证据链」否)

### D7 W4 未过处置
- (a) 一刀切:切片任一条不过都直接停(最忠实原文)
- (b) 分级处置:定位红线失败即停;工程失败给一次性 2 周修复窗口后复验,同一份检查表同一批判据,窗口不得续杯(拍板,纪律入 ADR-0007)
- (c) 迭代到达标为止(被「停止条件退化为无限修复」否)

### D8 验收时机
- (a) W4 末一次性终审(被「末期才发现点回做不出来风险最大」否)
- (b) W3 末预检(冒烟)+ W4 末终审(全量),两阶段(拍板)

### D9 复现抽查(第二轮新增维度)
- (a) AFK 会话冷启动重跑,对照混淆矩阵条数必须完全一致(原推荐,被「随机层本来就该不同,必然误报」否)
- (b) 两层口径:闸层(must_* 零违例)逐位复现;判定层(矩阵条数)按文档化容差;违例级背离 = must_stale 被判 fresh 等(拍板)

## 6. 面试讲法(grilling 预案)

**Q:W4 验收怎么判过?**
A:两层级。Demo 层是确定性检查:金标里有 T1 证据的主张逐条点回且 anchor 命中,一镜到底录屏;四条界面红线全部有人审兜底,代码单测只负责防回归。冒烟层只压随机系统:must_stale 切片跑 3 遍 × 3 seed、显式非零温度,≥2/3 遍出有效反证即过「Critic 给得出反证」这条停止条件。

**Q:为什么是 3 遍不是 5 遍 10 遍?**
A:n=3 没有统计功效,我自己先说破——它是冒烟,不是方差估计。正式的多运行 runner(`--runs N≥5`)已经拍板在 W5–W8 实装,不重复建设;W4 用 3 遍只为排除「单次运气」,成本每主张约 0.1 分钱。

**Q:为什么不把 temp 钉死求复现?**
A:temp=0 时 seed 没有采样意义,三个 seed 跑出三个相同结果,会拿到「3/3 一致」的假信心。复现性由语料 checksum 和金标扛,运行间采样要真的在变,所以显式非零温度。

**Q:「可理解的反证」怎么操作化,不算主观?**
A:三硬一软。硬:可点回的 t1 证据、显式因果句、引用 span 与金标 causal_chain 登记的致死段落对齐——机器可查。软:真人抽两条复述当兜底。原方案拿真人复述当硬判据,被我自己用「判据本身不可复现」否决了。

**Q:验收不过怎么办?**
A:分两类。定位红线失败(界面已是聊天框、盲看复述成 EvidenceOS)= 不可修,立项失败直接停。工程失败(点回/反证不达标)= 一次性两周修复窗口,用同一份检查表同一批判据复验,窗口不得续杯——这条纪律进了 ADR,因为「迭代到达标为止」会让停止条件名存实亡。

**Q:单人开发,谁监督你自己?**
A:三个机制。一,判据 pre-registration:检查表先于结果锁定,事后改 = 验收作废。二,复述测试必须真人盲看,我自己测自己不算数。三,AFK 会话冷启动复现抽查——把 AFK agent 会话当项目里的「第二个人」,对照留档数字。
