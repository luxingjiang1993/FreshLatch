FreshLatch 现状摘录

对照四闸字段整理已经写下来的内容。本文不批准新方案，也不改 ADR。

盘面分两层。提交 48fa644 里有规格、ADR、研究文档和 scripts/smoke_dashscope_tool_loop.py。工作区里还有未入库的 data/ 与 docs/product/。没有 src/freshlatch/、skills/、tests/、requirements.txt。下面凡是写「规格」的，都还没有对应实现。

1. 产品

问题

顾问、产业研究员、战略岗已经发出过一版判断。两周到六周后，客户追问「还成立吗」。T0 卷宗看起来仍可辩护，T1 里价格、监管、访谈已经变了，人仍把旧的绿灯附件发出去。要的是能指回 T0 与 T1 原文的复验单，不是再生成一篇摘要。

锁定课题，开工后禁止改：两周前那份「是否在未来 12 个月进入东南亚中小企业 AI 客服市场」的判断，现在还成立吗。只用合成材料，界面标 synthetic。

成功判据

仓库里没有另写一个转化率或收入数字。已经写死的是北星和 W4 验收，不是事后补的指标。

  • 北星：已签发主张在 T1 是否仍可复验。过期、冲突、无 T1 原文支持的主张不得保持绿灯。人决定作废或续命。
  • W4 锁定判据在 docs/spec/07-验收-W1-W4.md：J1 点回（demo，全量不抽样）、J2 有效反证（冒烟，3 遍 × 3 seed，不报方差）、J3 四条红线、J4 复现抽查。统计层 --runs N≥5 不在 W4 内。

立项切片里的价格（课题 3000–8000 元，或 199–349 元/月）是买方描述，不是验收指标。

已有表述

把已签发主张从「曾经为真」改成「现在仍可复验」。过期、冲突、无 T1 原文支持的主张不得保持绿灯，人决定作废或续命。主界面是复验单，不是聊天框，不是记忆列表，也不给出「建议进入 / 不进入市场」的裁决。公司名是 FreshLatch，不是 MemoryForensics，不是 EvidenceOS。

屏幕

规格定的是一张双栏复验单：左栏主张卡片（灯色、理由、evidence_id、人审动作），右栏原文，点 doc_id#anchor 高亮。主按钮文案是「开始复验」。续命按钮在 W3–W4 渲染但 disabled。本工作区没有可打开的页面文件。双糙样在分支 prototype/ui-双糙样，不在当前工作区。

2. 架构

怎么接上现有仓库

不改前四轮仓库，不改第五轮正本。EvidenceOS 只作为 T0 导入形状（statement + t0_evidence_ids），不做新调查。LangGraph 只在 W3 起做人审 interrupt，隔离在 latch/，Agent 循环不 import 它。评测是旁路，不进复验单 UI。

端点

规格只写下这两条，都是同步 def，W3 起才启用：

  • POST /api/latch/decide：决定列表 discard 或 renew，恢复 interrupt。
  • POST /api/latch/rerun：单主张重跑，新 thread reverify-{claim_id}-{ts}。

拆单里写了 docket 导入端点，没有写下具体路径。这里不补。

数据

工作区未入库、但文件在盘上：data/t0_docket.json（12 条主张）、data/corpus/t0 与 data/corpus/t1 各 12 篇、data/eval/gold.json（must_stale 为 c1/c2/c3/c7，must_fresh 为 c4/c5/c6/c8，must_unknown 为 c9–c12）。data/checkpoints.db 不存在。SQLite 四表（chunks、documents、invalidation_list、latch_log）只有规格，没有库文件。

主路径

导入 T0 → Runner 注入预算和作废/隔离名单 → Lead 裸循环（检索、读原文、写判定，W3 起才 spawn_critic）→ 规则闸（绿灯唯一出口）→ Scribe 只排版 → HumanLatch（W1–W2 直通，W3 起 interrupt）→ 复验单。Critic 只回吐反证。Auditor、Forensic 不在 W1–W4 挂载。评测 runner 跳过 HumanLatch，代码级禁联网。

外部

  • 环境变量名 DASHSCOPE_API_KEY。冒烟脚本里的端点是 https://dashscope.aliyuncs.com/compatible-mode/v1，模型 qwen-flash。
  • web_search 只留插座，评测期不联网。
  • 不接 Mem0，不暴露删除，不做「开始新调查」。

图由 archify 按规格生成，不是运行中的进程。节点上的「规格未编码」表示仓库里还没有这些 Python 模块。证据钉在提交 48fa644；data/ 未入库，所以图上的出处链到规格，不链到卷宗文件。

规格里的签名

下面是规格已写的形状，仓库里没有函数体。

def rule_gate(claim: Claim, decision: GateDecision, ctx: GateContext) -> GateResult
retrieve(query, source_type, as_of)
read_source(doc_id)
reverify_claim(claim_id, status, evidence_ids)   # 仅 Lead
mark_stale(claim_id, reason)
mark_gap(description)                            # 仅 Lead
spawn_critic(focus?)                             # 仅 Lead，W3 起
spawn_auditor(claim_id)                          # W5–W8，本期不挂载
finish_reverify()                                # 仅 Lead
report_finding(...)                              # 仅 Critic
verdict(fresh | stale | unknown)                 # 仅 Auditor，W5–W8

W1–W4 的 Lead 白名单不含 spawn_auditor，也不含记忆卫生工具。W1–W2 还不含 spawn_critic。focus 六个值已定：competitor_pricing、regulatory_stance、interview_reversal、cost_model、market_structure、tech_ecosystem。

调用顺序

Runner 调用 Lead。Lead 调用检索库和 DashScope；W3 起可同步拉起 Critic，Critic 以 report_finding 返回。Lead 的写入进 rule_gate。通过后 Scribe 排版，再进入 HumanLatch，最后到复验单。评测从 Runner 旁路进入，不经过人审页面。

测试计划

名称已经写在 docs/spec/07，测试文件还不存在：规则闸四条不变量、gold.json 驱动的闸单测、技能一致性四断言、红线前三条源码断言、假绿对照、金标 runner（N=1）。W4 的 J2 预先写成冒烟，不报方差。

规格里已经登记的风险

这不是新的未决项，是 docs/spec/08-拆单建议.md 第 8.5 节的原清单：qwen-flash 多文档时间线偏弱；BM25 可能漏掉同义改写；LangGraph 1.0.x 要锁版本；Windows 上同步 SqliteSaver 的文件锁要在 T9 开工时验证；DashScope JSON mode 要在 T10 顺带冒烟。
