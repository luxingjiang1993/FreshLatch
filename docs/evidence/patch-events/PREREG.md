本页不改生产。不改 `PRODUCTION_RETRIEVAL_MODE`，不改金标文件，不改 `data/corpus`，不调用付费 API，不提交密钥。本页只锁口径。

主张收窄为 fail-closed attested edit：每处修改必须绑定 chunk 级证据，并通过自动核验；核验不过就 hard reject。不写成笼统的「可解释的文档更新」。测量的是「改不改」的风险，不宣称发明了新的 risk-coverage 方法。

## 样本框

- 只有第一课题 `thesis-1`：`data/t0_docket.json` 的主张，证据来自 `data/corpus/t1` 与对应的 `data/corpus/t0`。
- 合成语料。不用 KPR 的 benchmark，不用医疗指南，不做第二领域。
- 一条样本是一次候选修改：主张原文、修改后文本、绑定的 evidence id、修改类型、构造金标。
- 构造金标只有两类：`正确`（该放行）、`坏`（该拒绝）。金标在任何系统输出和任何评委打分之前写死。评委标签和用户裁决都不替换构造金标。
- 主张按 `claim_id` 字典序取用。某个槽位按下面的算子做不出来，这个槽位作废，换下一条主张，算子不改成更好做的那一个。语料不够就把缺额写进结果，不在本页把配额改小，主比较不成立。

pilot、n=30、n=100 共用这一条名单。pilot 占每层最前面的槽。n=30 紧跟其后。n=100 是 n=30 的超集，沿同一顺序继续取。pilot 的 id 不进入 n=30 和 n=100。

## 配额

层内正确条数 = floor(k/2)，坏条数 = ceil(k/2)。k 为偶数时严格各半。k 为奇数时坏修改多一条。这个余数规则先写死。

| 用途 | 数值 | 日期 | 条款替换 | 删除 | 合计 |
|---|---:|---:|---:|---:|---:|
| pilot | 4（正确 2 / 坏 2） | 4（2 / 2） | 4（2 / 2） | 3（1 / 2） | 15 |
| n=30 | 8（4 / 4） | 8（4 / 4） | 8（4 / 4） | 6（3 / 3） | 30 |
| n=100 | 25（12 / 13） | 25（12 / 13） | 25（12 / 13） | 25（12 / 13） | 100 |

n=30 是小样本门槛。n=100 是满样本门槛。两次都用本页的同一套检验。n=30 的区间只描述这 30 条的重抽样噪声，不写成总体结论。

共形预留集不从上面的配额里挖。四层在满样本之后再各留 5 条，凑够才可以做可选的误放率上界。不够就写「未做」，主比较照常按本页判决。

## 构造算子

正确修改：改完的事实与所绑 T1 chunk 一致，evidence id 指向该 chunk。

- 数值：换成该 T1 chunk 里同一指标、同一对象的数字。
- 日期：换成该 T1 chunk 里同一事件的日期。
- 条款替换：换成该 T1 chunk 里同一义务主体的对应条款表述。
- 删除：删掉该 T1 chunk 已经写明废止或不再存在的限定。

坏修改：表面像一次更新，但与证据矛盾，或证据不能支撑。层内坏槽按出现顺序从 0 编号，算子 = 编号 mod 4。符号由编号 // 4 决定：偶数用加号或放大，奇数用减号或缩小。扰动结果若与正确值相同，该槽作废，不另选算子。

数值：

0. 正确数字 ±10% 后取整。原数是整数则取整数，否则保留两位小数。0.5 远离 0。
1. 正确数字 ×10 或 ÷10。
2. 换成同一 chunk 里另一个不同的数字。chunk 里少于两个不同数字则该槽作废。
3. 保留正确数字，单位在 `%`、`个百分点`、`元`、`万元` 中换成下一项（循环）。换完与原文相同则该槽作废。

日期：

0. 正确日期的年份 ±1。
1. 正确日期的月份 ±1，跨年则进位。
2. 换成同一文档里另一个不同的日期。没有则该槽作废。
3. 日期文本用正确值，evidence id 改指同一文档的 T0 chunk。没有 T0 则该槽作废。

条款替换：

0. 义务方向对调：`应当` 与 `不得` 对调。两者都没有时，在主要动词上加上或去掉 `不`。文本没有变化则该槽作废。
1. 义务主体换成同一文档里点名的另一个主体。没有则该槽作废。
2. 换成同一文档里另一条条款。没有则该槽作废。
3. 条款文本用正确值，evidence id 改指文档顺序中的下一块，且那一块不含该条款。下一块仍含该条款则该槽作废。

删除：

0. 删掉 T1 仍然肯定的限定。
1. 删掉例外或阈值，使主张范围变大，且所绑证据不支持这个放大。
2. 删除文本与正确删除相同，但 evidence id 为空。
3. 只删一个不改变金标事实的修饰，并在修改说明里写「按新证据必须更新」。

## 实验组

四组吃同一批候选。生成侧若要调用模型，只用本仓 `DEFAULT_MODEL`，即 `qwen-flash`。不得为了本实验改这个默认值，也不得改草稿解码预锁。温度或种子缺省则该次生成作废，不许事后补填。

| 组 | 做法 |
|---|---|
| C | 无证据改写。不绑定 chunk，不跑自动核验，不 hard reject。生成成功即自然放行。 |
| T | attested patch，fail-closed。修改必须绑定 chunk 级证据，且 evidence id 属于本次已入库 T1；自动核验不过则 hard reject，不写回。 |
| B1 | post-hoc verify。先改后验，RARR 式。核验发生在修改生成之后。核验不过则拒绝。不得把这种拒绝记成 T。 |
| B2 | KPR 式 claim → diff。先从主张得到 claim，再生成 diff。核验不过不自动 hard reject。 |

主实验里 T 的检索只读 `src/freshlatch/store/base.py` 在针 `d42276d` 上的赋值：`PRODUCTION_RETRIEVAL_MODE = "hybrid+rerank"`。本实验不改这一行。

消融只在 T 上做，不进入主比较顺序。四项都要报，任一单项不得改写主比较的判决：

- 拿掉 chunk 绑定
- 拿掉自动核验
- hard reject 换成 soft warning
- 检索臂在脚本里换成 BM25，另记一列 hybrid+rerank。生产赋值不动。主臂已经是 hybrid+rerank 时，这一列与主臂相同，仍单独记账。

## 指标

放行率 = 放行数 / 候选数。

误放率 = 放行且构造金标为坏的条数 / 放行数。放行数为 0 时无定义，禁止记成 0。

误拒率 = 构造金标为正确且被拒绝的条数 / 构造金标为正确的条数。

错改率 = 放行且构造金标为坏的条数 / 候选数。它是全体上的坏放行比例，不是放行集里的风险。

可复验率 = 放行样本中，evidence id 非空、能解析到本次已入库 T1 chunk、且有再验记录的条数 / 放行数。放行数为 0 时无定义。

延迟：每条候选从输入到放行或拒绝的 wall time，报中位数和 p95。不含模型加载。

成本：该臂若调用付费 API，按当次 token 与单价记账；没有调用则记 0，并写明没有调用。单价记账单上的数字，不在本页预填。

主指标是固定放行率下的误放率（edit-level risk-coverage）。x 是放行率，y 是误放率。误拒率必须同时报。错改率、可复验率、延迟、成本都报，但不参与「成立」。

固定放行率用 T 的自然放行数 k。k = 0 时，固定放行率上的误放率无定义，主比较不成立。

- 有排序分数的臂：分数从高到低放行前 k 条。分数相同则 `claim_id` 字典序在前的先放行。
- C 没有验证分数。用名为 `coverage_c` 的 `random.Random(20261007)` 无放回随机放行 k 条。这条随机流只用于覆盖率对齐，不表示 C 有验证器。

各臂自己的自然放行率另报，不替代主指标。

## 主比较

比较顺序写死，一次只推进到下一条：

1. 第一主比较：T 对 C 的误放率。
2. 第二：T 对 B1 的误放率。
3. 第三：T 对 B2 的误放率。

配对差 = 对照的误放率 − T 的误放率。正值表示 T 更低。

一条比较成立，当且仅当：点估计 > 0，且下面的 95% 区间下界 > 0。下界 ≤ 0 或点估计 ≤ 0，该条不成立。无定义不是成立。

统计：配对 bootstrap 10000 次。单位是候选 id。每次有放回抽取与原样本等长的 id，两组用同一批 id 重算指标。95% 区间用线性插值百分位。

名为 `bootstrap` 的 `random.Random(20261007)` 单独一条，按比较顺序消耗。每个比较内部的指标顺序是：误放率、误拒率、错改率、可复验率。每个指标 10000 次。误拒率及以后的区间只报告，不参与「成立」。某次重抽样的放行数为 0，该次误放率或可复验率丢弃，不填 0。丢弃比例超过 5% 时，该指标无定义。

延迟和成本不进这条 bootstrap。

消融放在三条主比较之后，用各自的自然规则报告，不占用 `bootstrap` 这条随机流的前三个比较。消融若要区间，另起一条 `random.Random(20261007)`，名字是 `bootstrap_ablation`。

## 评委

三家外部评委，都走 API，都不是生成系统 `qwen-flash`：

| 评委 | 锁定的 model 字符串 | 额外请求 |
|---|---|---|
| Qwen2.5-72B | `qwen2.5-72b-instruct` | 不使用 `qwen-flash`、`qwen-plus`、`qwen-max` |
| DeepSeek-V3 | `deepseek-ai/DeepSeek-V3` | 思考关闭。禁止 `deepseek-chat`、`deepseek-reasoner`、`deepseek-flash`、`deepseek-v4-pro` |
| Kimi | `kimi-k2.6` | `thinking` 为 `{"type":"disabled"}`。禁止 `kimi-latest`、代码专用 id、`kimi-k3` |

Qwen2.5-72B 与 `qwen-flash` 同属通义，但是另一个 model 字符串，只做评委，不参与生成。

每条请求 temperature=0。服务端拒绝该参数、回显的温度不是 0、或拒绝关闭思考，则该评委整次运行作废。不得改用服务端默认温度再打一轮当作原计划。托管端点会漂移；响应里的 model 与上表不一致时，该评委整次运行作废，不得换一个仍在线的新模型顶上。跨会话复现只能近似，这个限制写进结果，不拿来放宽上表。

评分细则逐字使用，不许加提示，不许改措辞：

```text
你是修改核对员。你只回答两个问题，不给修改建议，不评价文风。
问题A：修改后的陈述与所附证据是否一致？只回答是或否。
问题B：所附证据能否支撑这次修改？只回答是或否。
证据缺失时，两题都答否。
输出一行 JSON，形如 {"A":"是","B":"否"}。A 和 B 只能是「是」或「否」。
不要输出其他文字。
```

用户消息只含四段：修改前、修改后、证据原文、evidence id。不含组别、不含系统名、不含构造金标、不含其他评委的答案。

输出必须是一行 JSON，A 和 B 各自只能是 `是` 或 `否`。解析失败允许用同一提示、temperature=0 再请求一次。第二次仍失败则该题记缺失，不许编成 `否`。

现有的模型双标可以附在表外。它不是评委，不进入 Cohen's κ、Fleiss' κ、多数意见和用户裁决。

κ 按题分开算，A 一题，B 一题，都是二分类，不加权。

- 两两 Cohen's κ：三对。分母是该对两家都给出 `是` 或 `否` 的条目。
- Fleiss' κ：三家都给出标签的条目。
- 报告每个 κ 所用的条数。缺失不插补。

三家都给了标签、且 A 或 B 上不是完全相同的条目，交给用户本人裁决。用户只看修改和证据，看不到三家各自的选择，也看不到组别。有缺失的条目单独列出，不算「意见不一致」，也不用多数票填上。

用户抽检在知道哪些条目不一致之前做完。抽检集是主样本的子集：

| 规模 | 每层抽检 | 其中正确 / 坏 | 合计 |
|---|---:|---:|---:|
| n=30 | 2 | 1 / 1 | 8 |
| n=100 | 5 | 2 / 3 | 20 |

`spotcheck` 这条流按层顺序消费：数值、日期、条款替换、删除。每层先打乱该层正确修改的 `claim_id`，取满该层的正确抽检条数，再打乱该层坏修改的 `claim_id`，取满该层的坏抽检条数。这条随机流不参与 bootstrap。用户抽检时看不到评委输出，也看不到组别。

抽检集里后来又落到不一致集的条目，以抽检时已经写下的答案作为裁决，不第二次看。

一致率 = 两边标签相同的条数 / 两边都有标签的条数。另报用户对每一位评委、每一题的 Cohen's κ。用户不进入三家的 Fleiss' κ。

评委侧的裁决标签只描述标注。它与构造金标冲突时，结果页列出冲突，不删样本，不改构造金标，不改本页。

结果页的标注身份写「模型评委加单人抽检」。不得写成两名真人盲审，不得写成真人盲审。

## 复现

确定性的部分必须逐位一致：配额、算子、四条命名随机流的种子和消费顺序、评分细则原文、三个 model 字符串、temperature=0。四条随机流是 `coverage_c`、`bootstrap`、`bootstrap_ablation`、`spotcheck`，各自单独构造，种子都是 20261007。构造阶段不用随机，只按 `claim_id` 排序。

随机的部分给留档，不假装逐位一致：评委 API 的文本在温度请求被遵守时仍可能因端点漂移而变化。响应 model 或温度对不上表，该评委运行作废，而不是放宽容差。

违例级背离：跑数后改本页；用未锁定的模型顶替；把现有模型双标算进 κ；把本次标注写成真人盲审；把 pilot 并进主表；为了结果改 `PRODUCTION_RETRIEVAL_MODE` 或金标；放行数为 0 时把误放率记成 0。
