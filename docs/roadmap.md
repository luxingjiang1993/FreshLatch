# FreshLatch 整合技术与产品路线图

> 状态：基于当前仓库事实与产品讨论整理的执行版路线图。  
> 约定：**先 RAG，后 Agent**；中间补证据/契约；联网只允许「落盘再复验」；不做开放问答主产品。

---

## 0. 北极星与硬边界

### 产品一句话

把已签发主张从「曾经为真」变成「现在仍可复验」；过期、冲突、无 T1 原文支持的不得保持绿灯；人决定作废或续命。

### 硬边界（全程有效）

| 允许 | 禁止 |
|------|------|
| 只认 **已入库 T1** 参与裁定 | 开放联网问答直接写绿灯 |
| `web/API → 落盘成 T1 → 再复验` | 搜索摘要只进 prompt、不入库 |
| 导引 / 解释 / 主张草稿类薄入口 | 通用对话助手绕过闸门 |
| 窄垂直做深 | 无关行业摊大饼稀释「卖作废」 |

### 执行顺序

```
Phase A（RAG）→ 中间层 M → Phase B（Agent）→ 增强 C（采编 / 嵌入 / 资产库）
```

阶段之间 **检索契约冻结**；Agent 阶段默认不改召回算法。算法变更须回到 Phase A 开新迭代。

### 与现状的关系（摘要）

- 主链已有：裸 ReAct 多角色、规则闸、HumanLatch、SQLite+BM25、人工 T1 三卡、金标/闸测。
- 明显缺口：vector/rerank 空实现、Memory 半激活、行为层统计未闭合、README 弱、无自动采编。
- `web_search`：仅架构插座，未进白名单，无真搜索。

## 1. Phase A — RAG 专项

**目标**：`retrieve(query, filters) → ranked chunks` 成为可独立测量、可替换的子系统。Agent 只当调用方。

| ID | 项 | 验收要点 |
|----|-----|----------|
| **A0** | 检索契约冻结 + 语料快照 + BM25 基线 | schema 单测；语料 checksum 入档；基线报告一页 |
| **A1** | Retrieval dev set + Recall@K / MRR | ≥30–50 query；`eval retrieve`（或等价 CLI）可复现 |
| **A2** | Dense 召回（填实 `stage_vector_fuse` 空实现） | 索引可重建；模型/向量失败时降级策略明确且可测 |
| **A3** | Hybrid（BM25 + dense） | BM25 / dense / hybrid 三列对比；主指标不低于两者较差者 |
| **A4** | Rerank | 有增益才默认开启；延迟预算写入报告 |
| **A5** | Query transform（检索入口 claim→query） | 改写前后 Recall 对比；**不**放进 Lead 自由发挥 |
| **A6** | Ingestion：PDF 纯文本切块 | ≥1 份真实 PDF 进库可检索（表格/HTML/OCR 后置） |
| **A7** | 版本字段 + 快照过滤（`as_of` / `source_type`） | 快照过滤可测；不做日历生效/失效窗；与后续腐烂对齐的是快照而非日历窗 |
| **A8** | 检索陷阱三类 v0（快照取代 / 同快照冲突 / 元陈述） | 检索评测与后续 Agent 对抗共用；路线图旧称「过期」读作快照取代 |

### Phase A 关门条件

1. 可复现的 retrieve 评测表（含基线对比）。
2. `retrieve` 契约稳定；轨迹能记录 `chunk_id` 列表。
3. 快照过滤可用；索引可重建步骤写清。
4. **本阶段不做**：Memory 挂载、对抗套件、并发、跨 Provider、开放联网问答。

### 关键路径（现状）

- `src/freshlatch/store/pipeline.py` — BM25；vector/rerank 空透传
- `src/freshlatch/store/ingest.py` — 当前偏 Markdown
- `src/freshlatch/store/sqlite_store.py` — schema / `vec` 留位

## 2. 中间层 M — 证据、契约、交付口径

**时机**：A 关门后、B 大改编排前；可与 B0 评测仪器并行。

| ID | 项 | 验收要点 |
|----|-----|----------|
| **M1** | 证据 span 点回（块内偏移 / 高亮） | UI 与导出能落到句段，而不只是文档/块 ID |
| **M2** | 系统契约单页 | 白名单矩阵、闸不变量、评测冻结规则、半激活禁令；与代码一致 |
| **M3** | claim–evidence 对齐分（可弱监督） | 有字段与最小评测；不阻塞 M1 |
| **M4** | 导出口径固定（sheet / client-memo） | 红/黄/绿对人解释一致 |

### M 关门条件

- span 点回可演示。
- 契约与默认白名单/阶段挂载一致（禁止「文档已写、主链不可见」口径）。

## 3. Phase B — Agent 专项

**前提**：检索 API 冻结；只许开关/权重。召回算法变更回 Phase A。

| ID | 项 | 验收要点 |
|----|-----|----------|
| **B0** | 评测仪器 + retrieve-miss vs judge-error 归因 | 固定模型/温度/seed/语料 checksum；一键复跑 |
| **B1** | 多 seed 消融 + 假绿对照实跑 | 规格容差变成可引用数字；诚实边界保留 |
| **B2** | Memory：**接入或切除**；若接入则 `must_quarantine` 金标 + harness | 禁止「代码在盘、主链不可见」 |
| **B3** | 对抗夹具 ATK 实跑 | 通过/失败分类表；建立在 B0 仪器之上 |
| **B4** | 工具 timeout / retry / 结构化错误 + 预算强制 | 超时与失败可单测 |
| **B5** | `basis_rot` ↔ 时间–版本全链路 | 依赖 A7；跨轮掉灯可测 |
| **B6** | HumanLatch 串行状态机 / 幂等 | 重入测试通过后再谈并发 |
| **B7** | 多 claim 并发 | 与串行结果一致（幂等约定写清） |
| **B8** | 可观测：轨迹 → 汇总指标 | 工具错误率、闸分布、token；CLI 或一页报告 |
| **B9** | Run 级成本 / 步数预算报表 | 可截图、可对比 |
| **B10** | 配置与密钥面自检 | 未接线配置清理；启动自检 |
| **B11** | 跨 Provider 对照（可选） | 证明闸层稳定；**非**硬关门项 |

### Phase B 关门条件

1. 半激活模块清零（接上或删除叙事与死路径）。
2. 多 seed + 归因拆分可复现引用。
3. 工具失败模式可测。
4. RAG 回归集仍绿；检索契约未被改穿。

### 关键路径（现状）

- `src/freshlatch/roles/lead.py` — 默认 `LEAD_TOOLS_W3`；记忆工具未挂
- `src/freshlatch/roles/forensic.py` / `tools.py`
- `src/freshlatch/gates/*`、`latch/pipeline.py`
- `src/freshlatch/eval/*`、`data/eval/gold.json`

## 4. Phase C — 增强（采编、嵌入、资产库）

**不阻塞 A/B 关门**；主链可信后再做。

### C1. 联网采编（允许的正路）

```
搜索 / 白名单源 → 落盘为 T1（URL、抓取时间、正文、checksum）
  → 入库检索 → 复验闸 → HumanLatch
```

| 规则 | 说明 |
|------|------|
| 必须先入库再参与裁定 | 未入库不得写绿灯 |
| 与人工 T1 同一主链 | 上传/粘贴路径已存在，采编是自动化入口 |
| 早期建议 | 白名单域名 + 入库确认 |

**验收**：至少一条源可一键或定时采编进库；checksum 可查；轨迹可标记 `source=crawl`。

**现状**：人工 T1 三卡已有；自动搜索/抓取未实现。

### C2. 嵌入现有工作流

卡在「要发了」：文档导出、邮件发送、交付包打包前的复验钩子。

**验收**：至少一条真实嵌入路径（插件或 API）跑通；用户无需换用新日常 App。

### C3. 主张资产库（更远期）

按主张 ID 管理版本、续命、作废历史；证据更新可触发关联掉灯（图谱可先列表化）。

**验收**：组织级「现在还能引用什么」可查询；不止单次 run。

## 5. 产品发展阶段（业务）

| 阶段 | 方向 | 含义 | 要证明的事 |
|------|------|------|------------|
| **现在** | 垂直复验引擎 | 顾问 / 研报 / 合规 **三选一** 做深 | 假绿下降；外发事故可追责 |
| **下一步** | 嵌入工作流 | 「发之前多一步」而非新习惯 | 嵌入被真实采用 |
| **再下一步** | 主张资产库 | 单次 run → 组织知识时效 | 台账与作废/续命历史 |
| **慎扩** | 通用助手、开放联网问答、无关行业乱扩 | 稀释「卖作废」 | — |

### 傻瓜式入口（若做）

仅允许：主张导引、复验单只读解释、草稿导入。  
**禁止**：对话写绿灯；替代 HumanLatch；引用未入库片段。

### 联网 vs 可复现（产品决议）

- **侦察**可以出门（搜索/抓取）。
- **裁判**只能看已归档 T1。
- 正确：`web → 落盘 → 复验`。错误：`web → 提示词 → 当场下判`。

## 6. 明确不做 / 后置

本路线图 **排除或长期后置**：

- 开放联网问答（搜完直接答）
- 通用聊天助手当主产品
- GraphRAG；为热度做的 Plan-Execute / 多 Agent 拓扑大改
- 微调 reranker（先证明离线 embedding + 轻量 rerank 有增益）
- MCP 生态、Docker/K8s 作为正确性前置
- QuoteTTL 等第二曲线：仅作同一闸门哲学的另一垂直，不抢 A/B

## 7. 里程碑总览

```
A-α  契约 + BM25 基线 + retrieve dev set v0
A-β  dense + hybrid + 快照过滤；评测表齐全
A-γ  rerank 决策 + query transform + 陷阱语料；【A 关门】

M    span 点回 + 系统契约 + 导出口径；【M 关门】

B-α  仪器 + 归因 + 多 seed / 假绿
B-β  Memory 闭合 + 对抗夹具 + basis_rot 对齐
B-γ  工具薄壳 + 幂等；可选并发 / 观测 / 跨模型；【B 关门】

C1   白名单采编落盘再复验
C2   嵌入发前检查
C3   主张资产库
```

---

## 8. 依赖关系

```
A0 → A1 → A2 → A3 → A4
              ↘ A5
A7 可与 A2–A4 并行；B5 依赖 A7
A8 尽早，供 A 评测与 B 对抗共用
A 关门 → M1–M4 → B0 …
C1 依赖已有「入库 T1」路径；建议不早于 A 可测检索
C2 / C3 依赖 B 主链可信（闸 + 人审 + 可追责）
```

---

## 9. 一句话执行摘要

先把检索做成 **可测子系统**，再补 **点回与契约**，再闭合 **Agent 测量与半激活**，最后加 **联网采编落盘** 与 **发前嵌入**；全程 **未入库不得裁定**。产品向 **垂直闸门 → 工作流嵌入 → 主张资产库** 发展，不向全能助手发展。
