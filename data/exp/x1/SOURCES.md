## 索引核对（切块是否吃进 frontmatter）

结论：BM25 与 dense 索引的文本不含 frontmatter，也不把 `title` 拼进向量。被索引的是 `chunk.text`，形如 `## pN` 加该块正文。法规名只在 `Chunk.title`（以及文档表的 title 列）里，不进词项、不进向量。本步未改代码。

依据（行号对应当时读到的文件）：

- `src/freshlatch/store/ingest.py` `parse_document_text`：第 47–53 行把 frontmatter 读进 `meta`，正文从结束标记之后的 `body` 起。第 58 行 `title = meta.get("title", doc_id)`，单独保存。第 63–69 行按 `## pN` 切开，块文本是 `## {clause_id}\n{chunk_text}`，`chunk_text` 只是标题行后面的正文。第 75 行把 `title` 放进 `Chunk.title`，第 76 行 `text=full`。第 81 行 token 数按 `full` 计，不含 title。第 90 行 `Document.full_text` 保存整份 markdown（含 frontmatter），那是 `read_source` 用的全文，不是 BM25 或 dense 的输入。
- `src/freshlatch/store/pipeline.py` `recall_bm25` 第 26 行：语料是 `tokenize(c.text)`。同文件 `rerank_lexical` 第 120 行也只对 `chunk.text` 做词重叠。
- `scripts/build_dense_index.py` 第 125 行：`texts = [c.text for c in batch]`，随后交给 `embed_texts` 或 `embed_texts_cached`（第 126–136 行）。没有 `title + text` 的拼接。
- `src/freshlatch/eval/retrieve_typed.py` `unique_embed_texts` 第 220 行：缓存键用的也是 `chunk.text`。
- `src/freshlatch/store/sqlite_store.py` 第 183–188 行：`title` 与 `text` 分列写入。查询向量走 `base.py` `_embed_query`（第 99–105 行），输入是问句本身。

因此本期把法规名放在 frontmatter 的 `title`、不写进块正文，三臂都不会因为标题前置而多召回。这与 RET-01「标题不进正文」一致。
